# Open topics

A **park-for-later** convention: non-trivial follow-ups that surface during work but cannot be resolved immediately live as `docs/open-topics/T<NNNN>-<slug>.md` files (resolved → `archive/`), indexed in `docs/open-topics/README.md`.

- **When to open**: a non-trivial item that cannot be resolved within the current iteration. If it can be resolved on the spot, resolve it instead. Trivial one-turn uncertainties do not qualify.
- **Opening takes the coordinator's word** — `zcrypto-main` in the multi-session setup, the owner otherwise. Resolve in-branch first — a converge the fix needs is a cost to weigh, never a reason to defer: if it touches the capture path or the live trade host, say so and take the owner's word on timing, but plan the fix into the iteration regardless. A finding that genuinely cannot be resolved in-branch goes to the coordinator as the topic's `Context` + `Why this matters`, and the answer — register, fold, or drop — is recorded. In an unattended run with no coordinator reachable, register it and name it in the hand-back for the owner's confirm-or-kill. A finding is never silently dropped, and a PR body is never its only home.
- **A deferred action is only tracked if it lives here — prose is not registration.** *(protected — every edit takes the owner's per-edit sign-off)* Reports, PR bodies, decisions-log entries, and docstrings are never a deferral's only home. A deferral on a precondition declares `ripe_when: <condition>` in its frontmatter, echoed in its index bullet; **every review that consults the index evaluates each trigger** — a fired trigger is live work now: pick it up or consciously re-defer with a reason. A hold is REPORTED by evaluating its trigger, never by restating it — a coordinator's summary included: name the false arm and the state that makes it false.
- **A `ripe_when:` is derived from measured state and verifiably satisfiable** — never an estimated date, never a condition the data source cannot deliver. Before registering, check the trigger against what actually produces the condition. **`ripe_when:` holds the condition alone, including the one check that evaluates it** (a `git log` invocation is part of the condition) — history, reasoning, and what the check READ go to the body; a trigger that must be read past is not a trigger.
- **"Human-gated" is per sub-item, never per topic.** Decompose: run an autonomous sub-item now iff it **feeds** the parked human decision or is **independent** of it — never if it **waits on** the decision. Never park a whole topic as "human" when half of it is public research.
- **A topic file may be stale by design while its work PR is open — the memo is the in-flight authority** (grep `.local/memo.md` before reporting a topic's status). And a topic registered but not queued in the memo is **invisible at pick time**: registration and queue insertion travel together.
- **Review and drain**: at every brainstorming-iteration start and before finishing a phase, review `### Open` / `### Partially done` and fold ripe items in. **End-state invariant (autonomous runs)**: by hand-back, everything still open is human-gated or deliberately deferred to a future phase — an autonomously-resolvable item left parked is a miss.
- **Status tracks sub-items live**: first sub-item done while others remain → `partial`; last one done → `resolved`.
- **The PR that completes a sub-item carries that topic's whole update — `status`, `ripe_when`, `## Done so far`, and removal of the finished next-step — in that same PR.** A correct `status` over a stale body is still drift (never split across PRs — see `branch-workflow.md`'s micro-PR ban).
- **A sub-item DONE or DECIDED in full with no leftovers MOVES to `## Done so far`, rewritten as its outcome — never edited in place under `## Suggested next steps`**, where a line reads as pending regardless of wording (`topic-ops` owns the move mechanics).
- **"Resolve" means the issue is SOLVED — never a status change.** Archiving records a resolution (fixed, measured non-issue, or consciously dropped with the reason written); it never substitutes for one. Never archive to shorten the list; never archive a topic carrying a live deferred sub-item — split that out first.
- **All file mechanics — serials, the required shape, partial/close procedures, archive moves, index sync — are the `topic-ops` skill** (`.claude/skills/topic-ops/SKILL.md`): load it for every topic file operation.
