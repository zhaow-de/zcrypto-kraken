# Agent operations

- **Never guess a path on a fleet host** — read `docs/reference/fleet.md` (roles, paths, mounts, endpoints; pins in `fleet-pins.md`) and the data catalogs first; probe only where the doc is silent, and write what the probe finds back into the doc in the same change.
- **A recorded footgun names the safe alternative in the same sentence** — "don't use the default X" without "use Y at Z" strands the next context at the moment it needs the answer.
- **Before requesting the user's word on an irreversible/production action, sweep the open-topics index + memo for blockers** and present the result with the request — "ready" without the sweep is not ready.
- **Verification is scoped to what the change can reach** — a diff nothing imports doesn't get the pytest suite (the commit gate always runs); name what each check would catch before running it. **The full suite is CI's**: it runs on every PR into `develop` and merge-on-green gates on it, so running it locally first buys nothing — except for the data-gated families, which skip in CI and run nowhere else. A workflow triggered on `push` (not `pull_request`) is outside PR CI's reach entirely — run its build locally before merging anything it consumes.
- **A guard (assert, alert rule, CI check, test) is unproven until the defect it names is constructed and seen to trip it** — on a fixture where defect and correct behaviour DIFFER: a degenerate fixture (one the defect cannot move) passes under the defect and proves nothing. Read WHICH failure fired before recording the result: a red exit can be the guard misfiring on a healthy path. The suite also needs a **true-positive** — a real, healthy, production-shaped input that must pass — or an always-refusing guard ships green.
- **Assert on what the defect moves, not on the headline** — exit codes, published aggregates, and `$?` after a pipeline (the last command's status, not the probe's) are routinely identical on both sides of a real defect, so a probe or test judged on the headline alone has proven nothing.
- **Timeout-guard every network-touching command** (`git push/pull/fetch/ls-remote`, every `gh` call): prefix `timeout 20`–`60`, and run it as its own small step — never buried in a long compound command. For CI waits, poll with per-call timeouts instead of one long foreground wait.
- **Never spawn a shell that polls/waits for a background job you started** — the harness re-invokes you when it completes. A genuine wait on external state (a clock boundary, a slow remote pull) goes *inside* the one backgrounded command doing the work, never in a second watcher shell.
- **`pgrep -f` / `pkill -f <pattern>` match their own command line** — bracket one character (`pgrep -f "[p]attern"`) or the guard never goes false / the kill hits itself.
- **A subagent whose final message says it is *waiting* for a backgrounded command is stranded** — its turn ended, the work sits uncommitted. Check `git status`, then resume the **same** agent via SendMessage with numbered foreground steps ending at the commit; never dispatch a fresh twin. A "failed: API error" notification can also be premature — check the tree before re-dispatching.
- **Subagent dispatch prompts say**: run everything as plain blocking commands, background nothing, do not end the turn before the commit exists — and still expect to occasionally resume.
- **Never run two subagents that may write the same worktree concurrently.** Dispatch write-capable agents one at a time, or give each `isolation: "worktree"`. Read-only reviewers may run in parallel with each other, but not alongside a writer — and a reviewer permitted to mutate-and-restore is a writer.
- **Mutation probes run through `infra/scripts/mutate-probe.sh`, never a hand-rolled mutate-and-restore loop** — the script's own header documents its refusals and the stale-`.pyc` neutralization. Verify the probe's selection actually collects the test under proof (`--collect-only` first) — a `-k` filter can deselect it, and a control that does not bite may be selection, not the guard.
- **A probe outside the repo tree must PROVE which tree it imported** — assert `cli.__file__` starts with the intended root before trusting any verdict. Two ways it silently tests the original instead: a copied `.venv` keeps its shebang pointing at the original interpreter (use `./.venv/bin/python -m pytest`, never `uv run pytest`, inside a copy), and `python script.py` sets `sys.path[0]` to the SCRIPT's directory rather than cwd. A dirty tree that `mutate-probe.sh` rightly refuses is a detached `git worktree` at the commit, not a hand-copied directory.
- **`git mv` stages a rename of the INDEX version** — edits made before the move stay unstaged and `git status` shows `R100`; `git add` the new path after every `git mv`, and verify an invariant against the **committed** tree, never the working tree.
- **Chain history-rewriting git commands one per call, never compounded** — verify each step's effect before issuing the next; `--amend` folds the staged set into HEAD, so read `git log -1 --stat` first — hooks see the staged set, never the mixture the amend produces.
- **A grep hit is not a call site** — before claiming X calls Y, open the match and confirm it is a call site — a docstring, comment, or string-literal mention justifies nothing about runtime reachability.
- **A count derived by arithmetic is not a measured count** — `total_a - total_b` is the set difference only when the sets nest. Measure the set.
- **Never write a digest or hash from memory** — read it from its source and verify shape and existence (64 hex, present in a commit) before recording it: an invented value in a rollback record looks usable and is not.
- **Attribute an observed mutation only after proving the suspect command's MODE could produce it** — an ansible `--check` renders against controller-local temp while a real write stages into the remote user's temp; fingerprint first, a timing coincidence is never an attribution.
- **Python `str.replace` edits silently no-op on a missed match** — `assert old in s` (or verify the output) every time.
- **Snapshot unversioned data before any tool rewrites it** — gitignored files have no undo, so copy them aside first and delete the copy only after the final verification that could read it.
- **Correct a durable doc by rewriting the narrative in place, never by appending retraction bullets** — the uncorrected story reads first, and more confidently than the correction below it; the file must read correctly cold.
- **Retiring or restructuring a durable doc first sweeps the removed text for live deferred actions** (owed checks, "no earlier than", pending verifications) — a deferral whose only home is prose dies with the prose; register, discharge, or explicitly drop each in the same change.
- **A number quoted from a reviewer's or subagent's report is unmeasured until you reproduce it** against the source data, at full precision.
- **A completion signal can belong to a different run** — a finished oneshot retains the previous run's `Result`, `is-active` exits 3 while `activating`, and a `Persistent=true` timer's catch-up tick answers right after a manual run: anchor every green to your own run's timestamps and reconcile the arithmetic against the work you dispatched.
- **Widen and prove a guarding test BEFORE the migration it guards** — a test still pointed at the old layout goes green against a file the content has left; land the widened guard first and see it bite on both layouts.
- **An empty filtered query is not an absent event** — require a positive trace before concluding nothing happened; validate the filter before trusting its emptiness. For ops-converge verification, `infra/scripts/ops-postverify.sh` embodies this rule. Print the input's line count and confirm it is non-zero before trusting any zero: `docker logs --since` takes a **duration or a full timestamp**, so a bare `--since HH:MM:SS` fails to parse, so a grep over its empty output reads as a clean bill. Unprivileged `journalctl -u` on a system unit prints `-- No entries --` **with a you-cannot-see-system-messages hint above it** — read the hint, rerun with `sudo`; the empty result is a permissions artifact, not an idle unit. A flat counter is likewise not a clean bill until the pipeline's booking opportunity for that window has passed (the reconciler books hour H only at the next `:12`/`:42` tick after H+2 h) — until then the answer is *pending*, never *clean*.
- **Time-gated reminders go to Slack `#zcrypto`** (`slack_search_channels` finds it) — never fall back to a DM, and a scheduled message cannot be deleted via API, so schedule it right the first time.
- **Never narrate a wall-clock time or elapsed duration you did not just measure** — run `date`/`uptime` first.
- **Host-touching (ssh/sudo) steps run in the main loop, never inside a dispatched subagent or workflow** — the permission gate blocks them there and the step dies where nobody sees the prompt; gather host evidence first, or expect the rejection and re-dispatch from the main loop.
- **A repo script failing on a missing host binary is a host finding to report, not a script to patch** — and what the probe found goes into `fleet.md` in the same change.
- **Observed drift is not license** — a recent change that skipped a required step is a finding to flag, never a template to copy.
- **A local branch is not a merge path until its remote/upstream is verified** — `git ls-remote --heads origin <branch>` plus the upstream ref; no remote and an upstream pointing elsewhere = a local composition that merges nowhere.
- **Sweep for the CLAIM, not the phrase you wrote** — enumerate its variants before grepping, re-sweep after each fix round, and name the point-in-time records deliberately left carrying the old wording.
- **A truncated sweep is not a sweep** — piping aggregated evidence through `head`/`tail` before the assertion silently drops the counterexample; bound the input per-file, never the evidence stream.
