# Agent operations

- **Never guess a path on a fleet host** — read `docs/reference/fleet.md` (pins in `fleet-pins.md`) and the data catalogs first; probe only where the doc is silent, and write what the probe finds back into the doc in the same change.
- **A recorded footgun names the safe alternative in the same sentence.**
- **Before requesting the user's word on an irreversible/production action, sweep the open-topics index + memo for blockers** and present the result with the request.
- **Verification is scoped to what the change can reach, and reach is grepped, not reasoned** — `git grep -l <path> -- tests/` plus whatever globs the file's directory; a meta-test that walks `tests/test_*.py` is reached by a file's EXISTENCE, so adding or renaming a file is its own blast radius. The full suite is CI's and the data-gated families are not (CLAUDE.md); a workflow triggered on `push`, not `pull_request`, is outside PR CI — run its build locally before merging what it consumes. A change to source TEXT reaches every test that reads the file's bytes, not only the tests that import it — a docstring or comment reaches the citation checks and the tripwire's tests, a rule or docs-only diff reaches the tracked-file walkers (`tests/test_internal_terms_not_operator_visible.py`, run before pushing a docs branch) — and the reach run is taken once, on the final tip, after the last rewrite. Name what each check would catch before running it, and the files run and the selection rule after: a green is evidence only about what it exercised, and a clean commit gate is a formatter pass, never a passing suite.
- **A guard (assert, alert rule, CI check, test) is unproven until the defect it names is constructed and seen to trip it** — on a fixture where defect and correct behaviour DIFFER (a degenerate fixture passes under the defect), reading WHICH failure fired (a red exit can be the guard misfiring on a healthy path), with a **true-positive** beside it — a healthy, production-shaped input that must pass, or an always-refusing guard ships green. Assert the SELECTION before the loop and print its count. A test double answers the MODE — a stub identical in every mode the code distinguishes is degenerate for every mode defect — and an injection default is a live call site, not a seam: require the keyword.
- **A tool that JUDGES the tree — a scanner, a checker, a ratchet, a measurement script — is a guard** and takes the same construction before it gates anything; its item list comes from the region it judges, never from the claim under test. For a check keyed by a value or aggregating a set, the fixture where the key COLLIDES and where the measure changes. Assert the coordinate, not the category (`[(line, kind)]` — a defect that moves the trip between sections is invisible to a kinds list); the defect-exact mutation DELETES the arm under proof, never makes the guard fire everywhere; a modified artifact's degeneracy is constructed from the shipped property, never the version it replaced; an assertion's message is dead code on every green run, so one deliberate red exercises any edit to what it reads. A string's SHAPE may only ever cause a refusal, never an admission — every admission is made on a resolved, existing object — and a guard refuses the class it does not handle rather than enumerating the ones it does. A property of a FILE is pinned by content (a verbatim region and its sha256), never by an enumeration of forbidden spellings; read any canonicalisation adversarially — every line it drops is a line the pin cannot see.
- **Assert on what the defect moves, not on the headline** — exit codes, published aggregates and `$?` after a pipeline (the last command's status, not the probe's) are identical on both sides of most real defects.
- **Timeout-guard every network-touching command** (`git push/pull/fetch/ls-remote`, every `gh` call): prefix `timeout 20`–`60`, and run it as its own small step — never buried in a long compound command. For CI waits, poll with per-call timeouts instead of one long foreground wait.
- **Never spawn a shell that polls/waits for a background job you started** — the harness re-invokes you when it completes; a genuine wait on external state goes *inside* the one backgrounded command doing the work.
- **`pgrep -f` / `pkill -f <pattern>` match their own command line** — bracket one character (`pgrep -f "[p]attern"`) or the guard never goes false / the kill hits itself. This shell is zsh: an unquoted `$var` is one word, never a split command — spell a probe command out or pass an array; and `$var:` followed by a letter is a history modifier, not a colon — brace the parameter, `"${rev}:path"`: quoting alone does not stop it (`"$rev:h"` still yields the head). Never name a variable `path`, `cdpath`, `fpath` or `manpath` — a loop over `path=` destroys command lookup.
- **Subagent dispatch prompts say: plain blocking commands, background nothing, do not end the turn before the commit exists** — a subagent whose final message says it is *waiting* is stranded with the work uncommitted — check `git status`, then resume the **same** agent via SendMessage with numbered foreground steps ending at the commit, never a fresh twin; a "failed: API error" notification can be premature — check the tree first.
- **Never run two subagents that may write the same worktree concurrently.** Dispatch write-capable agents one at a time, or give each `isolation: "worktree"`. Read-only reviewers may run in parallel with each other, but not alongside a writer — and a reviewer permitted to mutate-and-restore is a writer. A worktree with a background run in it is a writer's worktree — no rebase, amend or checkout there until the run ends; never edit the tree a reviewer is reading.
- **Mutation probes run through `infra/scripts/mutate-probe.sh`, never a hand-rolled mutate-and-restore loop** — its header states its refusals. `--collect-only` first: a `-k` filter can deselect the test under proof, and a control that does not bite may be selection, not the guard. A dirty tree it rightly refuses, and a reviewer that must mutate, both get a detached `git worktree` at the commit — the reviewer dispatched write-capable, never a hand-rolled loop inside a read-only brief.
- **A probe outside the repo tree must PROVE which tree it imported** — assert `cli.__file__` starts with the intended root before trusting any verdict. A copied `.venv` keeps its shebang on the original interpreter (inside a copy, `./.venv/bin/python -m pytest`, never `uv run pytest`); `python script.py` puts the SCRIPT's directory in `sys.path[0]` while a relative WRITE resolves against cwd — a scratch script's outputs are absolute paths, named as such in the dispatch. The same proof for every WRITE and check: a session's cwd persists across calls, a subagent's resets between them, and a removed worktree drops you into whatever is beneath — so every write names an absolute path inside your own checkout, every git command runs with `-C`, a write script asserts an anchor unique to the intended tree (`git status` is not that assertion), linters run from the target tree's root, and a verdict names the tree it measured.
- **`git mv` stages a rename of the INDEX version** — edits made before the move stay unstaged and `git status` shows `R100`; `git add` the new path after every `git mv`, and verify an invariant against the **committed** tree, never the working tree.
- **Chain history-rewriting git commands one per call, never compounded** — verify each step's EFFECT (HEAD moved, subject matches, tree equal) before issuing the next, never its exit code; `--amend` folds the staged set into HEAD, so read `git log -1 --stat` first — hooks see the staged set, never the mixture the amend produces. A conflict resolution is three separate calls — the resolver alone; its exit read and every file grepped for markers (a formatter can rewrite them: mdformat turned `>>>>>>>` into a blockquote); then stage and continue — never a script chained to `git add && git rebase --continue`, which runs whether or not the script raised.
- **A grep hit is not a call site** — open the match and confirm it before claiming X calls Y; a docstring, comment or string literal justifies nothing about runtime reachability. A vocabulary sweep finds the surfaces that already SAY the thing, never the ones that depend on it silently — enumerate call sites and states, one adjudication row per site, and a closure claim names the tree it covers.
- **A number in prose is first asked whether it is needed at all** — an enumeration carries no count beside it ("the following points", never "the following three points"). A number that stays names the set it quantifies and the command that measured it, in the same sentence: never arithmetic over totals that may not nest, never the tree before the change when the change's tree is the claim, never a reviewer's or subagent's figure before you reproduce it at full precision, and never a relay of an unreproduced figure into a dispatch, memo or report. The order is fixed: run the proof, then paste ITS summary line — never compose the claim and the command that would produce it in one step; a count over a set operation is computed by a command with its inputs kept; a figure that crosses a compaction is re-derived before use. A command that measures a SUPERSET is a different measurement — `grep -c` counts lines, not values; a token grep over a template matches imports; a diff-scoped scan re-reports what an edit above it moved — so derive the count from the set that defines the claim and name the unit the command returns; a proxy set or label drifts from what it stood for; the same for a coordinate: a dispatch that names a parameter or a `path:line` opens it first, or cites the claim as a claim. A claim about what an external library returns names the measurement that produced it and how to repeat it — a finding from a run you called untrustworthy is discredited with it.
- **Never write a digest or hash from memory** — read it from its source and verify shape and existence (64 hex, present in a commit) before recording it.
- **Attribute an observed mutation only after proving the suspect command's MODE could produce it** — fingerprint first (an ansible `--check` renders against controller-local temp; a real write stages into the remote user's temp); a timing coincidence is never an attribution.
- **Python `str.replace` edits silently no-op on a missed match** — `assert old in s` (or verify the output) every time; a batched edit script that raises has applied a prefix — re-run it whole from a clean tree, never patch forward from the line that raised. An anchor is copied from the file's own bytes (`sed -n Np | cat -A`, `git show rev:path`), never from a display pipeline that folds, indents or truncates, and asserts count == 1 — splices included.
- **Snapshot unversioned data before any tool rewrites it** — gitignored files have no undo, so copy them aside first and delete the copy only after the final verification that could read it. A scratch worktree that symlinks canonical datasets unlinks them BEFORE `git worktree remove`, and the main checkout's `data/` listing is read after.
- **Correct a durable doc by rewriting the narrative in place, never by appending retraction bullets** — the file must read correctly cold.
- **Retiring or restructuring a durable doc first sweeps the removed text for live deferred actions** (owed checks, "no earlier than", pending verifications) — a deferral whose only home is prose dies with the prose; register, discharge, or explicitly drop each in the same change.
- **A completion signal can belong to a different run** — a finished oneshot retains the previous run's `Result`, `is-active` exits 3 while `activating`, and a `Persistent=true` timer's catch-up tick answers right after a manual run: anchor every green to your own run's timestamps and reconcile the arithmetic against the work you dispatched.
- **Widen and prove a guarding test BEFORE the migration it guards** — a test still pointed at the old layout goes green against a file the content has left; see it bite on both layouts.
- **Two producers measuring the same thing independently are the check on each other** — when they disagree, the disagreement IS the finding; a single source cannot report that it is under-reporting. A reconciliation of two authoritative sources, or a transcription onto an operating surface, takes a second reader asked *nothing invented* and *nothing mis-stated* by name — the author's own checks can only ask *nothing lost*.
- **Rule out your own changes explicitly, with timestamps** — compare an alert's `activeAt` against every converge, restart and drill of that day before attributing it to anything else. A lock or fixture that must survive a scheduled event is checked against that event's own code path first — enumerate the processes the event runs, not the people who might act.
- **An empty filtered query is not an absent event** — require a positive trace, validate the filter before trusting its emptiness (`infra/scripts/ops-postverify.sh` embodies this for ops converges), and print the input's line count before trusting any zero: `docker logs --since` takes a duration or a full timestamp — a bare `HH:MM:SS` fails to parse and greps clean; unprivileged `journalctl -u` on a system unit prints `-- No entries --` under a hint to rerun with `sudo`. A flat counter is *pending*, never *clean*, until the pipeline's booking opportunity for that window has passed (`infra/runbooks/drills-telemetry.md` states the reconciler's tick). **Alert timing comes from the source system** — the rule's `activeAt`, or `GET /api/v1/rules/history` with `from`/`to` in epoch SECONDS as `infra/scripts/ops_daily.py` calls it — never a Slack delivery stamp; an empty history page is a unit or window error before it is an absence. A filter over machine output claims that output's grammar: print the line that PRECEDES each match, cross-check the recap's own count, and classify a terminal state positively (`status == COMPLETED`), never as the absence of pending words. A refusal prints nothing on stdout; a failed extraction leaves an empty file a counter reads as a real zero; a report's own scope and count line is read before its verdict, never through `tail` — a check whose success looks like silence is read only after a positive: the count, or a known-non-empty control.
- **Time-gated reminders go to Slack `#zcrypto`** (`slack_search_channels` finds it) — never fall back to a DM, and a scheduled message cannot be deleted via API, so schedule it right the first time. A wall-clock read during a busy stretch rides this channel or a payload poke, never a session-only one-shot cron, which fires only while the session is idle.
- **Never narrate a wall-clock time or elapsed duration you did not just measure** — `date -u` at the TOP of the command that writes the stamp, never at its end; a peer message's or owner instruction's time is the transcript's own timestamp.
- **Host-touching (ssh/sudo) steps run in the main loop, never inside a dispatched subagent or workflow** — the permission gate blocks them there; gather host evidence first, or expect the rejection and re-dispatch from the main loop.
- **A repo script failing on a missing host binary is a host finding to report, not a script to patch** — and what the probe found goes into `fleet.md` in the same change.
- **Observed drift is not license** — a recent change that skipped a required step is a finding to flag, never a template to copy.
- **A local branch is not a merge path until its remote/upstream is verified** — `git ls-remote --heads origin <branch>` plus the upstream ref. Before a `..`/`...` range or a merge-base authorises anything, run it on a known-positive and a known-negative ref and quote both: a two-dot `git diff` from develop reports develop's own files as the branch's; a three-dot `git diff` is EMPTY for a merged branch while `git log`'s three-dot symmetric difference is not; and a post-merge merge-base compares a tip to itself.
- **Sweep for the CLAIM, not the phrase you wrote** — enumerate its variants before grepping, re-sweep after each fix round, and name the point-in-time records deliberately left carrying the old wording. The sweep runs BEFORE the first edit, at the widest scope, riskiest surface first — after the edit it finds what the edit already changed.
- **A truncated sweep is not a sweep** — piping aggregated evidence through `head`/`tail` before the assertion silently drops the counterexample; bound the input per-file, never the evidence stream.
- **Append to `.local/agent-lessons/<your session>.jsonl` the moment it happens** — in the main checkout, never a worktree's (removed after merge): *it was mine* / *I mistakenly* / *the third time* / *a miscount: a count typed beside data that says otherwise*; a rule you decided not to follow (which, and why); feedback on a rule or skill. Through `infra/scripts/append-lesson.py` — it validates the record by the checker's own rule and refuses a worktree's inbox — never a bare append; your own file, never a committed ledger; never at closeout from memory.
- **A cause that fits is not a cause that was checked** — before reporting one, name the cheapest check that would refute it and run it. The live shapes: a PATTERN substituted for the NAMED field; a claim about a state the reporter structurally cannot see (`docs/reference/multi-agent-protocol.md` names which states a payload session cannot see); an anchor verified unique but not for what ENCLOSES it.
- **Announcing a step is not taking it** — "sending X" / "next: Y" followed by an ended turn. At the top of every turn, read your own last declared next step against what actually happened, before anything else.
- **Never say a job, review, or subagent is running unless you dispatched it in this turn and hold its result line** — otherwise the words are *not started* or *unknown*.
- **Re-open the authority at the moment of use** — the spec, the memo chain, the approval text — never a stored summary of it: the summary is usually right and incomplete. The moment of use is BEFORE the step it governs, and it includes a rule you are about to cite as a reason: quote its clause and its scope line, never its gist.
- **`grep`/`rg` here honour `.gitignore`** — a whole-tree sweep silently misses everything under `.local/` (the memo, the coordination table, the inboxes); the bare `grep` in this shell is a ugrep function (`/usr/bin/grep` is GNU; a fleet host runs its own — a claim about grep behaviour names the binary it measured) and needs `--no-ignore-files`, `rg` needs `--no-ignore` (`rg --no-ignore-files` still hides it) — or name the file.
