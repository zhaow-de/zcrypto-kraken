# Commit message convention

[Conventional Commits v1.0.0](https://www.conventionalcommits.org/en/v1.0.0/): `<type>(<scope>)<!>: <subject>` — types `feat` `fix` `docs` `refactor` `perf` `test` `build` `ci` `chore` `revert` plus **`claude`** (any change to `CLAUDE.md` or `.claude/` — never `docs`). Scope: the snake_case component, or `config`/`build` for cross-cutting. Subject: imperative, lowercase, no trailing period; an `iter-<N>` tag is permitted where informative (closeouts routinely carry one).

Stage by explicit path, one commit-type's file kind per commit — never `git add -A`/`-u`: blanket adds sweep another kind's files into the typed commit; when a change spans kinds, plan the split before staging anything. The enforced boundary (pre-commit `staged-kind`) is claude-kind vs everything else; `feat`/`fix` commits legitimately mix code, tests, and docs. A refused commit leaves its staged set in the index: `git reset` before re-staging by path, and read the hook's own line before retrying.

Breaking changes: append `!` after the scope (preferred). A descriptive footer must use the **hyphenated** token `BREAKING-CHANGE:` — the space form is not a valid git trailer, and when it shares the footer block with `Co-Authored-By:` git drops the whole block, silently losing the co-author. Commitizen bumps MAJOR for either spelling.

## Trailers

- **Trailer order: `Co-Authored-By:` first, `Reviewed-by:` LAST, no blank line between them.**
- **Never a `Claude-Session:` trailer** — the harness default adds one; the owner's override stands repo-wide, subagents included.
- Every Claude-authored commit carries `Co-Authored-By: <the ACTUAL authoring model> <noreply@anthropic.com>` — opening the trailer block, blank-separated from the body; a subagent credits its **own** model (verify against the dispatched model; dispatch prompts never hardcode a version), and the dispatching session's own system prompt goes stale after a mid-session `/model` switch — the transcript's per-message `model` field is ground truth; the harness's attribution block names a model string and a session and is never the source, and a brief never hardcodes the trailer string — it names who decides it.
- **Review before push is mandatory, and the reviewer is a DIFFERENT agent from the author** *(protected — every edit takes the owner's per-edit sign-off)* — an implementer's commit is reviewed by a subagent other than the implementer, and the orchestrator is never its own reviewer. **The cadence**: a commit that adds or changes a guard — a test, assertion, hook, alert rule or checker — takes a review at drafting; a prose-only or mechanical commit takes none of its own; ONE whole-branch read is the pre-push gate, and after it fix-ups are commits, not review events — only a Critical from that read, or a fix landing on the capture path, the live trade path or canonical data whatever its grade, takes a scoped re-read of its diff. Each reviewer that returns is recorded ONCE for the branch — a `Reviewed-by:` trailer on HEAD, which the PR body aggregates; a reviewer is never a co-author. Rank every dispatch by blast radius (`spec-plan-locations.md`'s clause covers every pre-push dispatch, not only plan reviews). **The third round carrying a Critical or Important on the same subject, whatever guard or claim carries it, ends iteration on it** — delete it, replace it as new work taking its own first review, or put the design to the owner; never a further round on the closed subject. Exactly four exemptions: an already-verified one-liner folded into an open related PR (`branch-workflow.md`); spec/plan/closeout-docs commits whose content the session's authority explicitly approved in the producing flow — the owner attended, `zcrypto-marco` by delegation, and the commit body names that approval; **the `ops-journal` branch's entry commits and its monthly PR** (`branch-workflow.md`) — a day's entry records what the pass observed and has nothing a second agent could check; merge commits (produced by `gh`, no trailers).
- **Before dispatching any review, the author self-checks the diff on its own tier against the classes that dominate findings**: a guard whose prose claims more than its assertions assert; a stub, check or measurement that answers the same in every mode it should distinguish; a number or claim not re-derived from the tree; a premise about a system this session cannot query that is not written as a source reading with its read-back registered before review. The self-check leaves a record: the dispatch prompt names what it ran and found. **The commit that adds a guard names its proof in the body — the mutation constructed and the assertion that fired, one line**; a fix a reviewer SUGGESTS takes the same construction before it lands. A review is the second reader, never the first.
- **Reviewer tiers, one authority**: never below the author's tier; Opus is the floor for any review; Fable for the review that GATES a change to the capture path, the live trade path, or canonical data — the pre-push review on the design-settled path, the floor passes of a plan review, every whole-branch final read — not every round of a loop; Sonnet only for transcription-grade implementation; never Haiku. **Whichever family, always its newest version** — a version number in guidance rots on the next release; the trailer names the version that actually ran. Every dispatch names its `model` explicitly — an omitted one inherits the session's, silently. A scoped re-review of a fix diff runs on Opus, or on the author's tier when that is higher — the same split the plan-review skill fixes for its own loop — and a dispatch that must converge names the previous rounds' closed subjects: do not reopen unless this diff made a new claim about them.
- **Record the review in the same turn it returns, before starting anything else — ONE record per branch, as a `Reviewed-by:` trailer on HEAD.** `infra/scripts/amend-reviewed-by.sh HEAD "<model>"` lands it; never mid-range for the branch record, which rewrites every hash after it for nothing. The one loop that lands trailers elsewhere is `zcrypto-plan-review`: its reviewers read different trees inside a single branch, so each trailer goes on the commit that reviewer actually read, and that skill owns the discipline. The PR body's `Reviewed-by:` line aggregates from the trailer (`open-pr`), so HEAD carries the record and the body is its readable copy — which keeps the audit answerable from `git log` alone, with no network in a pre-push path. When a fix-up lands after the read the record moves to the new tip with it: the trailer says this BRANCH was read by that model, and the branch has changed. A fix-up after the record is a NEW commit, never an amend of the trailered tip — an amend keeps the record while changing the tree under it. A CHANGES-REQUIRED verdict is a completed review: the record says who looked, never that they approved. An unrecorded review is invisible and gets re-run, paying for the same review twice. A trailered commit's tree is frozen — the amend touches the message only.
- **`infra/scripts/review-trailer-audit.sh` computes compliance — run it, never recall it.** It asks whether HEAD carries the record, so a trailer left on an early commit with unreviewed work after it no longer passes; it cannot tell whether the reviewer was a different agent, because a trailer names a model and author and reviewer are routinely the same model. Memory has been wrong here by an order of magnitude.
- Keep commits local through the iteration; push at finishing points. A branch that reached remote unreviewed: review now, land the record on HEAD, `git push --force-with-lease` (permitted on feature branches and `develop`; **never rewrite `main`**).
- PR-description aggregation of authors and reviewers: the `open-pr` skill.
