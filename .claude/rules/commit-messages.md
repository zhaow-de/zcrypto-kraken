# Commit message convention

[Conventional Commits v1.0.0](https://www.conventionalcommits.org/en/v1.0.0/): `<type>(<scope>)<!>: <subject>` — types `feat` `fix` `docs` `refactor` `perf` `test` `build` `ci` `chore` `revert` plus **`claude`** (any change to `CLAUDE.md` or `.claude/` — never `docs`). Scope: the snake_case component, or `config`/`build` for cross-cutting. Subject: imperative, lowercase, no trailing period; an `iter-<N>` tag is permitted where informative (closeouts routinely carry one).

Stage by explicit path, one commit-type's file kind per commit — never `git add -A`/`-u`: blanket adds sweep another kind's files into the typed commit; when a change spans kinds, plan the split before staging anything. The enforced boundary (pre-commit `staged-kind`) is claude-kind vs everything else; `feat`/`fix` commits legitimately mix code, tests, and docs.

Breaking changes: append `!` after the scope (preferred). A descriptive footer must use the **hyphenated** token `BREAKING-CHANGE:` — the space form is not a valid git trailer, and when it shares the footer block with `Co-Authored-By:` git drops the whole block, silently losing the co-author. Commitizen bumps MAJOR for either spelling.

## Trailers

- **Trailer order: `Co-Authored-By:` first, `Reviewed-by:` LAST, no blank line between them.**
- **Never a `Claude-Session:` trailer** — the harness default adds one; the owner's override stands repo-wide, subagents included.
- Every Claude-authored commit carries `Co-Authored-By: <the ACTUAL authoring model> <noreply@anthropic.com>` — opening the trailer block, blank-separated from the body; a subagent credits its **own** model (verify against the dispatched model; dispatch prompts never hardcode a version), and the main session's system prompt goes stale after a mid-session `/model` switch — the transcript's per-message `model` field is ground truth.
- **Review before push is mandatory, and the reviewer is a DIFFERENT agent from the author** *(protected — every edit takes the owner's per-edit sign-off)* — an implementer's commit is reviewed by a subagent other than the implementer, and the orchestrator is never its own reviewer. Each reviewer that returns gets `Reviewed-by: <actual reviewer model> <noreply@anthropic.com>` on that commit — one trailer per distinct reviewer model per commit; a byte-identical second records nothing — a reviewer is never a co-author. Exactly four exemptions: an already-verified one-liner folded into an open related PR (`branch-workflow.md`); spec/plan/closeout-docs commits whose content the user explicitly approved in the producing flow; **the `ops-journal` branch's entry commits and its monthly PR** (`branch-workflow.md`) — a day's entry records what the pass observed and has nothing a second agent could check; merge commits (produced by `gh`, no trailers).
- **Reviewer tiers, one authority**: never below the author's tier; Opus is the floor for any review; Fable for the review that GATES a change to the capture path, the live trade path, or canonical data — the pre-push review on the design-settled path, the floor passes of a plan review, every whole-branch final read — not every round of a loop; Sonnet only for transcription-grade implementation; never Haiku. **Whichever family, always its newest version** — a version number in guidance rots on the next release; the trailer names the version that actually ran.
- **Amend `Reviewed-by:` in the same turn the review returns, before starting anything else — onto the commits inside the diff range the reviewer read, never onto HEAD by position.** A CHANGES-REQUIRED verdict is a completed review: the trailer records who looked, never that they approved. An un-trailered review is invisible and gets re-run, paying for the same review twice; a trailer on the fix that answers a review credits a review that never happened and leaves the reviewed commit bare. The trailer is part of the review step, not of the push — `infra/scripts/amend-reviewed-by.sh <commit> "<model>"` lands one trailer on one commit, HEAD or not, so nothing waits to be batched.
- **`infra/scripts/review-trailer-audit.sh` computes compliance — run it, never recall it.** It fails on any code-kind commit lacking the trailer and reports doc-kind ones for a human. Memory has been wrong here by an order of magnitude.
- Keep commits local through the iteration; push at finishing points. A commit that reached remote unreviewed: review now, amend the trailer, `git push --force-with-lease` (permitted on feature branches and `develop`; **never rewrite `main`**). The iteration's closeout commit is the fallback home for a trailer that couldn't land on its own commit.
- PR-description aggregation of authors and reviewers: the `open-pr` skill.
