# The engine's own re-pin gate: the candidate image's offline preflight on the engine host — implementation plan

> No value in this plan waits on a rollout reading: the first engine converge under the gate is read at that rollout, by the rollout skill's Phase 3 and Phase 5 lines Task 5 adds, and its deploy-log row is the record.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An engine re-pin is refused unless the candidate image's own `zcrypto engine preflight` passed on the engine host against a candidate render of its configuration and the image's revision is a merge on the first-parent line of `develop` or `main`, or a reason-bearing `engine_preflight_override` is on the record; the capture bake no longer gates the engine (spec 00124).

**Architecture:** Seven tasks on `feat/00124-engine-repin-gate`, one pull request. The subcommand first, because the role's tests describe the command the role runs and the rule names the subcommand; then the role, the wrapper, the counts, the prose, the merge gate's arm with its two closures, and the final sweep. The first image to carry the preflight is the one built from the merged tree.

**Tech Stack:** Typer (`cli/engine/command.py`), the exec gate's readers (`cli/engine/execgate.py`), Ansible 2.x with the Templar test substrate (`tests/test_infra_converge_guards.py`), bash (`infra/ansible/scripts/converge.sh` and its python3 row writer, `infra/scripts/count-list.sh`), jq (the counts), `infra/scripts/mutate-probe.sh`.

- A guard change is proven with `infra/scripts/mutate-probe.sh`, never a hand-rolled mutate-and-restore. The script refuses a dirty tree, so a task commits with the line `PROBE_VERDICT` in its message, runs its probes on the committed tree — each with `--control '1,$d'`, the mutated file emptied, unless the probe still passes on an empty file, when its control is a mutation its test must fail (the script refuses a control that does not fail, rc 5) — and then a message-only amend with the tree clean replaces `PROBE_VERDICT` with each probe's command and its verbatim verdict, `mutate-probe: KILLED (control proven, tree restored byte-identically)`; the branch is unpushed and unread while the tasks run, so the amend rewrites nothing a reader holds. A mutation's sed is written against the committed text and addressed to the one line it mutates (a line number read from the committed file), so a clause an echo or the record repeats verbatim is not mutated with it; one that makes a `that:` or a `when:` always true writes the string `"true"`, never the YAML boolean.
- Nothing reaches a host, a venue, Grafana or a registry, and GitHub only at the two steps that name it — Before Task 1's `git fetch origin develop` and Task 7's `open-pr`; no `ansible-playbook` runs — the workstation is a fleet host; role behaviour is proven on the Templar substrate the existing guard tests use.

Never read, print, grep or diff a file whose path contains `vault`: every recursive grep carries `--exclude='*vault*'`, which every tracked vault path's file name matches, and a vault-path test the exclusion leaves out of a local Run runs in CI's full suite.
