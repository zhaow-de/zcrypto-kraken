# Phase 6 — mutation audits of the gate-critical code (2026-07-20)

Two mutation audits of the code deciding whether the deployed strategy may trade real money: the concordance gate arithmetic (`cli/engine/concordance.py`) and the gate-evidence cache (`cli/engine/gate_cache.py`).

**Neither found a live defect.** Every finding is test coverage, not correctness — the code computes the right thing everywhere probed. What the audits measured is which *guarantees* would survive being broken, i.e. which claims decay silently at the next refactor.

**Why they were run.** Not a scheduled sweep: iter-111 (spec `00061`) found several of its own tests vacuous — swapping two labels, or attributing a result to a source that never ran, left the suite green because the assertions were order-agnostic membership checks. That is a defect in the *testing practice*, not in one test, and the retroactive-audit rule requires re-auditing everything built under the same practice. These two modules are the most consequential such code.

**The findings are tracked in \[[T0076]\] (concordance) and \[[T0075]\] (gate cache).** This document is the durable evidence behind them — the per-mutation tables below are what a future investigator needs to re-run or extend the work, and they are committed here rather than left in a session scratchpad precisely because an audit whose evidence evaporates is an audit nobody can check.

**Two methodological cautions for anyone repeating this**, both learned the hard way here:

1. **Purge `__pycache__` between mutations and assert on disk that the mutation is still present after the test run.** CPython validates `.pyc` on source mtime+size; a detected mutation completes in ~2 s, so consecutive iterations collide inside the same mtime second and pytest silently re-runs the *previous* mutation's bytecode. This biases in **both** directions — the concordance audit's first pass produced two false "undetected" and two false "detected" before it caught itself.
2. **Give each concurrent mutation agent its own git worktree.** The first concordance run shared a working tree with the cache run; both restored files via broad `git checkout -- cli tests`, so each could revert the other's in-flight edit, after which a test runs against unmutated code, passes, and is recorded as "nothing caught this" — fabricating gaps that do not exist.

**A raw undetected count is not a finding.** Both audits triaged every undetected mutation into genuine gap vs. equivalent/safe-direction mutant, the cache audit by writing an exploitability script that constructs the input which would now produce a wrong verdict. Report the triaged number, not the raw one.

### Finding 1 (HIGH) — the four original modules are pinned by nothing

The detection split is exactly along the review-history fault line. The **six modules added at review** are held by an explicit membership assertion in `test_replay_fingerprint_covers_the_live_and_latent_gap_modules`:

```python
expected_new = {governor.py, journal.py, a1.py, a2.py, builder.py, strategies.py}
assert expected_new <= covered
```

The **four modules from the original design** — `crossfreq_system.py`, `crossfreq.py`, `limits.py`, `concordance.py` — appear in **no** assertion anywhere. The only test touching the real list, `test_replay_fingerprint_default_covers_the_real_files`, asserts merely that the result is a stable 64-character string, which holds for a list of any length ≥ 0.

This is the highest-severity coverage finding in the audit. `concordance.py` (M05) contains `replay_cycle`, `compare_targets` *and* `evaluate_gate` — the entire verdict pipeline. `crossfreq_system.py` (M01) contains `build_crossfreq_system_fast`, the builder the fast route actually runs. Silently dropping either leaves the cache serving pre-change verdicts forever, with a green suite.

The regression-shaped risk is concrete: the fix for review-hole #1 wrote a test that pins *only what that fix added*, leaving the pre-existing majority of the list unguarded. The list's completeness — named in the task brief as "the property most likely to rot" — is guarded for 6/10 of its members.

**Recommended pin:** assert the full expected set with equality against the real list, not `<=` on a subset:

```python
assert covered == {crossfreq_system.py, crossfreq.py, limits.py, governor.py,
                   concordance.py, journal.py, a1.py, a2.py, builder.py, strategies.py}
```

Equality also catches an accidental *addition*, and makes any future edit to the list a deliberate, test-visible act.

### Exploitability check

Undetected ≠ exploitable, so each undetected drop was tested against a *realistic tamper* of that field (`scratchpad/exploit.py`), comparing the base and tampered digests with the field removed:

```
field         real code    field dropped  verdict
pair          caught       caught         still caught (sort key masks it)
grid          caught       caught         still caught (sort key masks it)
first_ts      caught       MISSED         STALE HIT (exploitable)
last_ts       caught       MISSED         STALE HIT (exploitable)
path          caught       MISSED         STALE HIT (exploitable)
```

`pair` and `grid` are self-healing: they are the `sorted(..., key=lambda s: (s.pair, s.grid))` key, so tampering either reorders the payload list and changes the digest anyway. **M16/M17 are therefore near-equivalent mutants, not gaps.**

### Finding 2 (HIGH) — `first_ts` / `last_ts` are the *same* tamper class as the fixed `n_bars` hole, and are unpinned

`replay_cycle` reconciles all three metadata fields in one condition (`cli/engine/concordance.py:118`):

```python
if len(ts) != entry.n_bars or ts[0] != entry.first_ts or ts[-1] != entry.last_ts:
    raise EngineJournalError(...)
```

Review-hole #2 was "the evidence key hashed only `content_hash`, so tampering `n_bars` let a cached PASS survive a replay that would have failed validation." The fix correctly added all seven fields to the payload — but `test_evidence_fingerprint_changes_when_n_bars_tampered_leaving_content_hash_untouched` pins **only `n_bars`**. `first_ts` and `last_ts` sit in the identical `or` clause of the identical guard and produce the identical failure mode, and nothing would catch their removal.

The code is **correct today**; this is a coverage finding. But it is the precise shape of defect the audit was commissioned to find: the fix was generalised, the test was not, so two-thirds of the fix is unprotected against regression.

### Finding 3 (MEDIUM) — `path` is unpinned and exploitable

`SnapshotEntry.path` is resolved by `_snapshot_reader` into the file the replay actually reads. Repointing one entry's path at a different pair's parquet is a verdict-changing tamper that a real replay would reject (hash mismatch), and it survives a `path`-less fingerprint as a stale cache hit. Unpinned.

### Finding 4 (MEDIUM) — partial-corruption tolerance is unpinned

Wrapping the per-item parse in `try/except: continue` makes a cache file with two valid entries and one malformed entry serve the two valid ones instead of discarding the file wholesale. That directly violates the stated design property — *"the cache must invalidate wholesale whenever anything that could change a verdict changes"* — and nothing catches it.

Every existing fail-open test exercises corruption that fails **before** the entry loop (truncated JSON, wrong schema, `replay_fp` mismatch, a directory instead of a file). The current code is correct (the bare `_outcome_from_dict` call propagates into the outer handler and rejects the whole file) — but that correctness is incidental to the code's shape, not asserted.

## Design-level finding (not a mutation) — a candidate third hole

The brief said to assume a third hole exists. Mutation testing found none in the *implemented* logic — but tracing the fast-route dependency closure of `replay_cycle` against `_REPLAY_CODE_PATHS` surfaces two verdict-determining modules that are **not hashed**:

**(a) `cli/engine/command.py`** — contains `_replay_one`, which is the *sole* place a replay's exception is converted into a verdict:

```python
except HashMismatchError:   return CycleOutcome(..., mismatch=True)
except EngineJournalError:  return CycleOutcome(..., validation_failed=True)
verdict = compare_targets(record.final_targets, replayed)
```

It also holds `_snapshot_reader` (which converts an unreadable parquet into `EngineJournalError` → `validation_failed`) and `_EVALUATE_JOURNAL_REPLAY_PATH`. Editing the exception→verdict mapping changes every future verdict while every hashed module's bytes stay identical — cached verdicts would then be served under the old classification indefinitely.

**(b) `cli/ohlc/dataset.py`** — `read_parquet` produces the `(ts, closes)` that feed *both* `snapshot_content_hash` and the builder. A dtype or timezone-handling change there alters computed hashes and therefore verdicts, again with no hashed module touched.

This is the same class as the two holes already found at review (a verdict-determining module absent from the list). Severity is bounded by a mitigating factor — a change to either module would *usually* accompany a change to a hashed module — but "usually" is exactly the reasoning the design rejects ("over-invalidation costs one rebuild, under-invalidation silently corrupts gate evidence"). I flag it as a design gap for the owner to rule on rather than a proven exploit, since the ten-module list is a spec-fixed number (spec `00060` D3) and extending it is a design decision, not a bug fix.

**Docstring inaccuracy (cosmetic, no safety impact):** `_REPLAY_CODE_PATHS` labels `a1.py`, `a2.py`, `builder.py`, `strategies.py` as "LATENT — only reachable on the verified route". They are in fact reachable on the **fast** route: `cli/portfolio/crossfreq_system.py:53-56` imports all four at module scope and `build_crossfreq_system_fast` uses them. They are covered either way, so this is a comment correction only — but the comment currently understates why they matter, which invites a future cleanup to drop them as dead weight.

## 0. A methodology defect found mid-audit (and fixed) — read this first

My first sweep reported 15 undetected. It was **wrong**, and the way it was wrong matters for how this audit's predecessor should be read.

Python validates a cached `.pyc` against `(source mtime-in-whole-seconds, source size)`. A large fraction of these mutations are **byte-identical in size** — `max(`→`min(`, `14`→`13`, `!=`→`==`, `set(a) != set(b)`→`len(a) != len(b)`, `1e-6`→`1e-3`. When the harness rewrote the file inside the same wall-clock second, Python silently reused the **previous** run's bytecode. The test then ran against code that was not the mutant.

Demonstrated directly:

```
round 0: mutant_reports=13  pristine_reports=13   STALE=YES
round 1: mutant_reports=13  pristine_reports=13   STALE=YES
```

`pristine_reports=13` is the tell — the pristine source says `14`; the interpreter was executing the mutant's cached bytecode.

This is the **same failure class the re-run was commissioned to eliminate** — a test running against code that is not what the auditor thinks it is, producing a green result recorded as evidence. It just arrived via the bytecode cache instead of via a concurrent `git checkout`. Concretely it cost one false verdict: **M35 (tolerance widened 1e-6 → 1e-3) was reported DETECTED in the contaminated sweep and is in fact UNDETECTED** — and it is one of the more serious findings below.

Fix: `PYTHONDONTWRITEBYTECODE=1` on every subprocess plus a `__pycache__` purge before the sweep, verified to restore correct A/B discrimination. **Every number in this report comes from the post-fix re-run**, both for the sweep and for the exploit triage. Any mutation-audit result — including the earlier shared-tree run — produced without this control should be treated as unreliable for same-size mutations.

A baseline-green assertion now also guards the sweep, so a broken harness cannot masquerade as "everything detected."

#### G1 — `_GATE_STREAK_DAYS` is unpinned from below: 13 clean days opens the gate (M02) — **HIGH**

```
- _GATE_STREAK_DAYS = 14
+ _GATE_STREAK_DAYS = 13
```

Tier 1 green; tier 2 green.

```
PRISTINE: 13 clean days -> streak=13 gate_met=False   (correct)
MUTANT  : 13 clean days -> streak=13 gate_met=True    (WRONG)
```

`test_gate_met_on_14_consecutive_clean_days` pins that **14 days is enough**. Nothing pins that **13 days is not enough**. The asymmetry is exact and it falls on the dangerous side: M01 (`>=`→`>`, gate met a day *late*) was caught instantly by the same test, and M03 (threshold→15, also later) was caught — but every mutation that opens the gate *earlier* survives. This constant is the single number deciding whether the strategy may trade real money, and its lower edge is untested.

**Antidote:** assert `gate_met is False` at `streak == 13` in the same test that asserts `True` at 14 — bracket the threshold, don't just sample above it.

#### G2 — a dead journal keeps reporting the gate met (M12) — **HIGH**

```
- upper_bound_day = max(last_observed_day, now.date())
+ upper_bound_day = min(last_observed_day, now.date())
```

```
PRISTINE: 14 clean days then journal DEAD for 5 days -> streak=0  gate_met=False last_failure='missing cycle'
MUTANT  : 14 clean days then journal DEAD for 5 days -> streak=14 gate_met=True  last_failure=None
```

The `max` is what forces evaluation forward through **days that have no entries at all**, so a journal that stopped writing is scored as missing cycles and the streak collapses. Under `min` the window stops at the last journaled day and the stale streak is preserved forever — the gate reports met, with `last_failure=None`, on a node that has been silent for days.

This is the highest-consequence undetected mutant in the sweep: the failure mode is *silent, permanent, and points at "trade"*. No test evaluates a journal whose last entry precedes `now` by more than a day.

**Antidote:** a test with a clean 14-day journal and `now` several days later, asserting `gate_met is False` and a `missing cycle` failure in the silent range.

#### G3 — the comparison tolerance is unpinned across five orders of magnitude (M35) — **HIGH**

```
- def compare_targets(..., tol: float = 1e-6)
+ def compare_targets(..., tol: float = 1e-3)
```

```
PRISTINE: BTC diverged by 1.2e-4 (120x the budget) -> passed=False  (correct)
MUTANT  : BTC diverged by 1.2e-4 (120x the budget) -> passed=True   (WRONG)
```

**This is the mutant the contaminated first sweep scored as DETECTED.** It is not.

The passing test uses diffs of ~1e-7; the failing test uses 1e-2. Everything in between — the entire band from just above float drift to a materially wrong position — is unpinned. `tol` can be inflated a thousandfold and the suite stays green. M34 (→1e-1) was caught only because it happens to exceed the 1e-2 diff the failure test uses; M36 (→1e-12, stricter) was caught by the passing test. So both *ends* are loosely fenced while the dangerous middle is open.

The docstring calls 1e-6 "the cross-environment floating-point drift budget, ~5e-6 of the 0.2 cap" — a specific, load-bearing quantity with no test standing behind it. A tolerance nothing pins is exactly the silent correctness hole the brief called out.

**Antidote:** a test just inside and just outside the budget — `diff = 9e-7` passes, `diff = 1.1e-6` fails — so the constant itself is bracketed rather than straddled at distance.

#### G4 — the daily no-peek hole reopens under a same-length peek (M47, M49) — **HIGH**

```
- if len(ts) != entry.n_bars or ts[0] != entry.first_ts or ts[-1] != entry.last_ts:
+ if len(ts) != entry.n_bars or ts[0] != entry.first_ts:
```

```
PRISTINE: daily tampered in last_ts ONLY (peeked in-progress candle, same length)
          -> EngineJournalError, builder ran 0x
MUTANT  : -> NO RAISE, builder RAN on tampered daily data (returned {'BTC': 0.1})
```

**This is the clearest instance of the meta-pattern the cache audit flagged.** `test_replay_cycle_daily_peek_disagrees_with_metadata_raises_before_build` exists precisely to pin the no-peek guarantee, and its docstring states the general claim — data must be reconciled against declared metadata. But its fixture appends a bar, so the tampered data trips **`n_bars` *and* `last_ts` simultaneously**. The test therefore only pins the **disjunction**: "at least one of the three conjuncts still fires." Each individual conjunct is free.

The exploit is the realistic shape, not a contrived one: a reader that returns the same *number* of daily bars but with the trailing in-progress candle swapped in for the last settled one (drop the oldest, append today's forming bar). `n_bars` matches, `first_ts` matches — only `last_ts` dissents. Under M47 the builder runs on peeked data and `replay_cycle` returns targets computed with lookahead, which then *compare equal* to the journaled targets. The gate sees a clean cycle.

Note the h4 grid is **not** exposed here: `validate_record` independently pins `240`'s `last_ts` to `cycle_ts - 4h`, and line 141 re-derives it again. The daily grid has neither backstop — the reconcile is its only defense, which is why the probe targets daily. M49 (reconcile reduced to `n_bars` alone) is the strictly weaker form and fails identically.

**Antidote:** three separate tests, one per conjunct, each tampering in exactly one dimension.

#### G5 — the `n_bars` and `first_ts` conjuncts are individually unpinned (M46, M48, M50) — **MEDIUM**

Same shape as G4, other conjuncts:

- **M46 / M50** — daily data with a duplicated middle bar: `n_bars` 4 vs declared 3, `first_ts` and `last_ts` both match. Pristine raises; mutant builds on it.
- **M48** — daily data starting one bar earlier: `first_ts` dissents, `n_bars` and `last_ts` match. Pristine raises; mutant builds on a different indicator warm-up window, silently changing the recomputed targets.

Lower severity than G4 only because neither is a *lookahead* leak — they are silent input corruption rather than future information. Same antidote.

#### G6 — the multi-pair shared-calendar check is entirely unreachable by the test fixtures (M62) — **MEDIUM-HIGH**

```
-            elif ts != shared_ts:
+            elif False:
```

```
PRISTINE: 2 pairs, ETH daily calendar DISAGREES -> EngineJournalError
MUTANT  : -> NO RAISE, builder RAN with misaligned series; returned {'BTC': 0.1, 'ETH': 0.2}
```

The guard in `_assemble` can only fire with **≥2 pairs on one grid**, and every `replay_cycle` test uses exactly one pair (`BTC`). The branch is dead with respect to the suite: deleting it changes nothing observable in CI. Production runs a multi-pair universe, where this guard is the only thing preventing per-pair price series with different calendars being zipped into one price dict and handed to the builder — which then produces plausible-looking, silently misaligned targets.

The gap is structural rather than assertion-shaped: no fixture is the right *shape* to reach the code, so no assertion could have caught it.

**Antidote:** a two-pair `replay_cycle` fixture, with one test where the calendars agree (happy path) and one where they don't (raises).

#### G7 — the evaluable-day cutoff anchor and window are unpinned (M09, M10) — **MEDIUM**

```
M09: cutoff = datetime(..., 20, ...) + _FRESHNESS_WINDOW   ->   datetime(..., 16, ...) + _FRESHNESS_WINDOW
M10: cutoff = datetime(..., 20, ...) + _FRESHNESS_WINDOW   ->   datetime(..., 20, ...)
```

```
M09 PRISTINE: now=17:00 on day 14 -> streak=13 gate_met=False   (correct)
M09 MUTANT  : now=17:00 on day 14 -> streak=14 gate_met=True    (WRONG — 3.5h early)
M10 PRISTINE: now=20:05 on day 14 -> streak=13 gate_met=False   (correct)
M10 MUTANT  : now=20:05 on day 14 -> streak=14 gate_met=True    (WRONG — 25min early)
```

Both let a day count toward the streak **before its last cycle is due**, so the gate can flip to met hours early on the final day.

The reason this survives is a fixture choice, and it is the meta-pattern again: `test_intra_day_evaluation_excludes_in_progress_day_without_breaking_streak` picks `now = 09:00`, which is safely below *every* candidate anchor (16:30, 20:00, 20:30) and so discriminates none of them. Only a `now` **between** the candidates has any power here.

**Antidote:** re-run that test at `now = 20:29` (day must still be excluded) and `now = 20:31` (day now evaluable) — that pins anchor and window together.

#### G8 — `last_failure` "most recent" is unpinned (M32) — **LOW**

```
PRISTINE: misses on day2@04:00 and day6@16:00 -> last_failure=2026-01-07 16:00  (most recent, correct)
MUTANT  : -> last_failure=2026-01-03 04:00  (the OLDER one)
```

Every failure test injects exactly **one** failure, so first-reset and most-recent-reset coincide and nothing distinguishes them. `GateStatus`'s docstring explicitly promises "the most recent break," and that promise is unpinned.

Diagnostic-only: `streak` and `gate_met` are unaffected, so no wrong trade/no-trade verdict. But it is the reported reason an operator would act on.

**Antidote:** one test with two failures on different days asserting the later `cycle_ts`.

### 2b. Unpinned but safe-direction / negligible

- **M08** — cutoff `>` → `>=`. Differs only when `now` equals the cutoff to the microsecond. Pristine admits the day at exactly 20:30 (window has elapsed, inclusive — the defensible reading); the mutant is *stricter*. Unpinned boundary instant, no exploit of consequence.
- **M37** — tolerance `<=` → `<`. Differs only when the worst diff is *exactly* `tol`. Measure-zero in floating point and the mutant is *stricter* (fails closed). Worth an inclusive-boundary assertion only if G3's bracketing test is written anyway.

### 2c. Equivalent mutant

- **M55** — removing the `h4_ts[-1] != expected_h4_last` re-derivation changes **nothing observable**, and this is provable rather than merely unobserved. `validate_record` pins `entry.last_ts == cycle_ts - 4h` for grid `240`, and the metadata reconcile pins `ts[-1] == entry.last_ts`; the two together already imply `ts[-1] == cycle_ts - 4h`. My probe (h4 data whose last stamp is `cycle_ts` itself, with honest metadata) is intercepted by the reconcile first, identically in both versions.

  The check is redundant **defense in depth**, not dead weight: it becomes load-bearing the moment the reconcile's `last_ts` conjunct weakens — i.e. M47 and M55 are mutually redundant *for the h4 grid only*. That mutual redundancy is why G4's exploit had to target the daily grid, which has no such second line. Leave the check in; it is cheap and it is the backstop for exactly the failure G4 describes.

## 3. Live defects

**None.** Every finding above is a *coverage* finding: in each case the shipped code behaves correctly and only the guarantee is unpinned. I specifically re-derived, rather than assumed, the pristine behaviour for the two highest-consequence cases — a 13-day streak correctly does **not** open the gate (G1), and a journal that stops writing correctly collapses the streak to 0 with a `missing cycle` reason (G2).

Two adjacent things checked and cleared:

- **Timezone handling** — production passes a tz-*aware* `now` (`datetime.now(timezone.utc)`), while `tests/test_engine_concordance.py` is entirely naive. Not a defect: `evaluate_gate` derives `tzinfo` from `now` and builds boundaries to match, and the aware path is exercised by `test_engine_command.py` / `test_engine_gate_export.py`. Worth knowing that the dedicated concordance suite tests only the naive path.
- **Intra-day `last_failure` attribution** — the per-day loop `break`s at the first failing boundary, so within the final unclean day the *earliest* failing cycle is reported. Defensible (that is the failure that made the day unclean) and consistent with the docstring.

## 4. Ranked remediation

| # | Gap | Severity | Fix |
| -- | -- | -- | -- |
| 1 | G2 dead journal reports gate met | HIGH | 14 clean days + `now` 5 days later → assert not met |
| 2 | G1 13 days opens the gate | HIGH | assert `gate_met is False` at streak 13 |
| 3 | G3 tolerance unpinned 1e-7…1e-2 | HIGH | bracket: 9e-7 passes, 1.1e-6 fails |
| 4 | G4 daily same-length peek | HIGH | one test per reconcile conjunct |
| 5 | G6 multi-pair calendar guard unreachable | MED-HIGH | two-pair fixture, agreeing + disagreeing |
| 6 | G5 `n_bars` / `first_ts` conjuncts | MEDIUM | covered by G4's per-conjunct tests |
| 7 | G7 cutoff anchor/window | MEDIUM | re-run intra-day test at 20:29 and 20:31 |
| 8 | G8 `last_failure` most-recent | LOW | two failures on different days |

The unifying prescription, and the thing worth carrying to the next audit: **the suite consistently pins that a guard fires, and consistently fails to pin which conjunct or which constant makes it fire.** Every gap above is one of two shapes — a conjunction tested only through a fixture that trips several terms at once (G4, G5), or a numeric constant sampled far from both edges rather than bracketed (G1, G3, G7). The classification and attribution logic, which was tested with identity assertions instead, came through the sweep intact.
