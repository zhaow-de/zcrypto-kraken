  (Decision: 1) — CPCV first: it's the cross-validation machinery the rest of the harness and the acceptance

[iter-014] Phase 2 — next harness component after CPCV. (Decision: 1)
CPCV (iter-013) produces the distribution of trial/path Sharpes. Candidates to consume/extend it:
  1. **Deflated Sharpe Ratio (DSR) + Probabilistic Sharpe Ratio (PSR)** — §9.4 multiple-testing control.
     Takes the observed best Sharpe, T observations, trial count N, and the variance of trial Sharpes →
     deflates against the expected-max-under-null benchmark (Bailey & López de Prado). Self-contained,
     pure-function, property-testable; **directly encodes the PoC's "NaN DSR minted a fake winner" lesson**
     by refusing to return NaN (raises on degenerate inputs) — the exact integrity the trial registry asserts.
     Recommended — the deployment-relevant "is this better than noise across all trials?" test.
  2. Stationary block bootstrap CIs (§9.5) — uncertainty bands on Sharpe/maxDD/delta-vs-benchmark. Also
     self-contained, but consumes a return series rather than the trial distribution CPCV just produced;
     logically pairs with DSR later.
  3. Trial-registry hash-chain (§9.7) — extends Phase-0 `cli/registry/`; foundational for logging but less
     tied to CPCV's output; the append-only integrity core already exists.
  (Decision: 1) — DSR/PSR next: it's the multiple-testing correction that turns CPCV's Sharpe distribution
  into a deflated significance verdict, and the NaN-refusal is the single most direct encoding of the PoC
  failure this whole harness exists to prevent.

[iter-015] Phase 2 — next harness component after CPCV + DSR. (Decision: 1)
CPCV (iter-013) splits; DSR (iter-014) deflates a single best Sharpe. §9.4 pairs DSR with:
  1. **PBO (Probability of Backtest Overfitting) via CSCV** — Bailey/Borwein/López de Prado/Zhu. Takes a
     T×N performance matrix (rows = time blocks, cols = strategy configs), and over all C(S, S/2) symmetric
     in-sample/out-of-sample block partitions measures how often the IS-best config lands below the OOS
     median → PBO ∈ [0,1]. Completes the overfitting-detection core (DSR = "is the best real?"; PBO = "does
     selection overfit?"), directly consumes a matrix CPCV-style splitting produces, and its logit is
     bounded in (0,1) by the rank normalization r/(N+1) → same never-NaN discipline. Recommended.
  2. Stationary block bootstrap CIs (§9.5) — uncertainty bands; self-contained but consumes a single return
     series, not the trial matrix; pairs naturally after PBO.
  3. SPA / White reality check (§9.4) — deployment-relevant "beats the benchmark?" test, but it needs the
     Phase-3 benchmark family to exist first; premature now.
  (Decision: 1) — PBO next: it and DSR are the two §9.4 multiple-testing metrics; PBO closes the
  overfitting-detection loop and reuses the combinatorial-split machinery, keeping the harness spine coherent
  before moving to bootstrap CIs and the acceptance suite that ties them together.

[iter-019] Phase 2 — trial-registry hash-chain (§9.7 tamper-evidence). (Decision: 1)
The Phase-0 registry (iter-001) self-hashes each record + checks contiguity/monotone counts, but its own
docstring says the self-hash is "NOT tamper-evidence against a re-hashing writer — that is the Phase-2 hash
chain." Options for the tamper-evidence:
  1. **`prev_hash` field linking each record to its predecessor** — each record stores the prior record's
     `record_hash` (genesis = "0"*64 for the first); since `prev_hash` is in the hashed body, the self-hash
     already covers it, and a new cross-record check verifies `prev_hash == prior.record_hash`. A single-record
     tamper — even one that correctly re-hashes that record (which the current self-hash would MISS) — breaks
     the next record's link. Bump `SCHEMA_VERSION 1→2` (no existing data — trials start in Phase 2). Recommended;
     it's the standard hash-chain, minimal, and closes exactly the gap the docstring names.
  2. A Merkle root / external anchor — stronger against full-suffix re-hashing, but needs an out-of-band anchor
     store; over-engineered for a local append-only-under-flock JSONL at this phase. Deferred.
  (Decision: 1) — the prev_hash chain: minimal, closes the named Phase-2 gap, and its corruption-detection test
  (re-hashing tamper of a mid-chain record → loud failure) is the §9.7 CI acceptance the acceptance suite reuses.

[iter-020] Phase 2 — the acceptance suite (§12 exit bar), scope of the first slice. (Decision: 1)
All harness pieces now exist (CPCV, metrics, DSR/PBO, bootstrap, registry chain). The §9 acceptance triad:
recover a planted signal, reject a null, catch an injected leak (+ registry-corruption, already done iter-019).
  1. **Recovery + null on a synthetic scaffold** — a `cli/validation/synthetic.py` linear-signal generator

  2. Injected-leak end-to-end (serial-correlation + embargo demonstrably removes the inflation) — the subtlest

     careful design), where it joins the registry-corruption acceptance into the full §12 suite.
  (Decision: 1) — recovery + null first: the clean, high-value core of the acceptance suite; the injected-leak

[iter-022] Phase 2 — the injected-leak acceptance test (§9 "look-ahead bug must be caught"). (Decision: 1)
The last acceptance check: demonstrate that CPCV's embargo removes a genuine data leak. A fixed rule can't leak
(no fitting), so the leak needs a FITTED predictor + overlapping labels. Construction options:
  1. **Overlapping-label series + nearest-neighbor-by-index leak metric** — labels `y_t = Σ_{k<H} e_{t+k}`
     (H-sum of iid noise, so `y_t, y_s` share `H-|t-s|` noise terms iff `|t-s| < H`); feature `x_t = t`, so
     the 1-NN-by-feature predictor picks the nearest train index. Metric = mean over test of `ŷ_i·y_i`. WITHOUT
     embargo, a test point at a CPCV block edge finds an ADJACENT train index (overlapping label) → `E[ŷ·y] =
     H-1 > 0` (fake skill = the leak); WITH `embargo=H` the H boundary indices are purged → nearest train is
     ≥H away → `E[ŷ·y] = 0`. Assert leak(embargo=0) clearly positive, leak(embargo=H) ≈ 0. Recommended — a
     genuine, analytically-grounded leak whose removal by embargo is measurable and unambiguous.
  2. OLS-coefficient leak — cleaner model but x⊥y gives β̂≈0 with or without purge, so it does NOT demonstrate
     a leak. Rejected (no measurable effect).
  (Decision: 1) — the overlapping-label NN construction: the leak is real (shared-noise covariance H-1),
  embargo's removal is analytically predicted and empirically checkable, and the reviewer (fresh context)
  verifies the effect is signal not noise — the right way to land the subtle "leak is caught" check.

[iter-023] Phase 2 — SPA / reality-check machinery (§9.4 "beats the benchmark?"), and its variant. (Decision: 1)
The last substantial §9.4 harness component: a data-snooping-corrected test of whether the best of a family of
strategies beats a benchmark. (Multi-seed runner is YAGNI-deferred — the plan de-emphasizes stochastic learners.)
Variant:
  1. **White's Reality Check (unstudentized), reusing the stationary bootstrap** — statistic `V = max_k d̄_k`
     (best strategy's mean outperformance vs the benchmark); bootstrap the time rows, recenter `V* =
     max_k(d̄_k* - d̄_k)`, p-value `= (1 + #{V* ≥ V})/(B+1)`. Correct + calibrated (White 2000), never-NaN
     (no `/std`, p ∈ (0,1]), and reuses `stationary_bootstrap_indices` (iter-016). Recommended.
  2. Hansen's SPA (studentized + data-dependent recentering, SPA_c/l/u) — more powerful/robust but materially
     more complex (variance estimation, threshold recentering) and the `/ω_k` reintroduces a NaN trap. Defer
     the studentized refinement; the Reality Check is the clean, correct v1.
  (Decision: 1) — White's Reality Check: the calibrated, bootstrap-reusing, never-NaN core of §9.4's
  benchmark-superiority test; acceptance = a planted-superior family → low p, an all-null family → FP ≈ alpha.
  The benchmark family it runs against is Phase 3; the machinery is proven on synthetic data now.
