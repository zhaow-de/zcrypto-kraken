[iter-001] Phase 0 kickoff — decomposition & first autonomous package. (Decision: 1)
Phase 0 (master plan §Phase 0) splits into autonomous work (the loop) and human-gated items (parked to
open-topics T0000). Autonomous packages, sequenced: P0-1 trial-registry schema + append-only store +
integrity asserts + unit tests; P0-2 ⏱ reconfirmation-sweep tooling → snapshot register v1; P0-3
NautilusTrader Kraken adapter smoke test → adapter memo. Which to run FIRST:
  1. **P0-1 trial-registry scaffolding** — local, no-network, TDD-able; the prerequisite for the Phase-2
     validation harness; directly encodes the PoC's broken-register lesson (§9: "loud failure on
     corruption"). Recommended — highest foundational value, zero external-dependency risk for an
     unattended run.
  2. **P0-2 reconfirmation sweep** — grounds the cost model, but the ⏱ facts were snapshotted 2026-07-06
     (one day ago), so re-verification adds little now; the value is the reusable tooling. Needs public
     web / Kraken API, whose availability in a headless run is uncertain.
  3. **P0-3 adapter smoke test** — validates the execution bridge early, but needs a heavy dependency
     install + a live Kraken WS connection; higher setup/flake risk unattended.
(Decision: 1) — start with P0-1. Rationale: maximal foundational value, zero network dependency (robust
unattended), and it is the first-class "integrity by construction" product the master plan calls for.
Phase-0 scope for P0-1 = schema + minimal append-only store + core integrity asserts + unit tests; the
hash-chain and registry-corruption CI are explicitly deferred to Phase 2 (per master plan §9).
Parked (human-gated → open-topic T0000): D3(i) account actions (verification-tier check, margin
enablement, API keys — read-only now, trade-scoped created-but-stored-unused) + live-account fee-tier
mechanics incl. the July-9-2026 AoP rule. These require the human's Kraken account; not autonomously doable.
