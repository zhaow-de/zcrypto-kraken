## 2026-07-12 — iter-093: the three-tier topology — Role A (the always-on NAS pull/archive) is LIVE

- **New topology (spec + plan `00048`)**: the durability path moves off the intermittently-online workstation to a **three tiers** — VPS producer (24×7) → always-on **NAS ops node** (Synology, Docker) → intermittent workstation. Failure-domain reasoning: the VPS is uncorrelated with the home ISP; the NAS+workstation share it (≤14 h outage) but the VPS 7-day ring buffer covers that with ~12× margin. Three roles, built incrementally: **A** pull/archive (this iter), **B** gate-verify replay, **C** redundant capture. Human gates (scope A+B+C, RAID-5 durability, reboot-window move, keep-Grafana, uid/gid 1000, plain-POSIX perms) were cleared one-by-one.
- **Role A code** (`cli/archive/`): `zcrypto archive pull SOURCE DEST` — rsync-over-ssh then a manifest hash-verify sweep (`verify_tree` walks `*.parquet`, skips in-progress `.part*`, checks each against its `.sha256` sidecar; a malformed/missing sidecar counts *failed*, never crashes) + a `pull_lag_seconds` dead-man (age of the newest verified segment). **Distinct exit codes**: 2 = transport failure (incl. a missing `ARCHIVE_SSH_KEY`) — a partial pull is never authoritative; 1 = hash mismatch; 0 = all verified. `--no-verify` for sidecar-less sources (the engine journal). Fail-closed ssh: `StrictHostKeyChecking=yes` + a pre-seeded read-only `known_hosts`, `IdentitiesOnly=yes`, `CheckHostIP=no`; `--chmod=D0775,F0664` forces the mandated perms (plain-POSIX share = no ACL inheritance).
- **NAS stack** (`infra/nas/`): a standalone `archive-pull` container under Container Manager (`restart: unless-stopped`, no systemd / no NAS-OS config), `user: "1000:1000"`, an in-container scheduler (`pull-entrypoint.sh`, SIGTERM-clean, hourly default) that runs the capture pull always and gates the journal pull on `JOURNAL_SOURCE` (**capture-only** in Increment 1 — the journal has no sidecars and needs a distinct key). Plus an idempotent plain-POSIX `normalize-archive-perms.sh` (0775/0664, group `zcrypto`).
- **Two-variant image ([[T0029]])**: the NAS Atom C3538 (Goldmont) has **no AVX**, so the standard `polars` wheel crashes `Illegal instruction`. Resolved with a `POLARS_RUNTIME` build arg + a 2-entry CI matrix (`.github/workflows/capture-image.yml`): the **default** multi-arch/AVX `polars-runtime-32` image for the VPS is **runtime-untouched**; an amd64 **`-compat`** build swaps to `polars-runtime-compat` (same polars 1.42.1 — `polars-lts-cpu` is deprecated, `rtcompat` is the maintainer's replacement). The shared image also gained `rsync`+`openssh-client` and a fixed **uid-1000** default user (ssh's `getpwuid` exits 255 otherwise) — both inert on the VPS (its compose overrides `user:`; capture/engine don't rsync).
- **VPS (`capture` role)**: a read-only `rrsync -ro` forced-command channel for the segment pull on a **separate** `sync_capture` key (vaulted private, public in group_vars); rsync installed; `deploy` added to the `kraken-capture` group; unattended-upgrades reboot window **04:00 → 02:00 UTC**. Converged with `--check` showing zero capture drift.
