## 2026-07-20 — iter-110: gate-export incremental scoring — the cost stops growing with the journal ([[T0069]], spec 00060)

- **`zcrypto engine gate-export --cache PATH` replays only what is new** — without the flag the behaviour is unchanged, and `report` is never cached because it is the human-facing verification tool and must genuinely re-verify.
- **The cache invalidates wholesale whenever any module a replay executes changes** — over-invalidation costs one rebuild, under-invalidation silently corrupts the evidence that decides whether the strategy trades real money.
- **Any cache problem degrades to a full replay and rewrites** — absent, unreadable, truncated, wrong schema or fingerprint mismatch; it never aborts and never serves a partially-trusted entry.
- **`zcrypto_gate_cache_replayed_total`, `_hits_total` and `_invalidated` emit always**, zero when caching is off, so a fingerprint that changes every run reads as no hits rather than as a working optimisation.
- **Topics**: T0069 (the code ships inert — enabling `--cache` and the relocation are attended deploys), T0074 (the fingerprint covers replay code, not the execution environment). Design: spec `docs/specs/00060-gate-export-incremental-design.md`.

## 2026-07-27 — desync recovery survives its first attempt failing ([[T0008]], spec 00072)

- **Desync recovery is a bounded ladder that terminates** — the transition resubscribe, three retries, exactly one escalation to a full reconnect, then stop; a cycling ladder turns one stuck pair into a reconnect loop that drops every pair, strictly worse than the defect.
- **Retries are driven by desync state, never by protocol responses** — a snapshot that fails its own checksum produces no error frame at all, so only "still desynced N seconds later" can see it.
- **The ladder's total length is budgeted against the dead-man** — while any pair is desynced the host's watchdog is dark for every pair, so a patient ladder trades one stuck pair for a liveness outage.
- **The parameters are unfitted and the spec says so** — there is no heal-latency distribution to fit; spec `docs/specs/00072-desync-recovery-design.md` carries the two constraints they come from.
- **Capture-daemon code reaches the fleet only through an image build, the secondary canary bake and the primary re-pin** — this merged unrolled, and T0102 took the reply-correlation half split out of it (delivered in the 2026-07-28 entry below).
