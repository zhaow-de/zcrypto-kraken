# BTC on-chain metrics computed from chain data — C3's first step

## Context — what

C3's first step, BTC first: compute BTC's on-chain valuation series — MVRV, MVRV-Z, realized cap, NUPL, SOPR, aSOPR and the STH/LTH split — ourselves from public chain data, with our own Bitcoin Core node and an unmodified Bitview/BRK (Bitcoin Research Kit) at a pinned commit, each UTC day cut by block height and written once as its vintage, and read inside the A1 gate. The route is stock BRK in native USD: each output is valued at BRK's own USD price, its bundled historical exchange prices below height 340,000 and its on-chain oracle from there, and no Kraken close values any output, so the price once to be chosen for outputs created before Kraken's BTC/EUR starts is moot, BRK pricing every height itself; the STH/LTH split is BRK's own 150-day one, "Uses short-term-holder UTXOs younger than 150 days.", fixed by the pinned commit and never tuned; and MVRV-Z, which BRK does not compute, is ours, from BRK's caps, as the STH supply share is from its supplies. LTC and DOGE follow only on a BTC signal worth sharpening. It is the free version on which C3 asks its one question, the marginal value of on-chain regime features inside the A1 gate (`docs/research/00.master-plan.md` §5, C3).

## Why this matters

Every vendor's multi-year on-chain history is restated in place and keeps no vintages, so a C3 backtest on vendor data reads values nobody could have read at the time; computing from chain data is point-in-time by construction from 2013, on public data with MIT-licensed tooling (https://raw.githubusercontent.com/bitcoinresearchkit/mono/main/docs/README.md), the only route the sourcing studies found that also allows trading. Its result decides money: C3 justifies the first paid data dollar "only if the free version shows a signal worth sharpening" (`docs/research/00.master-plan.md` §5, C3), so any Glassnode purchase waits on this topic's BTC reading.
