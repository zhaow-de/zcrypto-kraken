# B2 derivatives-positioning data sourcing (funding / OI / liquidations)

## Context — what

Pre-work for opening the §5 **B2** family — "derivatives-positioning features at intraday horizons (funding, OI, liquidations) as short-horizon de-risking / re-entry triggers for the spot book" (master plan §5). The tradeable book is Kraken EUR spot; the derivatives signals come from USDT-M perp markets elsewhere. The free-data landscape was mapped autonomously (iter-088/089 research, six sources) so the family can open without a blocking data-discovery round — leaving exactly one genuine decision for the human. B2 does **not** open here (no trial, no budget spend); this topic parks the decision the harness spec depends on.

## Why this matters

B2 is the §5 ranked-queue head after B1's kill (T0022) and the A-family close. Its economics were pre-flagged as living on maker-fill realism + turnover control; before any of that, the family needs a data substrate, and the substrate has a hard asymmetry (below) that the master plan's one-line "free external data (Coinalyze/Binance)" note glossed over. Deciding it wrong — e.g. designing a liquidations factor with no free history to backtest it — would waste a trial.

## Findings so far

The full source map (access model, history depth, granularity, exact endpoints/paths, rate limits per source) was captured in the iter-089 research workflow. The decision-relevant conclusions:

- **Funding — solved, keyless, deep.** Primary backfill = **Binance Vision monthly `fundingRate` dumps** (`data.binance.vision/data/futures/um/monthly/fundingRate/<SYM>/…-YYYY-MM.zip`, `.CHECKSUM`-verifiable, 8h cadence, back to each perp's listing). Top up the current month with keyless REST `/fapi/v1/fundingRate`. Bybit v5 `/v5/market/funding/history` (keyless, paginates to listing) is a clean cross-check/backup.
- **Open interest — solved but shallower & uneven.** Only free history source = **Binance Vision daily `metrics` dumps** (`…/daily/metrics/<SYM>/…`, 5-minute `sum_open_interest` + `sum_open_interest_value`, resample to 1h/4h/8h; also ships free long/short + taker ratios). The REST `/futures/data/openInterestHist` is hard-capped at ~30 days → **useless for history, live/top-up only**. Per-symbol OI start dates are later than funding's. **MEASURED at the 2026-07-24 backfill** (this line previously predicted an uneven per-symbol spread — it is not): there are exactly **two** start dates — BTCUSDT from **2020-09-01**, and **all nine other symbols from 2021-12-01**, verified against the CDN (ETH/SOL/LTC all 404 before that date and 200 from it, so Binance simply began publishing non-BTC metrics that day).
- **Liquidations — NOT free-backfillable (the binding constraint).** Binance removed the public `allForceOrders` REST feed in 2021, there is **no Vision liquidation dump**, and the live WS `!forceOrder@arr` stream is **keyless but lossy** — since 2021 it emits ≤1 order/sec/symbol and (2026 doc change) only the *largest* liquidation per 1000 ms window, so any liquidation-volume feature from it is a lower-bound proxy, not the true tape.
- **Coverage / panel.** All 10 names have 5.8+ yr of perp history; a balanced 10-name **funding** panel is bounded by the last listing (~AVAX 2020-09), forfeiting the 2019-09→2020-09 window BTC/ETH alone would give. **But funding is not the binding leg.** The measured OI panel starts **2021-12-01** (above), so a balanced funding+OI panel — what the first B2 trials actually run on — **starts 2021-12-01, and OI is the constraint, not funding.** SOL & AVAX are the thinnest legs. Kraken EUR spot is far longer for the pre-2020 tokens (DOGE/LTC/XRP/LINK/ADA) — the derivatives layer is the short leg, so B2 features start years after the spot book does.
- **Aggregators.** **Coinalyze** — free, all 10 names, dedicated funding/OI/**liquidation** history endpoints, 40 calls/min — but intraday history is a purged rolling window (1h ≈ 2–3 months, deleted daily) → **live-only, no multi-year backfill**; needs a free account + API key. **Coinglass v4** — deepest single-vendor backfill (native 8h, ~1 yr hourly, daily all-time) and the natural place to *buy* liquidation history, but **no free API tier** and commercial use licensed only from **$299/mo Standard**. **Laevitas** — Enterprise-gated (~$500/mo) or x402 pay-per-call; funding is an OI-weighted aggregate (won't map 1:1 to single-venue raw funding).

## Done so far

- **Funding substrate DELIVERED (iter-090, spec/plan `00047`)**: `cli/derivatives/funding.py` (checksum-verified Binance Vision monthly `fundingRate` backfill, bounded retry-with-backoff) built `data/derivatives-funding/` — 10 USDT-M perps, 68,281 realized-funding prints, **`basket_sha256 e08ea1a9…`**. QA matches this topic's coverage prediction exactly (balanced-panel start 2020-09-22, AVAX); the one flag — SOL's 4h→2h funding in the 2022-11 FTX-collapse window — is a real venue action preserved via `interval_hours`. This was the first human-gate-independent half; **OI followed 2026-07-24 (below); only liquidations remain** (live-only by the owner's ruling).

- **OI backfill TOOLING DELIVERED (2026-07-23, branch `feat/t0023-oi-substrate`)**: `cli/derivatives/oi.py` + the `derivatives-oi` `data rebuild` target — the sibling of the funding build, checksum-verified Binance Vision **daily `metrics`** dumps (5-minute `sum_open_interest`/`_value` + the free long/short and taker ratios), leading-404-skip with an interior-hole error, typed/sorted/deduped 5-min series into `data/derivatives-oi/<PERP>/oi.parquet` with a funding-shape manifest. 18 TDD tests plus real-data proofs. **Two early-history data patterns the first full run surfaced (and the code now handles + pins with tests):** (i) 2020-09→~2021-05 metrics publish **every row twice, byte-identical** — the `ts` dedup collapses each to one bar; (ii) some early rows leave the ancillary `sum_taker_long_short_vol_ratio` **blank** (e.g. BTCUSDT 2020-09-27) while the OI columns are populated — an empty ancillary field now parses to **null** rather than aborting the run (the first strict-parse run *did* abort on it, which is how it was found). Also handled: midnight boundary bars appearing in two daily files with differing values (a deterministic `maintain_order` dedup keeps the owning day's). The "clean 288-bar 5-min cadence" holds for recent data; early history is raggeder, which is why the guards above exist. **Confirmed the Coinalyze substitution does NOT touch this**: OI comes from `data.binance.vision` (the dump CDN, measured non-geo-fenced, T0023:32), not the geo-fenced `fstream.binance.com` live WS that forced Coinalyze; and Coinalyze cannot serve deep OI anyway (its intraday retention is a ~2–3 month rolling window). **SUBSTRATE DELIVERED 2026-07-24 (PR #201):** the full 2020→present run completed — 10 series, **5,010,882 rows**, `basket_sha256 e9f7344c…`, ~189 MB — promoted to the canonical unstamped `data/derivatives-oi/`, registered in `authored_sets`, pushed to the NAS hub (verified there) and catalogued, so the ops node can `data fetch` it. The run surfaced two further issues, both fixed and pinned: Binance publishes each day's metrics **~1-2 days late**, so the trailing frontier 404s are tolerated up to a bounded `_MAX_TRAILING_LAG_DAYS` (a longer tail gap is an outage/delisting and still raises), and a transient CDN **503** now retries with backoff while 4xx stays definitive. **OI columns are dense (zero nulls); the four ancillary ratio columns are nullable** (BTCUSDT ~15% null toptrader ratio) — consumers must treat them so. **Follow-ups (registered):** (1) the fetch/checksum/unzip flow in `oi.py` is a near-copy of `funding.py`'s — dedup into a shared `cli/derivatives/vision.py` when either is next touched (kept separate now to leave the delivered, in-use funding module untouched pre-departure). (2) **HTTP 429 is not retried.** `_get_bytes` retries 5xx (the CDN 503s under a long sequential backfill) but treats every 4xx — including 429 Too Many Requests — as immediately fatal, because a 404 must stay definitive for the leading-404/frontier logic. A ~40k-file sequential downloader against a public CDN is arguably as likely to hit 429 as 503; the completed backfill never did, and failing loud is the safe direction (no silent data loss), so this is a hardening gap rather than a defect. **Fix it inside the shared `vision.py` when (1) happens** — that consolidation is the natural place to add 429 to the retryable set for both modules at once. (Both surfaced by the 2026-07-24 reviews.)

- **2026-07-15 — Binance futures WS is GEO-SILENT from every egress we own.** The forceOrder recorder (built + reviewed + deployed, spec 00051 OPS-2) connects fine but receives zero frames — and so does a plain `btcusdt@aggTrade` control on `fstream.binance.com`, from BOTH the home-LAN (DE) and the Linode egress, in both URL forms. Handing the aligned funding frame to the funding trio is the mistake this item exists to prevent: on a 1h grid it inflates every sign run eightfold and shrinks a 90-print window to 3.75 days, it is perfectly causal so the truncating-prefix guard is blind to it, and no test in the harness can see it. Lands with the B2 family.
