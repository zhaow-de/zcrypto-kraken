# The reconciler books unfilled silence as healed, and double-counts it as permanent loss

## Context — what

Split out of [[T0101]] on 2026-07-27. Measuring the 2026-07-27 07:00 UTC capture blackout against the parquet — rather than against the reconciler's own ledger — found four defects in `cli/archive`, all in the same direction: the reconciler over-states what it repaired and under-states what was lost.

For that one hour the ledger claims **2,311.536587 s healed** across 11 pairs, each record carrying `residual_seconds: 0.0`. Measured from the files:

| quantity | value |
| --- | --- |
| claimed `healed_seconds` | 2,311.536587 s |
| **actually healed** (canonical hole vs primary hole) | **82.955463 s** — 3.59% |
| secondary rows spliced in | 2,434, of which **2,200 are eleven 200-row single-timestamp snapshots** |
| genuine `update` rows justifying the claim | **234** |
| total span of the spliced secondary blocks | 69.997211 s |
| L2 permanently absent from the canonical archive | **2,437.147792 s** across 12 pairs |

LINK/EUR is the sharpest case: **6 update rows, booked as 209.493793 s healed.** Their spliced block spans 1.638743 s from its single snapshot; the update rows themselves span 0.005246 s across 3 distinct timestamps.

## Why this matters

**The counters that are supposed to tell us whether redundancy is working are the ones that are wrong**, and they fail in the reassuring direction. `zcrypto_reconcile_healed_gap_seconds_total` is the number an operator reads to conclude "the secondary covered it"; for this event it over-stated the repair by 27×.

It also **double-books**. `fleet_dark_windows` (`cli/archive/settle.py`) ends a dark window on any row type, while `secondary_covers` (`cli/archive/reconcile.py`) accepts only `type == "update"`. So the fleet-dark window is a strict subset of every primary gap, and **198.820666 × 11 = 2,187.027326 stream-seconds landed in both** a "we covered it" counter and a "nobody covered it" counter in the same cycle. Both are in stream-seconds, so the overlap is a true double-count, not a units artifact.

**The mechanism is not broken in general — it is broken in exactly one shape.** The 2026-07-17 drill (primary deliberately stopped, secondary genuinely up) healed **99.8444%** for real. It over-claims when *both* mirrors go dark together and the secondary contributes only its post-resubscribe tail. That shape is precisely the one the test suite never constructs.

Bounded blast radius, measured rather than estimated: the ledger's lifetime `healed_seconds` is 17,821.065725 s across exactly two hours, of which **2,228.581124 s (12.5053%) is fictional — all of it this one event**. (An earlier revision of this file said 2,252.718188 s / 12.6408%; that figure reconciled with neither of the two measurements beside it and is superseded by the direct one below, which re-runs the window arithmetic over the minted parquet itself.)

## Findings so far

- **The trigger was re-based on 2026-08-22 (owner-approved), because the old one could not be met and said so itself.** It required three distinct non-zero daily values *from steady state after the 2026-07-28 counter fix*, named 2026-08-27 as the earliest plausible date with a scheduled reminder, and added that a flat-zero series means re-park with a new floor rather than fit anyway. Measured 2026-08-22: `increase(...[1d])` produced **zero** non-zero days across every day the datasource can answer for, with the counter flat at 18850.166149 and `changes(...[90d])`/`resets(...[90d])` both 0 — so the flat-zero case is the one that occurred. **That window is ~14 days, not 30**: Grafana Cloud holds no sample of this series, nor of `up{job="integrations/unix"}`, before ~2026-08-08, so everything earlier is *no data* rather than zeros — the same trap [[T0129]] registers, where a `[30d]` selector was read as thirty days of evidence over a series that had not lived that long. The ops-host reconcile ledger is this counter's own source of truth and reaches further if a longer baseline is ever wanted. The trigger now states the spread condition alone, since a date is not the condition and the rule forbids one. **The 2026-08-27 Slack reminder is not gone and cannot be** — a scheduled Slack message cannot be deleted through the API, so it will land in `#zcrypto` on the day. Treat it as a prompt to re-read this topic, not as a trigger. If it stays flat that is itself the answer: the threshold this topic wants to re-derive guards a condition that is not occurring, and the re-derivation should be dropped rather than waited on.

- **`healed_seconds` measures the input, not the output.** `cli/archive/command.py` computes `healed = sum(gap.seconds for gap in gaps)` — the full *width* of each primary-silence window — before the splice, and never revises it against what the splice actually inserted. The admission gate is only `secondary_covers`, whose own docstring says *"True iff the secondary has at least one **update** row inside `gap`"*: **one row books the whole window.**
- **`residual_seconds` on a minted record is a hardcoded `0.0`**, as is the `residual_gaps=[]` passed to `mint_hour` — which is why every provenance sidecar reads `residual_gaps: []`. On a `both_streams_silent` record it *is* measured.
- **A pair with a real gap and no update witness produces NO ledger record at all.** ADA/EUR's 208.566668 s hole — the largest in the canonical archive for that hour — is invisible to `healable_gap_seconds_total`: the secondary held 200 rows inside the gap, all `type='snapshot'` at a single timestamp, zero updates, so `secondary_covers` was False, `find_book_gaps` returned `[]`, and the `if not gaps: continue` path wrote nothing. **The gap-rate signal is blindest exactly where the damage is worst.** (ADA/EUR also has no reconciled file at all, so `canonical_segments` falls back to the raw primary.)
- **`trade_deficit` records book `residual_seconds: 0.0`** — 18 of the ledger's 47 records; suspected at the time to be the symmetric defect for trades. **Enumerated since, and it is not one**: every one of the 18 is a *secondary* deficit (`trades_added = 0` in all 18, 1,926 secondary rows in total across 2026-07-14T18/19, 07-17T16 and 07-23T19/20), so the canonical stream lost nothing and the `0.0` is correct. See *Done so far*.
- **The residual counter under-states too, and separately.** This event's residual was booked as the intersection window × stream count (2,385.847992 s) rather than each pair's own hole, under-stating the measured per-pair loss by **51.299800 s**. Closed — a healed hour books its own unfilled remainder on top of the fleet share, and each stream is booked its own window rather than the intersection; **6.821701 s** remains unbooked under the landed code, all of it ADA/EUR's (see *Done so far*). **The same intersection-vs-own-window shortfall measures 34.243169 s on the 2026-07-13 event** — closed 2026-07-28, see *Done so far*. An earlier revision attributed that one to an hour-boundary straddle; the straddle is real but small, **1.203668 s fleet-wide** (0.002794 s DOT … 0.308901 s ETH), so it explains 3.4% of the difference and not the rest.
- **A minor predicate asymmetry that did not bite here** (fixed — see *Done so far*): `fleet_dark_windows` kept windows `>= min_seconds` while `find_book_gaps` requires strictly `> min_gap_seconds`, so a window of exactly 30.0 s was residual-booked and never heal-considered.
- **Every minted file now carries TWO snapshots** ~7 s apart (the spliced secondary one and the primary's own resubscribe). Measured on `BTC/EUR` hour 07: 07:04:27.350301 and 07:04:34.576215; the raw primary has one. Consumers that reset the book on every snapshot row discard whatever the splice inserted — so for such a consumer the effective heal of this event is ≈0 s. Whether that is a defect here or in the consumer is undecided; see [[T0104]].
- Provenance sidecars (`*.provenance.json`) record the blocks actually spliced and are the cheapest assertion surface for a fix: `healed_seconds` vs `sum(secondary block spans)` is a **pure file assertion over data already on disk**, needing no replay harness.

### The alert inversion — observed live, 2026-07-27

| --- | --- | --- |
| *Reconciler · residual gap increased* (**critical**) | fired 09:18:35Z, **false-resolved 10:18Z** via `grafana_state_reason = MissingSeries` — 60 min | **correct**: 2,437 s permanently gone |
| *Reconciler · primary gap rate high* (**warning**) | active since 09:48:00Z, re-notified 4× (11:48 / 15:49 / 19:50 / 23:53 CEST), **still firing 24 h later** | its summary says *"Every gap was covered"* — **false**; only 82.96 s was really healed |

So the alert that got the facts right went quiet after an hour, while the one asserting the fiction has re-notified four times and continues until the 24 h window rolls past the ledger append (~09:12Z). Its `A` value is pinned at **2313.14** across all four notifications. That is the fictional healed figure this topic exists to correct, paged repeatedly as though it were reassurance — and it does not equal the ledger's **2,311.536587 s** exactly because `increase()` extrapolates a counter step to its window edges (the same arithmetic that returns ~1.0007 for a single increment, recorded under [[T0008]]'s alert leg). The ~1.6 s difference is the extrapolation, not a second event.

This is live evidence rather than analysis, and it raises the ranking: fixing the counters (above) also fixes what the warning *says*, and the `increase(...[1h])` window (below) is what silenced the page that was right.

## Done so far

**The counters now measure the splice** — `cli/archive/{reconcile,command,mint,settle}.py`, commit `1da2ea52`. `measure_residual` re-runs the window arithmetic over the frame actually minted; `healed_seconds` becomes claimed − unfilled; the unfilled remainder reaches the provenance sidecar as real `residual_gaps` instead of a literal `[]`; the new `claimed_seconds` field keeps `healable_gap_seconds_total` — the degrading-primary *rate* — denominated in primary silence, because a correlated outage is not the primary degrading. `fleet_dark_windows`'s `>= min_seconds` became `> min_seconds`, so the two silence predicates agree and a window of exactly 30.0 s can no longer be residual-booked while never being heal-considered.

**The double count is gone in both directions, and neither side recomputes.** Each side subtracts what the *ledger records* the other already booked (`overlap_seconds`): a per-pair record subtracts the ledgered `both_streams_silent` windows for its own stream, and that fleet record in turn subtracts whatever a stream's own book record already booked. Subtracting a *fresh recomputation* instead was measured wrong in both directions — a pair whose mirrors land after the fleet decision was never given a share of it (its whole loss vanished), and an unreadable segment suppresses the detector for a cycle, so a pair minting meanwhile books first and the fleet record would book the same seconds again. `residual_seconds` also joined the per-(pair, kind, hour) dedup `healable` already rode: an hour ledgered `would_mint` and then `minted` carries the same measured residual twice, and the second step reads to the CRITICAL page as a fresh permanent-loss event.

**Validated on a known answer before its verdicts were read.** Re-run over the real ledger and the minted parquet on the NAS (read-only):

| hour | claimed | measured healed | fiction |
| --- | --- | --- | --- |
| 2026-07-17T15:00 (the drill — primary deliberately stopped, secondary genuinely up) | 15,509.529138 s | **15,509.529138 s** | **0.000000 s (0.0000%)** |
| 2026-07-27T07:00 (the blackout) | 2,311.536587 s | **82.955463 s** | 2,228.581124 s (96.4112%) |

The drill hour is not slandered by the stricter measure — the guard against "correcting" a genuine heal into a phantom. And the blackout's 82.955463 s reproduces this file's independently derived figure *to the microsecond* by a different method (that one compared the canonical hole against the primary hole; this one re-runs the arithmetic over the minted rows), which is why the fiction figure above is the one that changed rather than this one.

**The `trade_deficit` residual is not a defect — measured, then dropped.** All 18 records enumerated from the ledger: **every one is a SECONDARY deficit, `trades_added = 0` in all 18**, 1,926 secondary rows missing in total (2026-07-14T18/19, 07-17T16, 07-23T19/20). The canonical trade stream lost nothing, so `residual_seconds: 0.0` on those records is correct rather than a symmetric blind spot. Permanent *trade* loss cannot appear in a `trade_deficit` record at all: rows absent from both mirrors are invisible to a cross-host union, and `zcrypto archive backfill-trades` already measures them as `unrecoverable`. Consciously dropped, with the measurement as the reason.

**An unwitnessed gap now leaves a record** — `find_unwitnessed_gaps`, commit `38f4e100`. It is the exact complement of `find_book_gaps`: both filter the same `_primary_silence` windows, so together they partition every primary-silence window wider than the threshold and none can fall between them. **Visibility only, on the owner's ruling** — ledgered and logged at WARNING, contributing to no series, because whenever the fleet was dark those seconds are already booked by `both_streams_silent` (a counter here would double-book them), and when the fleet was not dark, one pair silent on both mirrors is indistinguishable from a quiet market. The witness rule itself is unchanged: a snapshot is full state, never market activity, so the remedy is to report the window rather than relax what counts as a witness.

**Each stream is booked its own window now, not the intersection** — `containing_dark_window`, commit `ad0f84b4`. The intersection is bounded by whichever stream returned FIRST, so `intersection × count` charged every stream with the binding stream's loss: 34.243169 s (1.27%) invisible on 2026-07-13. The booking is **per-intersection-window** rather than per-stream-window, which is the whole design — booking every window a stream was dark for would move the thin-market false positive out of *detection*, where the fleet-wide intersection exists to resolve it, into *quantification*, where it lands in a monotone counter driving the CRITICAL page. Deduplicated per stream (two intersections exist only because another stream ticked between them, so a stream that did not tick has one window spanning both), computed from **both** mirrors' stamps, and the record carries `stream_windows` so `_booked_dark` subtracts exactly what was added. Pre-split records carry only `windows`, and there that WAS what got booked — both shapes are tested, and exactly-once was verified numerically on the real 07-27 hour (0 mismatches at 1e-9, in both cycle orders).

**Two things this does NOT do, both caught in review rather than left to be discovered.** It *bounds* the thin-market false positive rather than excluding it — the containing window is still the stream's own undecidable silence, and a constructed 31 s fleet blip inside a 600 s thin-pair quiet books 976.5 s against a truth of 372 s. What makes it safe today is the universe, not the algorithm: across all 24 hours of 2026-07-26, both mirrors, all 12 pairs, the maximum natural silence is **11.44 s** and there are **zero** windows above the 30 s threshold, so the containing window exceeds the intersection only by about twice the per-stream spacing. Re-measure that distribution before admitting genuinely thin pairs. And it does **not** fix the cross-hour straddle, which is re-registered below rather than folded in.

**Two of the three alert defects are fixed and PUSHED LIVE** (`infra/grafana/alerts.yaml`; pushed to Grafana Cloud 2026-07-28 on the owner's authorization, and read back from the provisioning API rather than trusted from an exit code — `residual-gap` now `range.from=86400` with `increase(...[24h])`, `healable-gap-rate` now carries the `scalar(count(count by (pair) (...)))` divisor. All four reconciler rules evaluate `health=ok` with no `lastError`; `healable-gap-rate` is `inactive`, correct now that the 07-27 event has rolled out of its 24 h window). The CRITICAL permanent-loss page now evaluates over 24 h instead of 1 h — the window *is* how long the page stays up, which is why a correct 2,437 s page went `MissingSeries` sixty minutes after firing. And `healable-gap-rate` is divided by the live pair count, so its threshold is wall-clock seconds and its existing "more than 10 minutes" summary becomes true *without touching the number* — verified against live Cloud, 600 ÷ 12 = 50 exactly, reproducing the figure this topic derived by hand. That also leaves the blocked re-derivation cleanly available. Both are pinned by tests comparing the summary's stated quantity to the evaluator's.

**What the corrected counters book for the blackout hour**, re-measured under the code as landed: 82.955463 s healed, and **2,430.326091 s** of loss — the per-pair residual is now 0.000000 s, fully absorbed into the wider fleet windows, so the attribution MOVED rather than duplicating. Against the measured 2,437.147792 s of permanent loss. The remaining **6.821701 s** shortfall is ADA/EUR's: it has no *minted* record to carry its own remainder, so only its 201.744967 s share of the fleet window is booked. It now at least leaves an `unwitnessed` record naming the window (above); the 6.8 s that remains is the unwitnessed-gap exposure registered in [[T0108]]. Two adjacent classes stay unrecorded by the command rather than by the detectors: a pair-hour with a primary file and **no secondary file** is skipped before either finder runs, and an hour minted in an *earlier* cycle is skipped by `already_minted`, so at deploy the already-minted hours inside the 48 h window get no retrospective `unwitnessed` record.

- **The CRITICAL page's summary reword is LIVE** (verified 2026-07-29: the repo text and Grafana's provisioned rule are byte-identical). Its gate — the counter fix running in production — was satisfied by the ops converge of 2026-07-28 15:59.
- **The 2,228.581124 s of existing fiction is recorded, not erased** (2026-07-29). A note record was appended to the ledger: `state: "correction"`, carrying `overstatement_s` 2228.581124 and `measured_actually_healed_s` 82.955463 of a claimed 2311.536587, and **no counter field**. Proven counter-neutral before the write by running the real `_totals` over the live ledger with and without it — all eight counters identical. A record that instead *lowered* `healed_gap_seconds_total` would read to Prometheus as a reset and make `increase()` report the post-reset value as fresh healing, louder than the fiction it corrects.
- **Two claims in this file were wrong and are corrected.** The ledger does **not** live on the NAS: the writer copy is `/var/lib/zcrypto-ops/capture-reconciled/reconcile-ledger.jsonl` on `zcrypto-ops`, and the NAS holds a pulled replica (both read 13719 bytes at the same mtime before the append). So the append is an ordinary `ssh` write to ops, not an NFS-mount problem — appending on the NAS would have been orphaned by the one-way ops→NAS pull. And `_totals` does not *filter* unknown states: it adds `record.get(...) or 0.0`, so the record is ignored because it carries no counter keys, not because its state is unrecognised — the safety depends on that and would end the moment a counter field were added.

- **The cross-hour straddle is accepted, not outstanding** (2026-07-29). Measured at 1.203668 s fleet-wide on the 2026-07-13 event — 0.045% of its 2,696.031909 s — and **not** structurally bounded by `min_gap_seconds` — a claim this topic carried until 2026-07-29 and which does not hold: H−1 books a stream's tail only when the *fleet*-dark window there clears the threshold, and that is bounded above by the stream's own, so a thin pair quiet well before the boundary can straddle far wider. The real bound is the measured silence distribution (max 11.44 s, all 12 pairs, both mirrors, 2026-07-26) — which also degrades correctly if a genuinely thin pair joins the universe, where the structural claim simply fails. Closing it costs an H−1 segment read per pair on every fleet-dark hour, which the measured share does not justify. Its previous trigger (">1% of a single event") was invented to keep the item on the list: nobody measures per-event straddle share, so it could never have fired. The decision now lives where someone meets it — a comment at the clamp in `cli/archive/settle.py`, and `infra/runbooks/capture.md#cross-hour-straddle`.
