## D1 — the attempts log: one per clone, in the main checkout's `.local/`, hash-chained, created once

- Built: `cli/registry/attempts.py`, class `AttemptLog` over `.local/trial-attempts.jsonl` in the main checkout. The path is `git -C <code root> rev-parse --git-common-dir`, resolved against the code root when relative, its parent being the main checkout — the resolution `infra/scripts/sweep.sh:65` makes — so every worktree and every session of the clone writes one file, and `git worktree remove` takes none of it; `.local/` is gitignored (`.local/.gitignore:1`) and kept (CLAUDE.md's layout line).
- Lines are JSON in the registry's canonical form (`canonical_json`), each with a contiguous `seq`, the previous line's hash as `prev_hash` and its own `line_hash` (the format section); appended under `fcntl.flock` and `fsync`'d as `store.py:151-175` does, through an append of its own, since `_append_locked` hashes a `datasets` block a line before the fit cannot have (`store.py:166`), and which refuses a short write — `os.write` returns the count it wrote and raises nothing when a full disk cuts the line — so an append returns only once its whole line, `\n` included, is written; read under the same flock through `_read_healing`, so another session's line half written is never taken for a torn one and truncated away, and any malformed line but a torn last one refuses — a torn last line being any last line without its `\n`, parseable or not, which under the flock only an append that refused or a writer that died leaves, so no number was printed past it. **Author's call** — the log copies itself aside before it heals: it is unversioned, and CLAUDE.md has unversioned data copied aside before a tool rewrites it, so before a torn last line is truncated the whole file is copied to `<log>.torn-<UTC stamp>` beside it, the chain is re-verified over the healed file as read back from disk, and the copy is deleted only after that verification passes; a heal whose verification fails keeps the copy and refuses, naming it. Line 1 is the genesis line: `log_id`, 32 lowercase hex from `secrets.token_hex(16)`, and `host`, `socket.gethostname()`.
- **Author's call** — the log is created by its own command, `zcrypto research attempts-init`, which writes the genesis line to an absent path and prints the row D6's allowlist needs; `eval` never creates it, so a lost log is never silently replaced by a fresh one on a trial's path. The build PR runs it once on the workstation and commits the row.
- Runs: on the workstation, inside `zcrypto research eval --register` and `zcrypto research attempts-init`; never in CI, which cannot see it — D8 carries what CI needs into the tree.
- Refuses: `attempts-init` over an existing path, empty or not; a read whose line 1 is not a genesis line, which holds a second genesis line, whose `seq` skips, or whose `prev_hash` or `line_hash` does not hold; a common dir whose parent is no checkout (`--separate-git-dir`, a bare clone's worktree), as `sweep.sh:66-69` refuses it.
- Remedy printed — no remedy names a copy that nothing makes: "<path> exists: a log is created once, never beside the records that cite it; for a damaged one, rename it aside, then restore it from a backup if one exists; otherwise create a new log with zcrypto research attempts-init and add its id to docs/reference/trial-attempt-logs.txt by PR, saying what was lost"; "<path>: line <n> <what breaks>: rename it aside, then restore it from a backup if one exists; otherwise create a new log with zcrypto research attempts-init and add its id to docs/reference/trial-attempt-logs.txt by PR, saying what was lost"; "<path>: the healed log breaks at line <n> <what breaks>, and its bytes before the heal are kept at <copy>: rename it aside, then restore it from a backup if one exists; otherwise create a new log with zcrypto research attempts-init and add its id to docs/reference/trial-attempt-logs.txt by PR, saying what was lost"; "no main checkout at <dir>, resolved from git rev-parse --git-common-dir: run from a clone with a working tree".

## D3 — the count: every attempt counts once, as the record it became or as an orphan

- Built: `reconcile` in `cli/registry/attempts.py`, a pure function of the log's lines and the landed records and readings, and `landed`, which reads them with no network — the target `--registry` and `--ledger` files, and the committed registry and ledger at `HEAD` and at `origin/develop` through `git show`. **Author's call**: the target files too, so a branch's own records count as landed for a run appending beside them, and `HEAD`'s too, so a scratch target misses none of them. A record counts once: by its `attempt` (log, id) when it carries one, else by its `record_hash` (records 1–48).
- Each attempt of the local log falls in exactly one class, tried in this order:
  1. landed — its (log, id) is some landed record's or reading's `attempt`, or in its `absorbs`;
  2. absorbed — a later attempt has the same subject, the same arguments (spec 00129 D1's invocation keys without `commit`), the same `spec_hash`, the same `metrics_hash` and the same verdict or stop, since the same numbers are the same look; an attempt with a `begin` and no `end` is absorbed by a later attempt with the same subject, arguments and `spec_hash` that reached its `end`; a rule edit that flips the verdict on equal metrics absorbs nothing, and both attempts count; an attempt some landed record's `counted` lists is absorbed by no attempt but this run, whose record then lands it through its `absorbs` (the listed orphan's class is final, below);
  3. stopped — its `end` stored the subject's `no_verdict`: it counts 0, as B2 trial 1's stop did ("the trial is unspent", `docs/research/10.phase4-decisions.md:247`); the stored outcome is read and the rule never re-evaluated, so widening a rule's stop after a look cannot reclassify the look;
  4. failed — **Author's call**: its `end` stored `failed`: it counts 0, since nothing printed;
  5. orphan — every other attempt: it counts 1 against its family and 1 against its bucket.
- **Author's call** — an open attempt counts but is never listed: at register time another session's attempt with a `begin` and no `end` counts toward `required_n` and `spent` (or is held out, below, when this run may absorb it), but a record's `counted` (D8) lists only finished orphans — attempts whose log carries an `end` line and that no record or reading has landed, which under the classes above are those whose `end` stored a verdict, since a stop or a failure counts 0. The tree therefore carries only finished orphans, whose class cannot change: the stored outcome is read and never re-evaluated, and a listed attempt is landed or an orphan, never absorbed by an attempt that does not land it. The carry rule below and CI check (xii) apply to those alone. An open attempt that never ends — a run killed mid-fit — keeps counting in its own log and reaches no record; a retry with its arguments absorbs it.
- **Author's call** — the count also carries the finished orphans any landed record's `counted` lists (D8) that no record or reading has landed since, from any log: the tree already holds them, so a second clone or workstation counts what a record has listed (the recommendation carried them per log).
- For family F in bucket b: `required_n(F)` = landed records of F + orphans of F + 1; `spent(b)` = landed records of b + orphans of b; a bucketless family (P1) has no `spent`.
- **Author's call** — provisional absorption: before the fit, an unlanded attempt with this run's subject, arguments and `spec_hash` is held out of the orphans, since this run may absorb it; after the `end` line, each held-out attempt is classified as every other is, this run now among the later attempts, and one this run does not absorb and that neither stopped nor failed is an orphan after all; when `required_n(F)` then exceeds the declared `n_trials` the run is refused after its print, both attempts counting. A same-arguments retry of a run refused after its print for anything but its count therefore needs no higher count; a re-run after a code change that moves its numbers does. The count a refusal on the count names (D4's `<m>`) is `required_n(F)` with this run, after the print, classified as any other attempt, and with the open attempts of this run's subject, arguments and `spec_hash` held out when the remedy asks for a raise, since the raised run absorbs each of them whatever its numbers, and nothing held out when it asks for a new subject, which absorbs no attempt of this one. For a new subject that figure is exact. For a raise that leaves the subject's spec file, so its `spec_hash`, unchanged, it is the figure that always admits, since the raised run holds every open attempt the figure left out and absorbs a finished one only on equal numbers and outcome: exact where the raised run's numbers move with its `n_trials`, which a non-zero `var_trials` ensures short of the deflated Sharpe's saturation at 1.0; where they do not — `b2-funding-derisk`, whose kill bars pass `var_trials` 0.0 (`cli/research/subjects.py:325`, `:404`), so `expected_max_sharpe` is 0.0 at any n (`cli/validation/dsr.py:20-21`), or a deflated Sharpe already at 1.0 — the raised run can return the old numbers and absorb a finished attempt made at the old count, and its record's `n_trials_in_family` then stands one above the count for each, which a subject may declare and its deflated Sharpe ignores. A raise that changes the spec file changes `spec_hash`, so the raised run holds none of those open attempts: it is refused before its fit, nothing printed, its refusal naming the full count, which a second raise meets.
- Staleness: a stale `origin/develop` moves an attempt between landed and orphan and never drops it, so no fetch is needed and the count works offline; what a stale ref can hide is a record another log landed on develop since the last fetch, which check (ix) catches on the PR's merge ref.
- Runs: on the workstation at register time, inside D2's critical section: about 35 ms of local git — six `git show` reads at 4–6 ms and two `rev-parse` calls at 1–3 ms (measured per call above) — against a fit of minutes.
- Refuses: an `origin/develop` that does not resolve (**Author's call**: a clone without it has no floor to count from); the refusals the count drives are D4's and D5's.
- Remedy printed: "origin/develop does not resolve in <root>: run git fetch origin develop, then run again".

## The record and log formats

The attempts log, `.local/trial-attempts.jsonl` in the main checkout — one JSON object per line, canonical form, `line_hash` the `compute_hash` of the line without it, `prev_hash` the previous line's `line_hash` (64 zeros on line 1), `seq` contiguous from 1. The genesis line, line 1 and only line 1:

```json
{"seq": 1, "kind": "genesis", "log_id": "<32 lowercase hex>", "host": "zcrypto-ops",
 "timestamp": "<UTC ISO-8601>", "prev_hash": "<64 zeros>", "line_hash": "<64 hex>"}
```

A `begin` line, written under the lock after the count (D2 step 3); `attempt` contiguous from 1 over the log's `begin` lines; `branch` null on a detached HEAD; `bucket` the family's in `BUCKET_OF` at the time, null for a bucketless family:

```json
{"seq": 2, "kind": "begin", "attempt": 1, "timestamp": "<UTC ISO-8601>", "host": "zcrypto-ops",
 "worktree": "<absolute code root>", "branch": "research/<name>",
 "invocation": {"subject": "<subject>", "dataset": "ohlc-full", "window": null, "as_of": null,
                "accept_holes": false, "comparator_trial": null, "commit": "<40 hex>"},
 "spec_hash": "<64 hex>", "family": "B1", "bucket": "B", "n_trials": 4,
 "registry": "<absolute path>", "ledger": "<absolute path>",
 "prev_hash": "<64 hex>", "line_hash": "<64 hex>"}
```

An `end` line, naming an attempt with a `begin` and no earlier `end`; exactly one of `verdict` (one of `adopt`, `reject`, `park`), `stop` (the subject's `no_verdict`) and `failed` (`<class>: <message>`) is non-null, and `metrics` and `metrics_hash` (`compute_hash(metrics)`) are null exactly when `failed` is not:

```json
{"seq": 3, "kind": "end", "attempt": 1, "timestamp": "<UTC ISO-8601>",
 "verdict": "park", "stop": null, "failed": null,
 "metrics": {"<key>": 0.0}, "metrics_hash": "<64 hex>",
 "prev_hash": "<64 hex>", "line_hash": "<64 hex>"}
```

A record at schema 6 adds `attempt`; `absorbs` holds ids of the record's own log below its `id`; each `counted` entry is a finished orphan as its `end` line held it, `verdict` one of `adopt`, `reject`, `park` and `metrics` the end's, never null, since an open attempt is counted and never listed (D3) (**Author's call**: the key is `verdict`, not the recommendation's `outcome`, since a stop or a failure is never an orphan):

```json
"attempt": {"log": "<32 hex>", "id": 7, "absorbs": [5],
            "counted": [{"log": "<32 hex>", "id": 3, "family": "B2", "subject": "<subject>",
                         "spec_hash": "<64 hex>", "verdict": "reject", "metrics": {"<key>": 0.0}}]}
```

A reading at schema 2 adds `attempt`, `{"log": "<32 hex>", "id": 4, "absorbs": []}` on a ruled subject's stop and `null` on a ruleless subject's reading.

The allowlist, `docs/reference/trial-attempt-logs.txt`, one row per log ever listed, never removed:

```
<32 lowercase hex> zcrypto-ops
```

## The CI checks

Over the committed files at HEAD — the PR's merge ref in CI — enumerating every record past 48, each at schema 6 by D8's floor, and every reading past 1, each at schema 2; "landed" is every (log, id) a record or reading carries as `attempt` or in `absorbs`. Each check gets a synthetic case that fires alone, beside `test_a_clean_b2_trial_yields_no_finding`.

- (vii) `family == SUBJECTS[subject].family`.
- (viii) `n_trials_in_family == SUBJECTS[subject].n_trials`, the count the subject's verdict deflated at (D4).
- (ix) `n_trials_in_family` ≥ the records of its family before it, from trial 1 + its `counted` entries of its family + 1; a record another log landed on develop after the author's last fetch makes this fail on the PR, naming the figure needed.
- (x) for each bucket in `BUDGET`: its records, from trial 1, + the distinct (log, id) its records' `counted` entries name and nothing landed ≤ `BUDGET[b]`; and every family a record carries is a key of `BUCKET_OF`. This is the first code enforcement of a budget: today only the per-key floor exists (`store.py:86-92`).
- (xi) every `attempt.log`, and every `counted` entry's `log`, is a row of `docs/reference/trial-attempt-logs.txt`; a (log, id) appears at most once across all `attempt` and `absorbs` of records and readings; a reading's `attempt` is non-null exactly when its subject has a rule.
- (xii) carry-forward: for each record K in bucket b — family F, for a bucketless family — every (log, id) a record before K in b lists in its `counted` is in K's `counted`, unless a record or reading lands it; truncating the log after a record listed an orphan therefore fails the next registration's PR in that bucket. **Author's call**: across logs, not per log as the recommendation had it, since D3 carries a listed orphan from the tree on any machine. Every entry a record lists is a finished orphan, which the store's form check holds (D8), so (xii) carries only attempts whose class cannot change (D3).
- The literals: `BUDGET` and `BUCKET_OF` asserted equal to the values D5 gives; every ruled subject's `family` a key of `BUCKET_OF` and its `n_trials` an int ≥ 1, a ruleless subject declaring neither; the allowlist's rows `<32 hex> <host>`, ids distinct; and each landed subject's `n_trials` pinned (D4): a literal maps every subject a committed record's `invocation` names to its `n_trials`, today `{"b1-hourly-rv": 3}`, equal to the subject's declaration and to each such record's `n_trials_in_family`, and a subject's first landed record adds its row in the PR that lands it.

## What stays prose

The design closes none of these; each is named so no reader takes it for checked. From the read's §2.8:

- Scratch drivers and direct `build` or `append` calls: spec 00129 calls making them uncallable "a convention" (`docs/specs/00129-trial-provenance-design.md:179`); its D5 replay catches a forged record (`:111`), but an unregistered look leaves nothing.
- Development runs before a subject has a rule, and an uncommitted edit that drops `verdict=` for one plain eval — the clean-tree read guards `--register` and `--reading` alone.
- What counts as a trial rather than an experiment or a reading: the census lists iter-058 to iter-142 as declared zero spend.
- Whether a subject's `var_trials` includes a counted orphan's Sharpe: the tree holds the numbers (D8), and plan-review decides per trial.
- Tampering with the log's tail before any record lists the orphan: the chain is recomputable by anyone, and only a record's `counted` fixes an orphan in the tree.
- A lost machine or disk: nothing in the tree holds the log (D11 rejects the mirror), and the workspace transport's other machine holds a copy only as of the last transport, so a loss takes every orphan no record has listed and that copy lacks; a backup is the operator's, nothing in the tree makes one, and the new log's PR says what was lost.
- A second workstation: the workspace transport's two machines share one log under one id, and attempts logged on both since the last transport fork it; the transport refuses to carry a copy over a longer or forked one (D6), and which copy goes on after a fork is the operator's, its pull request's account of what the other held read by a reviewer, not checked. A workstation the transport never reaches keeps a log of its own, listed under its own id, whose orphans reach the tree only at its own next registration — after which D3 carries them on any machine.

Added by the author:

- A second clone on the same workstation: its own common dir, so its own log, listed under its own id — the case of a workstation the transport never reaches, on one disk (READ · the skeptic on the attempts log).
- An expansion PR's quote of the owner's ruling, and a fresh log's PR account of what was lost: each is read by its reviewer, not checked.

## Non-goals

Backfilling records 1–48 or reading 1 with an `attempt` block: the files are append-only and hash-chained, and the floors at 48 and 1 exempt them by id, frozen. The mirror, pre-registration rows, the open-PR rule and a nightly reconcile (D11). Re-evaluating a stored outcome under today's rule. Changing what the deflation counts: `n_trials_in_family` stays per family key and the budget per bucket, as master plan `:256` and `:323` have them. A report command listing orphans: a refusal names them, and the tree holds every listed one. Making `TrialRegistry.append` or a build uncallable. A merge-gate arm: nothing in `infra/scripts/merge-gate.py` reads the registry, and every check here runs in the required suite.
