- Schema 5 adds one field, `invocation`, with exactly these keys — the run's arguments plus the code's commit:

- The store checks its form at append and at load, with no disk read and no git (the layering `cli/registry/record.py:72-75` keeps): `subject` a non-empty str; `dataset` a key of the record's own `datasets`; `window` null or two str; `as_of` null or `YYYY-MM-DD`; `accept_holes` a bool; `comparator_trial` null or an int at least 1 and below the record's own id (D3); `commit` 40 lowercase hex. `append()` takes `invocation` as a required keyword and writes schema 5; beside the floor at 46, a second floor refuses at load any record past 47 below schema 5 — so a record past 47 without an invocation does not load, and `tests/test_registry_store.py::test_live_registry_file_loads_clean` fails CI on it, as it does for spec 00086 D4's floor.

## D3 — the comparator is computed in the same run; a trial compared against by id is backed by a subject

## D4 — the verdict is the subject's rule from its spec

- `Subject.verdict` is the spec's decision matrix as a pure function of the stored metrics. A subject with no rule is evaluate-only: `--register` refuses it, and it records only readings (D7). A rule returning `None` for a run is a stop — no verdict, no trial spent — and D7 keeps the run as a reading whose outcome is the subject's `no_verdict` text.
- The command computes the verdict. `--verdict` becomes an optional assertion: typed and different from the rule's, a stop included, it refuses and nothing is written. `--spec-hash` likewise: the command computes it from the subject's spec at the clean HEAD, and a typed one that differs refuses — so an author can pin the spec a review read.
- CI recomputes the rule over every record past 47, ungated, since it is a pure function: `record.verdict == verdict(record.metrics)`.
- `b2-funding-derisk`'s rule is spec 00128 D6's four rows plus the two instrument findings its metrics show; the third finding there, the inputs' block hash against the measured basis, is not a metric and stays a pre-flight step of the plan that registers:

```python
def _b2_verdict(m: dict) -> str | None:
    if not m["arm_a_passes"] or not any(m["engaged_per_year"].values()):
        return None  # instrument finding: no verdict, the trial unspent
    if not m["passes"]:

```

- A consequence, not a new rule: T0214's re-price, a planned record, registers through the command like any record past 47, so its spec writes its subject and its rule.
- Options weighed: a typed verdict (today: measured, `adopt` stored on invented numbers); a rule checked only in CI (rejected: a mistyped verdict would reach a PR before anything says so); the rule in the command and in CI (chosen).
