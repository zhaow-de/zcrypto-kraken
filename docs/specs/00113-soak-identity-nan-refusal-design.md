# The soak's identity check refuses a comparison it could not make

## Problem

`realized_internals` (`cli/engine/soak.py`) carries spec `00059` D2's window-wide identity proof: every scored cycle's journaled `final_targets` must equal the rebuilt row to `tol`. It counts each `(record, asset)` pair into `compared` and then decides on two comparisons of the same value — `diff >= worst_diff`, which moves the worst-case detail, and `diff > tol`, which drives `identity_ok`.

A NaN `diff` is False on both. So a comparison whose operands make `diff` NaN increments `compared`, never moves `worst_diff`, and never drives `identity_ok` to `False`. A window whose every comparison is NaN reports `identity_ok: True` with `identity_detail` still reading `at n/a` — the identity checked and agreeing, over nothing measured.

`identity_ok is False` is what `soak_report` turns into the `realized-internals identity mismatch` void reason. `True` is the pass, and the pass is what a go-live decision reads: `soak_report` places no trade but steers whether trades are placed at all.

## Decisions

**D1. The refusal belongs at the comparison, and that is the guarantee rather than the belt.** The competing placement — validating the scored records at the read, the way `latest_record` already is — closes it for every consumer of those records at once, and it is the better-sounding answer. It is not the one this spec takes, and the reason is measured rather than argued from blast radius.

The rebuilt side of the comparison is not provably finite. `_validate_grid` (`cli/portfolio/crossfreq_system.py`), the fast builder's own front door, checks the prices dict's shape, its key set against `config.assets`, the ts stamps' type and strict ordering, and each series' length. It never tests a close VALUE. What refuses a NaN price today is `float.as_integer_ratio()` raising deep inside the rolling statistics — an accident of exact rational arithmetic, not a guard anyone wrote, and the builder's own docstring already warns that the two paths' error behaviour is not gated where their outputs are. The verified path's refusal — `AlphaError` or `BenchmarkError`, by which grid carries the NaN — is a written guard; the fast path's `ValueError` is not. So "the rebuilt side cannot be NaN" is true today and rests on nothing anyone would notice removing.

A refusal that holds by design therefore has to sit where the wrong answer is produced. Read-side validation remains a good idea and stays available as the belt — as `T0194`, not here.

**D2. A non-finite `diff` is counted as UNMEASURABLE, and is neither a comparison made nor a mismatch found.** The test is the finiteness of the `diff`, never which operand produced it — and that is load-bearing rather than incidental. The measured basis below got its own premise wrong once, claiming NaN was the only input reaching the silent path when two matching infinities reach it too; keying on the diff makes the decision survive that error, because the arm catches a non-finite `diff` whatever produced it. A decision that needed the premise to be right would have shipped the hole. The loop gains a second counter beside `compared`. `compared` keeps its present meaning — comparisons actually made — so a NaN pair increments `unmeasurable` and not `compared`. Counting it as `compared` is what produces the defect; counting it as a mismatch would put a number in `worst_diff` that no measurement produced.

**D3. Any unmeasurable comparison makes `identity_ok` False.** `None` is not available as the answer for a partly-NaN window, and this is a fact about the consumer rather than a preference: `soak_report:1718` reads `if internals.available and internals.identity_ok is False`, so `None` appends no void reason and the run is not voided. Answering `None` would move the silent pass one branch over rather than close it.

`False` is the honest direction for an instrument that steers a go-live decision: the identity was not established, and the failure must be *refuse to certify*, never *certify what was not measured*. The objection that `False` names a mismatch nobody found is answered by D5's detail string, not by weakening the verdict.

**D4. The unmeasurable check is evaluated BEFORE the `compared == 0` arm, and this ordering is a decision rather than an implementation detail.** `T0183` added `identity_ok = None` when `compared == 0`. Under D2 an all-NaN window has `compared == 0` and `unmeasurable == n`, so the two arms are reachable by the same input and the order decides the answer. Evaluated in the other order, the all-NaN window — the exact case this spec exists to close — falls through to `None` and does not void. The `compared == 0 and unmeasurable == 0` case keeps `T0183`'s `None`; those two remain disjoint, and it is the ordering that keeps them so.

**D5. `identity_detail` states the unmeasurable count, the first pair it could not compare, and that pair's two operands.** Its reading `at n/a` on an all-NaN window today is the symptom, not a cosmetic gap: the field exists to carry the *why*, and a `False` with no detail sends a reader to look for a magnitude that was never computed. When `unmeasurable` is non-zero the detail names the count, the first offending `cycle=`/`asset=`, and the journaled and rebuilt values beside the worst-diff text it already carries, so a reader can tell *the rebuild disagreed* from *the record could not be compared* without opening the journal. The operands are load-bearing rather than decorative: D2 keys the arm on the `diff`, so the arm itself never decides which side went non-finite, and D1's own reading is that the rebuilt side is not provably finite — a coordinate alone would send a reader to the journal for a fault that may not be there.

**D6. The void reason distinguishes the two, because the operator's next action differs.** A mismatch means the rebuild disagrees with what was journaled; an unmeasurable comparison means an operand of that comparison is not a number — which of the two, the arm does not say, because D2 keys it on the `diff`, and D5's detail carries both so the operator does not have to guess. Both are void. `soak_report` appends `realized-internals identity mismatch` today and gains a second string for the unmeasurable case; neither carries an internal traceability token, so `operator-facing-text.md` is satisfied either way. When both hold — a measured comparison over `tol` AND a comparison that could not be made — the reason names the unmeasurable case, because a partial measurement is the weaker claim; nothing is lost, since D5's detail line carries the worst measured diff and the unmeasurable count together. One field carries this: `RealizedInternals` gains `identity_unmeasurable`, the count, which the `--json` payload publishes beside `identity_ok`. A second boolean for *mismatched* would exist only to emit a second void reason the detail already states.

**D7. The guard's fixture is NaN-ONLY, with a true positive beside it.** A fixture that also breaks the identity by magnitude passes under the defect for the wrong reason and proves nothing about this change — the `diff > tol` arm fires on the magnitude and `identity_ok` goes `False` with or without the fix. The defect fixture is therefore one scored record whose journaled target for an asset is `float("nan")` against a rebuilt row that is a real number and matches everywhere else. Beside it, `test_realized_internals_identity_holds` is the true positive and must stay green: a healthy window still reporting `identity_ok: True`, or an always-refusing check ships green. The mutation that must turn the new assertion red is the removal of the unmeasurable arm.

## The measured basis

Every premise below was produced by a command against this branch's base, `398ed686`.

**The arithmetic, and NaN is not the only input that reaches the silent path.** With `worst_diff = 0.0` and `tol = 1e-6`, six operand pairs measured: `nan` against a finite value gives `diff = nan`, `False` on both bars — silent. `inf` against a finite value, and `-inf` against `inf`, give `diff = inf`, which is `> tol` — caught today, as a mismatch. But `inf` against an equal `inf`, and `-inf` against an equal `-inf`, give `abs(inf - inf) = nan`, `False` on both bars — silent, exactly like the NaN case. Two MATCHING infinities are therefore a second silent input, and an earlier draft of this spec claimed NaN was the only one. Two finite floats cannot produce a NaN `diff`, and cannot overflow to `inf` at the magnitudes a portfolio weight takes.

`math.isfinite(diff)` is `False` on all six of those pairs, including the three the `> tol` bar already catches. That is a consequence D2 must own rather than discover: under it, an infinite journaled target against a finite rebuilt value stops being reported as a mismatch and is reported as unmeasurable instead. Both void the run; the reason string changes and D5's detail records which. That is the right reading — an infinite target is a corrupt record, not a disagreement of magnitude.

**`_validate_grid` never tests a close value.** Read at `cli/portfolio/crossfreq_system.py`: it refuses a non-dict or empty `prices`, a key set unequal to `config.assets`, a `ts` that is not a list of at least two stamps, a non-`datetime` stamp, a `ts` not strictly ascending, and a series whose length differs from `ts`. There is no finiteness or positivity test on any element.

**The fast path's refusal is incidental.** One NaN close injected into `synthetic_grids(220)` at six placements — first, middle and last bar of the daily grid and of the 4h grid — makes `build_crossfreq_system_fast` raise `ValueError: cannot convert NaN to integer ratio` at every one of the six. The same input makes `build_crossfreq_system` raise a written refusal carrying the message `prices must be None or finite positive numbers, got nan` — `AlphaError` at the three 4h placements, `BenchmarkError` at the three daily ones. `AlphaError` (`cli/alpha/errors.py`) and `BenchmarkError` (`cli/benchmark/errors.py`) are separate direct `Exception` subclasses, so neither is a `PortfolioError` and neither is caught at `realized_internals:827`; D1's argument is unchanged, because both are guards someone wrote. The baseline grid builds with every `final_targets` value finite. `build_crossfreq_system_fast`'s docstring states the asymmetry itself: *"outputs are gated, error paths are not — on degenerate inputs the verified path may raise where this path returns a result."*

**The journaled side is unvalidated, and it is the reachable NaN source.** `cli/engine/soak.py:1658` loads every record with `records = [from_json(p.read_text()) for _, p in arts]` and never validates. `realized_internals` calls `validate_record` at `:824` on `latest_record` alone. `validate_record` does refuse a non-finite `final_targets` value, so the guarantee exists — it is just not applied to the records whose values reach the comparison. `_expand_to_basket` (`cli/engine/cycle.py:308`) carries each model value onto its `/EUR` leg unchanged and fills the two `/BTC` legs with `0.0`, so it neither introduces a NaN nor removes one.

**The call-site census.** `validate_record` has exactly four production call sites: `cli/engine/concordance.py:78`, `cli/engine/cycle.py:686`, `cli/engine/feeders.py:84`, `cli/engine/soak.py:824`. The writer is `cycle.py:686`, which validates before journaling — which is why an artifact this engine wrote is guarded and one arriving by any other route is not.

**The consumer.** `soak_report:1718` voids on `internals.identity_ok is False` alone; `None` appends nothing. `realized_internals:827` catches `(EngineError, PortfolioError)`; `class PortfolioError(Exception)` and `class EngineError(Exception)` are both direct `Exception` subclasses.

**The existing tests this change lands beside.** `tests/test_engine_soak.py` carries `test_realized_internals_identity_holds` (the measured pass), `test_realized_internals_identity_is_unmeasured_with_no_scored_record` (`T0183`'s `None` arm, including the empty-targets route through the inner loop), and `test_realized_internals_shift_breaks_identity` (the mismatch arm). They monkeypatch `build_crossfreq_system_fast` with a fake result, so the NaN fixture is built by giving one scored record a `float("nan")` target against that fake — no builder run, and no dependence on the incidental `ValueError`.

## Out of scope

**`T0193` — a non-finite snapshot close escapes the soak report as a traceback — is deliberately excluded, and the reason is that it carries an unanswered design question rather than a mechanical fix.** The `ValueError` above is caught by nothing: not `realized_internals:827`, not `soak_report` (the call sits in the `else:` of the `build_null` try, unwrapped), and not `cli/engine/command.py`'s soak command, which catches only `EngineError`. So the function's docstring contract — a failing build returns `available=False` — is false for that input class. The obvious repair may be the wrong direction: `available=False` would make the failure QUIETER than a traceback, degrading a go-live run into a report that reads almost normally. That fork is a decision for its own topic, and folding it into a spec written to close a silent pass would settle it by convenience.

**`T0194` — several journal readers never validate the record they read — is the belt D1 names, and is excluded for blast radius.** Moving validation into the read reverses `from_json`'s documented position that schema stays "the caller's separate concern", and would make journal artifacts that load today raise on the live trade path. It needs the reader enumeration `T0194` asks for first.

**`cap_consistent` is not swept.** Its `breach` comparison reads a NaN as False the same way, but `apply_position_caps` refuses a non-finite position on the way in, so `combined` and `capped` are finite by construction. The topic states this and it is not re-litigated here.

**No change to `tol`, to spec `00059` D2's identity itself, or to what `compared == 0` means.** This spec adds an arm; it does not restate an existing one.
