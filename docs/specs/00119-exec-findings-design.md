# Rung 1's execution findings: a reprice waits for its tick and crosses through the IOC, the ledger reader matches margin rows, and a restart settles the intents it orphans

## Problem

## Decisions

The decisions fall in five clusters. D1 to D6 are the reprice ladder, D7 to D12 the ledger reader, D13 to D16 the adopt pass after a restart; the third cluster is the one the owner may strike at the spec review, and nothing in the first two depends on it. D17 to D21 are the re-cancel on reconnect, the third cluster's pass at one more moment, so the fourth stands or falls with the third; D22 to D25 are the gate gauges after a restart, on nothing but the executor's tick.

**D1. A reprice prices off a tick newer than the one that priced the order it replaces.** `_ActiveIntent` gains `quote_seq`, advanced by every tick `on_quote` stores (both sides usable), and `priced_seq`, set by `_place` to the `quote_seq` the order was priced at. `_reprice` resubmits at once when `quote_seq > priced_seq` and otherwise enters a new phase, `awaiting_reprice`, from which `on_quote` resubmits on the next stored tick. Two other identities were read and set aside: the tick's `ts_event` or `ts_init`, which the executor never reads, the test fixture hard-codes to 0 and the node test's ticks do not carry, so a timestamp needs a tolerance for a missing field that a counter does not; and a touch that differs from the priced one, which strands the wait until the time-box on a feed that ticks on size alone, when a new tick at the same touch is the venue's book re-read, which is what the crossing asked for, and the count bound covers a second crossing. The cost is one tick of latency per reprice on a resting instrument, and six existing tests gain the quote line the reprice now waits for. Entering the wait detaches the ended order, `client_order_id` and `order` cleared, so `_on_order_event` routes a fill racing the cancel or a replayed ack through the detached path, which appends without a state claim and credits `filled` through `_claims`, and a replay spends no budget. Two other routings were set aside: a phase test in `_on_order_event` that sends the waiting intent's events detached while the ids stay, which leaves the ids naming an order the venue ended, so a trip during the wait would cancel that order again through `_cancel_resting`; and stopping only `_on_fill`'s row write from reopening a closed row, which leaves a replayed ack reaching `_on_cancel_ack` and counting a crossing. The cost is that a trip during the wait cancels nothing of the intent's own, which is true of the book, and that the ended order's row is written by the detached path alone. When the tick arrives with less than one lot step left, `_resubmit` ends the intent `filled`, `_on_fill`'s completion test at the one path every resubmission takes; ending it at the detached fill itself was set aside, since that path is built to claim nothing, and leaving it to sizing was set aside, since a zero remainder is `BelowMinimum` there and the intent would end `partial` carrying its whole quantity. `_poll`'s `awaiting_reprice` arm runs the same test first, before its three checks, since a completed intent starved of ticks would otherwise end `revoked` on silence or the kill file, the plan halted, or `partial` on rest-cancel's box, its whole quantity in `filled_qty` either way. The cost is one comparison on every resubmission, the IOC ladder's included, and one on every timer tick of the wait, that changes an outcome only when a detached credit completed the intent. A one-sided tick is not stored and so is not the tick the reprice waits for.

**D2. While a reprice waits, the intent is bounded as a resting one is: the gate level, quote silence and the time-box, checked in `resting`'s order.** `_poll` gains an `awaiting_reprice` arm, D1's completion test at its head. Nothing rests, so a level the intent no longer clears, or `_QUOTE_SILENCE` (30 s) since the last stored tick, ends the intent on the tick with no cancel: `revoked` with the verdict's reasons or `quote_silence`, and the plan halted, as every revoke halts it. The time-box takes `_on_cancel_ack`'s requested arm less the cancel, `_time_box_with_nothing_resting`: `execute` crosses through the IOC fallback, `rest-cancel` ends `rest_cancel_ok` or `partial`, `rest-hold` ends `rest_hold_expired` or `partial`. A bound of its own for the wait was set aside: the silence bound already says when the feed is dead, and a second constant is a second number to keep true. `_publish_resting_age` counts `resting` alone, so the gauge reads 0 while a reprice waits, which is true of the book. A raise inside the resubmission, which now runs in `on_quote`, refuses the intent with `filled` carried, `_submit`'s rule. Silence is proven to outrank the box by a wait whose silence bound and time-box are both past: silence ends it, not the IOC.

**D3. In `execute` mode the crossing that spends the maker budget crosses through the bounded IOC fallback; the rest modes keep `unfilled`.** The sixth crossing (`reprices > _MAX_REPRICES`, 5) calls `_fallback`: at most `_MAX_IOC_ATTEMPTS` (3) limit-IOC orders at the stored opposite touch, each sized to the remainder and gate-evaluated in `_submit`, and the intent ends `unfilled` with `the bounded fallback did not fill` only once both budgets are spent. `rest-cancel` and `rest-hold` end `unfilled` with `reprice budget exhausted` as today, since a mode built never to fill may not take. Ending `unfilled` on the maker budget alone was set aside: the T0090 ruling is maker-first with a taker fallback because an unfilled leg strands the tax probe, and the measured window needed a second plan placed by hand. Waiting for a fresh tick before each IOC was set aside too: an IOC is price-bounded, so a stale opposite touch costs an attempt and never money, and the time-box path fires its IOC off the stored quote today. The operator text's `unfilled` now means both ladders were spent, and the runbook line says so.

**D4. No plan field bounds a taker order; `mode` stays the one switch.** `probeplan.py`'s `_INTENT_KEYS` is unchanged. The IOC's limit is the opposite touch the tick showed, so a buy pays at most that ask and a sell receives at least that bid, and the fill is never worse than the book the tick showed; the notional beyond the declared one is the remainder times the spread, and the plan cap (`exec_max_plan_notional_eur`, 100 EUR) was checked on the declared notional at pickup. A per-intent slippage or taker-permission key was set aside: it would be a new `_INTENT_KEYS` entry an older engine refuses whole, for a bound the limit already gives. Re-running `_over_cap_reason` at the IOC price was set aside: it runs for `qty` intents alone, a spot disposal, a sell, whose IOC at the bid is bounded by the book.

**D5. Each order's row records the quote that priced it: `bid`, `ask` and `quote_seq` inside the row's `order` payload.** `_ROW_KEYS` in `execledger.py` is unchanged, so the schema version stays 2 and no readers-before-writer deploy is owed; `validate_exec_record` does not read inside `order`. A reader sees two rows of one intent sharing a `quote_seq` as two orders priced off one tick — the count restarts with each intent — the reading that took a hand replay of the 2026-09-25 log. A top-level row key was set aside: `EXEC_SCHEMA_VERSION` 3 and the ordered deploy, for three numbers.

**D6. `_on_cancel_ack`'s venue-cancel arm keeps repricing an `execute` order whatever the cancel's reason.** Keying on `payload["reason"]`, `Post only order` against `User requested`, was read and set aside: the reason is the venue's text, unpinned across adapter versions; an operator's stop for an `execute` order is the kill file, which revokes within one tick; and a hand cancel followed by a reprice is bounded by D1's tick and D3's count. This is an explicit drop, not a deferral.

**D7. `margin` rows are matched by `refid` exactly as `trade` rows are.** `_MATCHED_LEDGER_TYPES = {trade, margin}` in `cli/engine/tracking.py`; a matched row counts under `matched` (rows, one per asset leg, as before); an unmatched one FAILS the reconciliation with its id named, the runbook's rule that every unmatched id is explained or is a stop; a matched or unmatched margin row counts as a comparison, so a window whose engine activity is margin alone reads `ok` or `FAILED`, never `insufficient-data`. Carrying leverage onto `Fill` so that a margin fill must match a `margin` row was set aside: type discipline the check does not need, since the reader's job is every venue row explained.

**D8. A matched row contributes its `fee`, and never its `amount`, as a reported figure beside the rollover total; the blend stays on the journal's fills.** `matched_fees_eur` sums the `fee` of matched rows whose `asset` is a euro code or `EURC`, under one set, `_EURO_FEE_ASSETS`, that the rollover arm reads too: the venue charges a margin open's fee in EURC after converting euro to it at par beside the row, the export's `collateralconversion` pair (the BTC/EUR open of 2026-09-25: a `margin` row with fee `0.084000` EURC beside `-0.0840 EUR / +0.084000 EURC`), and the adapter reports that fill's commission in euro, so the journal already counts it at par (0.08 EUR for that fill); the report prints the sum as the venue's own fee total over the journaled fills the export's rows matched — the window's total only where the export's span covers the window, which the reader does not compare (the reverse direction, under Out of scope), so the runbook has the operator read the export's `time` span against the window first — beside the journal's cent-rounded fees the blend carries (0.32 EUR journaled against the venue's 0.3269 in the window, 0.2429 of it on euro rows and 0.0840 on the EURC row). A `margin` row's `amount` is the position's realized PnL, a result, summed nowhere. Two options were set aside: replacing the journal's fee with the ledger's inside `cost_blend`, which would have a run without an export propose a different rate from one with; and nothing, which leaves the venue's exact figure nowhere to be read beside the journal's.

**D9. `settled` and `collateralconversion` are known no-fill types, counted under `known` and printed on their own line; `ignored` keeps the types the reader has not met.** `_NO_FILL_LEDGER_TYPES` gains both. `settled` is a hand settle's delivery pair, which the journal holds no row for by design (a hand settle is counted, logged and nothing else); `collateralconversion` is the venue's own currency swap for a margin fee, keyed to the position's opening trade, a swap and not a cost. Failing on either was set aside: a sanctioned hand act would fail every window that settles by hand. The rendered block gains `rows with no fill behind them by construction: <type> <count>` for `known`, and its `row types this reader places nowhere` line keeps `ignored` and names it as the types to settle against the export that carries them.

**D10. The rollover and matched-fee figures print at four decimals.** The export's euro `fee` column carried four (0.0040, 0.0795, 0.0794), and the runbook's comparison demands equality with the hand read, which two decimals cannot give: 0.016 printed 0.02. The JSON carries the float, and the sum stays a float sum, since four rows of 0.0040 sum to 0.016000000000000000333 and the print rounds it; Decimal arithmetic was set aside as a conversion the JSON value would need for a difference below the print. The `basis` text and the matched line read `ledger trade or margin row(s)`.

**D11. The rollover arm keeps summing every euro `rollover` row regardless of `refid`.** The hand read it is compared with is the whole export's, so the two agree by construction; splitting engine positions from hand-opened ones by the opening trade id is a reading the `refid` makes possible and this spec does not take.

**D12. The closed world of row types is a fixture, `test_every_row_type_of_the_real_export_lands_in_exactly_one_place`.** It carries the six types the export carried, in the sixteen-column header and with the export's own asset spellings (`EUR`, `BTC`, `EURC`), one row per arm: `trade` (`tradespot`, one row per asset leg), a `margin` row charged in euro and one charged in EURC beside its `collateralconversion` pair, `rollover` under the opening trade id, a `settled` pair under an id of its own, and `deposit`; it asserts `ignored` empty and the EURC fee inside the figure. A seventh type is a fixture row, Minor. The shape is the export's and the figures are synthetic: the real export carries account figures and is not committed.

**D13. A rest-hold intent does not survive a restart.** The pass cancels a non-reducer (spec 00108 D3 and D4 ruled the restart's adopt pass unchanged and its cancel the drills' expectation), and `restart_hold` holds the gate at `REDUCE_ONLY`, where `_level_permits` refuses an open intent; re-arming the hold from the row's `OrderAccepted` stamp would contradict both. The cost is a drill whose induction spans a restart losing its subject, which is drill G's own expectation.

**D14. After classification, the pass settles every `pending` intent of the two-day window from what its rows show; an intent with an open row the pass sent no cancel for stays `pending`.** A new `execledger` accessor, `pending_plan_intents`, lists every (boundary, plan_id, index) still `pending`; no process runs those plans, since this one starts with `_plan` None and the plan wall refuses a re-drop, so nothing else would ever end them. Each is written through `update_plan_intent` at its own boundary, without `self._plan`: `filled` when the sum of its rows' `filled_qty` reaches the first order's quantity, taken as the largest `order.qty` among its rows since every later order is a remainder, within `_OVERFILL_TOLERANCE`; `revoked` with `the engine restarted while the intent was in flight` when it ran and did not fill, the cancelled opener's case and the closed-while-down case alike; `refused` with `not run -- the engine restarted before it ran` when it has no row, `_halt_plan`'s precedent. `filled_qty` is the sum over the intent's rows. The sweep runs whether or not anything rests, and is skipped whole when the venue read failed, when the ledger read failed, or when the pass latched the kill switch — a withdrawal or an overfill, whose row keeps the figure the venue refuted — since the rows' fills were then never compared, never read, or refuted, and are no figure to journal — run over no rows it would write every intent of the window `refused` as never run. The ledger read's failure reaches the sweep as a flag the pass carries from its read to its last line, `ledger_read`, the trip as `_kill_tripped`, and the skip is one test of three conjuncts. Folding that failure into `venue_orders` as `None` was set aside: `_read_venue_orders` says `None` is its own read's failure and sets the plan refusal for it, so one word would carry two failures with different consequences; returning from the pass at the failed read was set aside, since the classification loop below must still cancel everything the Cache holds when the ledger cannot vouch for it. The cost is one flag and one keyword on the sweep. Written at classification time, the kill trip's precedent, which journals the active intent `revoked` before any acknowledgement; the cost is that a fill landing after the write — racing the cancel, or on an order the cancel did not reach — is on the order's row and not in the intent's `filled_qty`, that a cancel the venue refuses leaves the order resting with its intent already `revoked`, which `_venue_terminal_state` logs at CRITICAL on the refusal, naming the hand cancel on Kraken's open-orders page, the own-order path's precedent for the same event, and no later pass revisits a written intent, so the pages say to read the row, and Kraken's closed orders and positions for an order gone from its open orders. An intent with a row still open after the pass that the pass sent no cancel for stays `pending` beside that row, since its order may rest where this pass reached nothing: the kept reducer, whose order is live and the row its record — a case forbidden by the operating rule (no restart with a position open) until T0213's engine half lands, whose D11 redesigns the startup pass over a cache that holds the engine's own orders, and which T0213's findings now name as owed there; a cancel that raised; an order the venue read returned still open outside the Cache; a row the read did not return or that recorded no txid; and a row whose reconcile raised on an order closed at the venue. A later startup inside the re-attach window — `_exec_records_in_window`'s in `cli/engine/execledger.py`, the intent's boundary day and the next UTC day, which `pending_plan_intents` and `open_submitted_rows` both read — settles the intents of a failed read, a cancel that raised, an order outside the Cache once the venue reports it closed, and a reconcile that raised; a row that recorded no txid, or whose txid no venue read returns, is marked `ambiguous` again at each startup inside that window and its intent stays `pending`, the operator's reading beside Kraken's open and closed orders, and an intent a latched kill skipped is written by no startup while the latch's cause stands; past the window no startup reads the intent or its row, and the window's entry records what stays `pending` beside Kraken's closed orders and positions read for the order. The rule is derived, not collected: the pass records the intents whose `cancel_order` returned, and the sweep leaves `pending` every intent with a row whose mirrored state is still in `_OPEN_ORDER_STATES` and is not among them. Collecting a skip set at each site — the keep branch, the cancel's `except`, `_reconcile_adopted_rows`' open-report and unmatched branches — was set aside: four sites restating one rule, `_reconcile_adopted_rows` returning a set it has no other reason to, and the no-txid row and the closed-at-venue raise left out until a fifth and a sixth site were added. The cost is that the sweep reads the state the pass mirrored into its row dicts, so the rule is only as complete as that mirror, and the one shape outside it: a Cache-resident order whose reconcile raised and which the loop then cancelled, settled from the figure the raise left unrepaired, the kill trip's precedent of writing before the ack. The test fixture's `_submitted_row` gains a `qty` keyword so the target rule has rows to differ on: a partial is `revoked` with its fills, two orders are summed against the first order's quantity, and a row with no readable quantity is `revoked`, never `filled`. Writing on the venue's acknowledgement was set aside, since in drill G it never came; a new outcome word was set aside, since `revoked` is the runbook's word for an intent taken mid-rest and the reason names the restart.

**D15. A terminal the engine minted for an adopted order writes the row `ambiguous`, at CRITICAL, naming Kraken's open orders as the discriminator and the hand cancel on that page as the action when the order still rests.** `_venue_terminal_state`'s reconciliation arm returns `ambiguous` instead of `None`: the active path's word for the same event (`_strand_ambiguous`'s row write) and `_mark_unmatched`'s, a claim about nothing at the venue, and a member of `_OPEN_ORDER_STATES`, so a startup inside the re-attach window (D14's) re-attaches and settles the row against the venue's order, which it reads before that process sends anything, and past the window the row stays `ambiguous`, the window's entry recording it beside Kraken's closed orders and positions read for the order. **D17. The trigger is the client's socket-state stream: the reconnect pass is owed when the last endpoint the client reported down reports back, and runs on the executor's next tick with nothing of this process in flight.** The library delivers `SocketStateChanged` to a strategy's `on_socket_state` once it has called `subscribe_socket_state()`, and nothing without the call — measured offline on the pinned wheel against `tests/test_engine_data_socket.py`'s loopback drop with a strategy that subscribed: `kraken-spot-data-streams` reports `CONNECTED` at the connect, `DISCONNECTED` when the client detects the dead connection, and `CONNECTED` 0.2 ms after its own `Reconnect succeeded` line. `ShadowStrategy` subscribes in `on_start` beside the tick and forwards the events, its fifth forwarder; the executor keeps the set of endpoints down and arms the pass when a `CONNECTED` empties it, so both sockets resubscribed is what arms it, F2's reading, and the connect's own `CONNECTED` arms nothing.
