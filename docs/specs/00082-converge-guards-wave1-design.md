# Spec 00082 — Mechanize converge discipline, wave 1: role asserts, the M-pair, mutate-probe, and the git-mv hook

**Topic:** [[T0111]] (wave 1 + the M-sized design pass, settled in this spec) with the agent-ops fold-in the owner directed 2026-08-03. **Goal:** every converge hazard that prose currently guards — and that a check *can* guard — refuses at the point of use, so the corresponding rule lines can shrink to pointers. L2 capture is unbackfillable; an assert refuses regardless of what a compacted context remembers.

**Ruled in the producing brainstorm (owner, 2026-08-03):** scope = wave 1 + both M-asserts + `mutate-probe.sh`; canary and pins overrides are **reason-required free text**; the pins assert reads the **controller tree**; the `git mv` hook is **taken**; the network-timeout hook is **dropped** (the harness re-invokes on completion and the `timeout NN` prefix habit is cheap — mechanizing it buys little).

## D1 — One override convention, three overridable guards

`-e <name>_override="<free-text reason>"` for exactly: `canary_override`, `pins_override`, `engine_window_override`. An override is **refused** when empty, literally `true`/`false`/`1`/`yes`, or shorter than 9 characters — a sentence fragment is the speed bump; a boolean would become the copy-paste default. The accepted reason is echoed in a `debug` task so the play log carries the why. All other guards have **no** override: their fix is always cheap and immediate (tag the run, add the pair on the primary first, write the pins line, create the secrets file).

## D2 — Placement and idiom

- **Play-level `pre_tasks`** for the two play-scoped guards: the un-tagged-primary refusal at `tags: [always]` (it must fire on every selection), and the engine window guard at **`tags: [engine]`** — cold review I2: an always-tagged window guard in the engine play would refuse `--tags capture` primary runs the rule permits (the real 2026-07-29 07:36 capture-only re-pin would have been refused), while every run that can actually restart the engine carries the engine tag, and a truly untagged primary run is already refused by guard 4. Everything else is a role-level assert block at the top of its role, following the engine role's §8-gate idiom: read-only probes (`failed_when: false`, `changed_when: false`, `check_mode: false`) feeding `ansible.builtin.assert` whose `fail_msg` **names the fix** (`agent-ops.md`: a recorded footgun names the safe alternative in the same sentence).
- Probes set `check_mode: false` so `--check --diff` previews still exercise the guards; the **engine window guard alone** is additionally skipped under check mode (`when: not ansible_check_mode`) so previews run at any hour — ruled in T0111.

## D3 — The thirteen guards

Each entry: behavior → the constructed violation its test must trip on.

1. **Digest-resident preflight — capture role.** `docker image inspect {{ capture_image }}@{{ capture_image_digest }}` (probe idiom above); assert rc 0 with fail_msg naming the pull command. → violation: probe rc nonzero must fail the assert; rc 0 must pass.
2. **Digest-resident preflight — engine role.** Same for `engine_image_digest`. → same fixture pair.
3. **Digest-resident preflight — ops role.** Same for `ops_image_digest` (every ops runner is `--pull never`; absence = every timer exits 125) — **gated `when: ops_image_digest is defined`, as are the liquidations and ops-pins guards**: the ops role's own convention is that a digestless converge (config/alloy-only) skips every image-consuming task, and a guard must not break it (cold review I3). → same fixture pair.
4. **Un-tagged primary refusal** — capture-play `pre_task`, scoped `when: inventory_hostname in groups['engine_host']`: assert `ansible_run_tags != ['all']` or `ansible_skip_tags` nonempty, i.e. the run names its tags explicitly. Kills the recorded disaster: an untagged `--limit zcrypto` pulls in the engine play and its digest assert fails the host closed. No override. → violation: `ansible_run_tags == ['all']` and empty skip-tags on an engine_host member must refuse; the same facts on `zcrypto-red` must pass.
5. **Engine inter-cycle window guard** — engine-play `pre_task`, `tags: [engine]` (see D2), skipped under check mode. Compute `since_boundary = target-host epoch mod 14400` and `until_next = 14400 − since_boundary` (chrony-disciplined clock, **read at task execution time** — this IS the 08-03 re-assert-immediately-before-acting item: a converge backgrounded for 3.5 h re-reads the clock when it fires, by construction). Refuse when `since_boundary < 1800` (the cycle-completion window `[B, B+30 min]` may still be running — capture-deploys' own contract) **or** `until_next < 600` (a stop→start beginning within 10 min of a boundary risks straddling it), unless `engine_window_override=<reason>` (D1). → violations: an epoch at boundary+1900 s passes; boundary+900 s refuses (completion window); boundary+13900 s refuses (too close to next); `engine_window_override=true` still refuses; a ≥9-char reason passes.
6. **Engine preflight** — engine role: assert `/opt/zcrypto-capture/logship-secrets.env` exists (absence crash-loops the engine rather than failing the render) and record the current `:9102` holder before restart. No override. → violation: stat says absent must refuse.
7. **Pair-add order guard** — capture role, secondary only. **Engages only when the converge would ADD a pair** (target list ⊄ the secondary's own deployed `CAPTURE_PAIRS`, read from its local compose): a routine bake converge with an unchanged pair list never consults the primary, so a primary outage cannot block secondary incident work (cold review I1). When engaged: delegate a read of the **primary's** deployed `CAPTURE_PAIRS`; refuse any target pair the primary does not already carry — **fail-closed on an unreachable primary**, because a new pair reaching the secondary first is precisely the reconciler poisoning this kills. No override. → violation: secondary target `[…, 'XRP/BTC']` with a primary list lacking it must refuse; equal lists pass; unchanged-vs-deployed target must skip the delegated read entirely.
8. **`daemon.json` change-ack** — docker role (shared; protects capture hosts, whose handler bounces dockerd under live capture): render to a probe path (**a deliberate, stated exception to the read-only probe idiom: it writes `/run/zcrypto-daemon-json.probe` even under `--check` — tmpfs, no secrets, no service touched**), diff against deployed, and **display the diff via a `debug` task before the assert** (a `failed_when: false` command prints nothing under the default callback, so without the debug the ack would acknowledge unseen content — voiding this guard's own boolean rationale); a difference refuses unless `-e daemon_json_ack=true` (a boolean is acceptable *here*: the diff itself is displayed, so the ack acknowledges specific shown content, unlike the D1 overrides which substitute for absent evidence). → violation: differing render without ack refuses; identical render needs no ack; differing render + ack passes.
9. **Liquidations repin decision** — ops role: when `ops_image_digest` ≠ the deployed liquidations compose pin, require `-e liquidations_decision=roll-after|defer`; any other value (or absence) refuses. Makes the never-restarted compose repin a conscious choice (`capture-deploys.md`: prefer rolling; the 30 h re-fetch self-heals). → violation: differing pin with no decision refuses; `roll-after` and `defer` both pass; `yes` refuses.
10. **Panel-timer hold** — ops role: `-e ops_panel_timer_hold=true` makes the enable-and-start task leave the panel timer stopped (today it silently re-arms after a converge — the exact trap the panel-regeneration section warns about). → violation: with hold set, the rendered task list must not start the timer; without it, it must.
11. **Canary digest-parity (M-1, owner semantics; unreachable-secondary semantics per cold review I1: `ignore_unreachable: true` on the probe, and the assert fires whenever the probe RAN — a secondary that cannot be read yields empty stdout, which refuses parity and routes through `canary_override`, never a silent pass).** In the capture role, scoped to the primary, active only when `capture_image_digest` differs from the primary's running digest: delegate `docker inspect --format '{{.Config.Image}}' zcrypto-capture` on **zcrypto-red**; assert the secondary runs the candidate, or `canary_override=<reason>` (D1). Digest identity is always `{{.Config.Image}}` (never `{{.Image}}` — host-dependent under classic storage). → violations: secondary ≠ candidate refuses; `canary_override=true` still refuses; ≥9-char reason passes; secondary == candidate passes with no flag.
12. **Re-bootstrap refusal** — `bootstrap.yml` (first-provision only): probe for the deploy user (`getent passwd zcrypto-deploy`, probe idiom); an already-bootstrapped host refuses without `-e rebootstrap=true` (boolean acceptable per guard 8's rationale: the refusal names the concrete evidence — the existing user — so the ack acknowledges shown state). → violation: probe rc 0 without the flag refuses; rc 1 passes; rc 0 + flag passes.
13. **Fleet-pins recording (M-2, owner semantics).** Before any re-pin, read the **target's currently-running digest from a container, never from a compose file** (capture-deploys' own rule — the 2026-07-31 armed-damage incident was a compose file lying while the container was right). Per tier: capture → `zcrypto-capture`, engine → `zcrypto-engine`, ops → **`liquidations-poll`** (the one long-running `ops_image` consumer; the timer runners are transient). A probe rc ≠ 0 (container absent — first provision) skips the guard: nothing runs, so nothing is being replaced. Read the pins file and `lookup('file', playbook_dir ~ '/../../docs/reference/fleet-pins.md')` from the controller tree; assert the current digest's first-12 appears in the file, or `pins_override=<reason>`. Enforces record-BEFORE-converge (an unrecorded pin is one `docker prune` from unrecoverable) and catches converging from a stale checkout for free. → violations: running digest absent from a fixture pins file refuses; present passes; absent + reason passes.

## D4 — `infra/scripts/mutate-probe.sh` (the agent-ops fold-in)

One wrapper for the mutate→measure→restore cycle, collapsing four `agent-ops.md` bullets into executable form:

- **Refuses a dirty worktree** for in-repo mode (`git status --porcelain` nonempty → exit with the fix named), because `git checkout -- <file>` restores the *committed* state and destroys uncommitted work.
- `--sandbox` mode seeds from **`git archive HEAD`** into a temp dir (never `cp -a`), and **refuses to run `pytest` inside the sandbox** (the editable install's `.pth` resolves `cli`/`tests` to the repo — every verdict would measure unmutated code); sandbox mode is for path-imported scripts only.
- Exports `PYTHONDONTWRITEBYTECODE=1` and purges `__pycache__` before every probe (the (mtime-seconds, size) cache key runs unmutated code on a same-second same-length mutation).
- **Control mutation is mandatory**: the first probe must be a mutation the caller expects to FAIL the given command; if it passes, the harness aborts — no real probe's verdict counts on an unproven harness (the guard-proving rule as code).
- Restores from a **pristine copy taken before any mutation** — the sandbox has no `.git`, so `git checkout --` cannot restore there; in-repo, git additionally verifies byte-identity. And **every apply must prove the file actually changed**: a sed expression that matches nothing silently no-ops (the `str.replace` trap), and a probe on unmutated code is a false SURVIVED — the harness aborts loudly instead (cold review I6).

## D5 — The `git mv` hook (taken; network-timeout hook dropped)

`.claude/hooks/git-mv-guard.sh`, wired as **PostToolUse, matcher `Bash`**, following memo-guard's settings idiom. The script reads the hook JSON from stdin; when `tool_input.command` contains `git mv`, it runs `git status --porcelain` and, for any `RM ` entry (rename staged, worktree modified — exactly the state where the staged rename carries pre-edit content), emits a warning naming the path and the fix (`git add <newpath>`; verify against the committed tree). **Warning, not block** — the mv has already run; the value is firing at the exact moment the trap forms rather than at commit time, which repo-side pre-commit structurally cannot do (the framework stashes unstaged changes before hooks run). Non-`git mv` commands: exit 0 silently, cheap. This failure bit twice on 2026-08-03; both incidents showed `RM`.

## D6 — Test substrate

The established infra-test pattern, extended from templates to task logic:

- `tests/test_infra_converge_guards.py` parses each guard's task YAML and evaluates its **actual condition expressions** through Ansible's own templar (`ansible` is already a venv dependency) against constructed-violation fact fixtures — every violation named in D3, plus the pass case, plus the override-rejection cases (`true`, empty, short) for all three D1 guards. Asserting "an assert task exists" is worthless; the expression must be fed the defect and seen to refuse.
- `mutate-probe.sh`: shell tests (pytest `subprocess` style, matching `test_capture_prune.py`'s pattern) covering: dirty-tree refusal, control-mutation-must-fail abort, sandbox pytest refusal, byte-identical restore.
- The hook: a test feeding it synthetic hook JSON + a scratch repo in the `RM` state, asserting the warning names the path; and the non-matching fast path stays silent.
- `ansible-lint` (already in the commit gate) covers idiom conformance.
