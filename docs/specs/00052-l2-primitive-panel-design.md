# 00052 — The L2 primitive panel (spec 00051 OPS-4)

Ratified 2026-07-15 in an attended design discussion (decisions logged `[iter-098]`, phase-1 running log). Executes spec `00051` D5 — the wide, append-only, hot-tier L2 primitive panel — as its own component. The implementation plan is `docs/plans/00052-l2-primitive-panel.md`.

## Goal

Materialize the captured depth-100 L2 book into a **1-second-grid, wide primitive panel** on the ops node, accruing hourly and replicated to the NAS — so research features derive hot→hot (never re-scanning raw), and [[T0014]]'s spread calibration (ripe ≈2026-07-22) becomes a one-query start.

## Decisions

- **D1 — Grid: 1-second state sample** (decision `[iter-098]`, options event-time / 1-min aggregates rejected). At each wall-clock second boundary within an hour, the book state as of that second is sampled; a per-second `updates` count carries activity. Uniform grid → trivial percentile/session-bucket math; ~50–100 MB/day for 10 pairs.
- **D2 — Primitives v0: the wide set** (decision `[iter-098]`): `spread` (quote abs), `spread_bps` (of mid), `mid`, `microprice` ((ask_qty·bid + bid_qty·ask)/(bid_qty+ask_qty)), `imbalance_l1` (bid_qty/(bid_qty+ask_qty)), `fill_bps_{bid,ask}_{100,1k,10k}` (effective-spread-at-size: walk the side accumulating price×qty until €X notional; VWAP vs mid in bps; **null** when the visible book is too shallow — never extrapolated), `depth_qty_{bid,ask}_{l1,l5,l10}` (cumulative base-qty at levels 1/5/10), `updates` (messages applied that second). ~20 Float64 columns; per D5's wide-panel philosophy, columns are near-free and each new one avoids a future cold re-scan.
- **D3 — Input is the canonical stream, with STATE THREADED across hours** *(corrected 2026-07-15 after first contact with real data — decision `[iter-098]` correction)*: hours enumerate via `canonical_segments(primary_root, reconciled_root, kind="book")` — reconciled-first, so healed hours feed the panel. The original "every hour opens with a snapshot" premise is **false**: Kraken snapshots arrive on *subscribe*, so ~96% of real hours open with plain updates (measured: 193/200 BTC hours). The materializer therefore processes each pair's hours in order carrying `OrderBook` state: a snapshot-opening hour resets state; an update-opening hour continues from its **contiguous** predecessor (exactly hour−1); a missing predecessor or no prior snapshot → the hour is **unanchored** (an honest gap, counted separately from errors) until the next snapshot re-anchors. For O(1) watermark resume, `write_hour` persists the end-of-hour book state as a small `<HH>.state.json` sidecar (itself `f(raw)`); a sweep resumes by loading the watermark hour's state. An hour absent from the canonical archive still produces **no rows** — gaps are honest, mirroring the no-trade-bar convention. *(Corollary: OPS-3's `verify-replay` `snapshot_anchored` check shares the wrong premise and is corrected to chain-anchored semantics in this component.)*
- **D4 — Storage: SegmentWriter-style tree, batch-written per hour**: `<panel_root>/<PAIR>/panel-1s/<YYYY>/<MM>/<DD>/<HH>.parquet` + the `"<hex>  <name>\n"` `.sha256` sidecar, written atomically (tmp → fsync-rename → manifest, the mint/archive pattern — an hour is materialized whole, so no incremental buffering is needed and `SegmentWriter` is not forced where batch-per-hour is natural). Zstd, one row per second per pair (≤3600/hour).
- **D5 — Versioning: a generation manifest, not per-run hashes**: `<panel_root>/panel-meta.json` records `schema_version`, the grid, the notional ladder, the K-levels, and the producing code ref. A grid/primitive change bumps the generation and **regenerates the whole tree** (the panel is `f(raw)` — recomputable by design; T0045's constraint lives with raw, not here). Research iterations consuming a panel window record that frame's `dataset_hash` in the trial registry exactly as backfill baskets do.
- **D6 — Ingest cadence: hourly, watermarked, after the recurring pull**: a systemd timer pair on the ops node — (1) `zcrypto-archive-pull` (NEW: the seed channel on a timer — rsync the four trees from the NAS hourly; this also closes the replay-staleness gap noted in [[T0033]]) and (2) `zcrypto-panel-materialize`, processing canonical hours strictly newer than the panel's per-pair watermark (= newest existing panel hour). No extra settle margin is needed: a canonical *final* is settled by construction (it exists only after capture finalized the hour and the NAS pull hash-verified it). Same digest-pinned-container pattern as the replay timers; textfile metrics (`ops_panel_*`: exit_code, last_run, last_success, hours_materialized) + a healthchecks.io dead-man.
- **D7 — Replication (00051 D9/D10)**: a dedicated `sync_panel` rrsync `-ro` forced-command key on the ops node pinning `<panel_root>`; the NAS gains an optional `PANEL_SOURCE`/`PANEL_DEST`/`PANEL_SSH_KEY`/`PANEL_SSH_PORT` pull — the exact `LIQUIDATIONS_*` optional-channel pattern in `infra/nas/{compose.yaml,pull-entrypoint.sh}`. Convenience-durability: the panel is recomputable, so the NAS copy is not custody-critical.
- **D8 — Backfill**: the first materialize run sweeps all seeded canonical hours (~3,400 finals). Single-process v0; measure, and only parallelize (per-pair processes) if the measured rate demands it.
- **D9 — Scope boundary**: this component ends at *panel exists, verified, replicating, accruing hourly*. [[T0014]]'s calibration (session-bucket spread percentiles → the `cli/costs/` spread term → the A-family robustness re-read) is its own research iteration; a first-look per-pair spread table is this component's verification-by-outcome only.

## Reuse

`canonical_segments` (`cli/archive/reader.py`), the row→message regroup + `OrderBook` walk (`cli/archive/replay.py` — the regroup is exposed for reuse rather than copied), the atomic-final+manifest write pattern (`cli/archive/mint.py` precedent), the ops role's timer/runner/textfile/dead-man templates (OPS-3), the `LIQUIDATIONS_*` optional NAS channel pattern (OPS-2), vaulted per-channel keys + pinned host keys, `dataset_hash` (`cli/derivatives/funding.py` / substrate conventions) for consumers.

## Non-goals

No CRC re-derivation (T0045), no wall-clock hour-finalization change (T0046 owns it), no consumer features (`cli/features/` derivations come with their research iterations), no multi-venue liquidation/panel mixing, and no OPS-5/6 content (reconciler offload, scraper, loop — sequenced after, per the `[iter-098]` decision).

## Risks / open parameters

- **Sampling semantics at second boundaries**: the sample is the book state after applying all messages with `ts <= boundary`; an hour's first samples before the snapshot settles are emitted only from the snapshot onward (no pre-snapshot rows).
- **Depth ladder currency**: notionals are quote-currency (EUR — the whole universe is */EUR). If a non-EUR pair ever joins, the ladder needs an FX hop (registered thought, not built).
- **Panel staleness**: covered by the D6 dead-man + the T0033 staleness-alert note (OPS-5 wires the scraper).
