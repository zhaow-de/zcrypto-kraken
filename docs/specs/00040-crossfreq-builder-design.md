# Record-44 builder + concordance core (design)

**Iteration:** iter-082 (attended — the first of the two shadow-engine build iterations decided `[iter-082]`; the second, iter-083, wraps the node/store/journal-writing/CLI around this iteration's output). **Goal:** the Phase-6 engine's committed computational heart — the deployable system's (registry **record 44**) builder as tested code with a verified path and an equivalence-gated fast path, plus the concordance core implementing the ratified 4h Stage-6a gate. *(Revised after the three-agent adversarial verification pass — feed map, newest-bar contract, no-peek invariant, replay-path reconciliation; decisions log `[iter-082]`.)*

## Why this shape

The engine's one hard promise (spec 00039, gate ratified 4h on 2026-07-10) is that the node's targets equal a replay of its journaled inputs to |Δ| ≤ 1e-6. That demands the target computation exist as one committed, tested function — not as trial-driver scratch. Record 44's construction currently lives only in the iter-080/081 drivers + spec 00038; trials 43/44 pinned its figures in the registry, which this iteration turns into frozen-figure regression tests.

## The builder — `cli/portfolio/crossfreq_system.py`

Two callables, one truth:

**1. `build_crossfreq_system(daily_prices, daily_ts, h4_prices, h4_ts, *, config=CrossfreqSystemConfig())`** — the **verified path**: a faithful transcription of the trial-44 driver (which reproduced trial 43's machinery bit-identically before the weight change).

**The exact feed map (registered-trial truth — not an ordered ffill step):**

- **RAW union prices (Nones preserved)** feed `dynamic_inverse_vol_basket` (lookback 30), `_inverse_vol_weights` (30), and the `build_combined_system` elementwise QA comparator — the record-33 primitives treat a `None` specially (basket disqualification), and BTC has genuine mid-history union gaps, so forward-filling here changes the B sleeve elementwise.
- **BTC-only forward-filled prices** feed `a1_book_returns` (both the price dict and the BTC regime series) and `a2_book_returns`.
- **Per-asset return grids** `ret_d`/`ret_h` = `_asset_returns` over the BTC-ffilled set with `None → 0.0` (sleeve noc series, A1 book QA, combined costing).

**Construction:** B sleeve = daily w·l3 (`sma_gate` 200 on the basket's own equity, `vol_target` 0.10/√365 lookback 30 on the raw basket, gate applied after); A1 sleeve = A1-lf weekly v0.12 (`A1Config(base="equal_risk_basket", regime="ensemble", short="off", target_vol=0.12)`) 7-offset-mean **positions** (offset `block_start` rule of the trial-34 test); both daily sleeves expanded to the 4h calendar via `expand_daily_positions` with **close-time-shifted boundaries** (daily_ts+1d, h4_ts+4h — the pinned contract); A2 sleeve = equal-weight per-asset mean of the three adopted arms, each `short="off"`, `vol_lookback=basket_lookback=180`, `periods_per_year=2190`, with their QA anchors:

| A2Config lookbacks | target_vol | anchor Sharpe (full, ppy 2190) |
| ------------------ | ---------- | ------------------------------ |
| (20, 50, 100) | 0.12 | 1.3274 |
| (60, 120, 240) | 0.10 | 1.3017 |
| (60, 120, 240) | 0.12 | 1.3585 |

then combination at **fixed ⅓ weights** → `apply_position_caps` 20 %/10 % → full per-asset net-of-cost at 0.006/side → `daily_cadence_governor` on **dense present-day ranks** of `date(h4_ts[k+1])`.

**Returns `CrossfreqSystemResult`**: **`final_targets`** (per-asset, per-4h-interval: multiplier × capped position — the tradeable decomposition and the quantity the engine journals; see the newest-row contract below), `governed_net`, `ungoverned_net`, `multipliers`, sleeve position sets, `cap_breach_bars` (count of bars where **any** asset was clipped, |capped−combined| > 1e-15), `governor_engaged_bars` (count of bars with multiplier < 1.0), `day_index`, `n_periods`. All turnover/noc loops start from a flat book (`prev = 0.0`; bar 0 charged full entry turnover) — the drivers' convention behind the frozen integers.

**The newest-row contract (the row the engine trades).** `final_targets` has exactly **one row per tradable 4h interval *including* the interval opening at the snapshot's last close** — one row more than the completed return bars. Implementation: append a **synthetic next boundary + dummy close** to each grid (daily: last stamp+1d; 4h: last stamp+4h) before position construction and expansion, so every sleeve's forming-interval position is computed from real data through the last journaled close; the **dummy close value must not affect the newest row** (positions for interval *k* consume data strictly before the interval's close). The newest interval's governor multiplier = governed state through the **last completed calendar day** (implemented by appending a zero day-return and reading its multiplier — value-insensitive by the governor's day-*t*-from-*t−1* contract). **Required unit test (the no-peek/no-drop invariant, synthetic mini-grid):** (a) the newest row carries non-zero daily-sleeve content when the sleeves are non-flat (guards the expansion tail rule silently zeroing B/A1); (b) extending the grid by one real bar and re-reading the now-interior row reproduces the previously-newest row exactly; (c) perturbing the dummy close leaves the newest row unchanged.

**P&L convention disclosure (flows into the runbook):** `governed_net` reproduces the registered trial's returns-overlay cost convention — **multiplier-transition turnover is deliberately unpriced** (inherited from record 33's ratified governor semantics): a live engine trading `final_targets` pays fee on |Δ(mult×capped)|, which exceeds the overlay's mult×fee×|Δcapped| on governor engage/disengage days. The targets gate is unaffected (it compares positions, not P&L), but live/paper P&L reconciliation must expect a systematic shortfall concentrated on multiplier-transition days, or compare against `governed_net` plus an explicit transition-cost adjustment.

**2. `build_crossfreq_system_fast(...)`** — same signature, same result type, vectorized (polars/numpy) where the profile says it matters (the three A2 arms dominate the ~13 min verified-path build). **Construction guidance:** discrete decision layers (SMA gate on/off, basket qualification, weight fallback, cap clipping, Donchian breakouts, governor rungs) must be fed values computed the **same way** as the verified path — vectorize only order-insensitive arithmetic; pin summation order where it feeds a comparison. **The equivalence gate (hard):** elementwise ≤ 1e-12 vs the verified path over the full frozen history on `final_targets` and both net series; identical `cap_breach_bars` and `governor_engaged_bars`; headline figures round to the registry's 4dp values. **Off-ramp (pre-agreed):** if 1e-12 proves unattainable on some layer, production runs the **verified path** (its ~13 min build fits the 30-min cycle deadline) until a revised fast path passes — the 1e-6 gate semantics never change. Speed is measured and recorded (target ~10× — advisory).

`CrossfreqSystemConfig` is a frozen dataclass carrying record 44's constants as defaults. It captures **record 44**, not a general framework — a future adopted record revises the builder under its own trial discipline (no speculative knobs).

## Regression tests — the registry as the oracle, the dataset frozen

- **The frozen oracle**: `data/ohlc-full` is the regression dataset **as of the trial-43/44 freeze and is never appended to** — the engine's live store (iter-083) is a **distinct root** (pinned in T0018). Every skipif-data test **asserts the dataset extent first** (per-pair bar count + last ts) and fails with an explicit "canonical dataset drifted — STOP" message before any figure comparison.
- **Verified-path figures** (skipif-data, record-33 test pattern): governed Sharpe **1.5609** full / **1.5583** decisive (k≥1380, ppy 2190), maxDD **13.57 %** (pre-governor 18.66 %), `cap_breach_bars` **1,318**, `governor_engaged_bars` **7,302**; the five sleeve anchors internally (daily bench 1.2455 elementwise ≤1e-12 vs `build_combined_system`; A1-lf book 1.3798; the three arm anchors above). Tolerances: 0.005 on Sharpes, 1e-12 elementwise — the drivers' conventions.
- **Fast-path equivalence** (skipif-data) + a **synthetic mini-grid equivalence test that runs unconditionally in CI** (catches gross drift; the full-history gate needs the data machine). **CI never executes skipif-data tests** (`data/` is gitignored on runners), so: any PR touching `cli/portfolio/crossfreq_system.py` must include a local data-machine run of the full equivalence + regression tests in its test plan (recorded in the runbook), and the daily verified-path spot replay (below) keeps the oracle in the operational loop.
- Unit tests (no data): config validation, degenerate-input errors, the newest-row invariant suite.

## The concordance core — `cli/engine/` (a library package like `cli/portfolio` — the `command.py`/`zcrypto engine` CLI group lands in iter-083 per the CLAUDE.md subcommand convention)

1. **Journal contract** (`cli/engine/journal.py`): a documented, versioned schema — per cycle: `cycle_ts` (the 4h boundary), the input-snapshot manifest (per pair × grid: n bars, first/last ts, content hash), snapshot file paths, computed newest-row `final_targets`, `started_at`/`completed_at`, code-version id (package version + builder path name). **Content hash pinned to the byte**: per pair × grid, sha256 over ts as int64 epoch-seconds little-endian concatenated in row order, then closes as IEEE-754 float64 little-endian (`None` encoded as NaN); the layout is covered by the schema version, and **both the iter-083 writer and this iteration's reader call the one committed hashing helper** — never reimplemented from prose. **Snapshot-boundary invariant (no-peek, hard validation):** per pair, the last 4h stamp == `cycle_ts` − 4h (the bar closing exactly at `cycle_ts`) and the last daily stamp == (last midnight ≤ `cycle_ts`) − 1d — the node must drop Kraken REST's trailing in-progress candle; a violated invariant is a **journal-validation error, classified as a failed cycle** by the gate, never silently replayed.
2. **`replay_cycle(entry, snapshot_reader, *, path="fast")`** — loads the journaled snapshots, verifies content hashes (a hash failure = **mismatch**: reset + investigate — corrupt evidence), enforces the boundary invariant, runs the builder (`"fast"` default; `"verified"` for the daily spot replay), and returns the recomputed newest-row targets **located by `cycle_ts`, never by last-index**, erroring on absence.
3. **`compare_targets(a, b, tol=1e-6)`** — per-asset **absolute** comparison (most positions sit at exactly 0, so relative error is undefined; 1e-6 ≈ 5e-6 of the 0.2 cap); **asset-set mismatch fails structurally, not numerically**; returns pass/fail + worst offender. The 1e-6 budget exists for **cross-environment floating-point drift** (VPS node vs workstation replay); same-platform replays are expected exact.
4. **`evaluate_gate(entries)`** — the ratified 4h gate over a **complete-UTC-days universe**: a day enters evaluation only after its 20:00 cycle's 30-min window has elapsed; days before (and including) a mid-day shadow start's partial first day are **excluded, not failed**. A day is clean iff all **6** cycles (00/04/08/12/16/20 UTC) are present, each `boundary ≤ completed_at ≤ boundary + 30 min`, each replay-compare passing at 1e-6, and no journal-validation failures (a **per-pair freshness violation = a missed cycle** — the gate proves tradable targets on time; stale-input targets aren't that). Gate = **≥ 14 consecutive clean days**; any miss/mismatch resets the streak. Returns streak status + most-recent-failure detail. **Replay policy:** every cycle replays through the fast path; **≥ 1 cycle per day additionally replays through the verified path** (the oracle stays in the live loop; ~13 min each, offline). Synthetic-journal tests: clean streaks; a missed cycle; a late cycle; a mismatch; a boundary-invariant violation; an intra-day evaluation mid-streak (streak unbroken); a mid-day start (counting begins at the first full day).
