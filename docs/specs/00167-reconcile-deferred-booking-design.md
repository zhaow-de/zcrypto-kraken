# A fleet-dark hour still missing a trades file waits for it, up to six hours, before the reconciler books it

Branch `feat/iter-214-reconcile-deferred-booking`, cut from `develop` at `3fb48bf8c` on 2026-11-27, iteration `iter-214`. The owner ruled the change on 2026-11-26 (D1–D3, D8); this spec designs it, and its plan is `docs/plans/00167-reconcile-deferred-booking.md`, written on the options of D4–D7 the owner picked on 2026-11-27, each the recommended one.

## Goal

A `both_streams_silent` hour in which a booked pair's trades file is not yet on either mirror is not booked when it is first examined but read again each `:12`/`:42` cycle until the file arrives or the hour is six hours old, and is then booked exactly as today.

Its own short spec and plan, reviewed, landing through an attended converge of this workstation's ops role."

## Operating model

- **The reconciler.** `zcrypto-archive-pull.service`, `Type=oneshot` (`archive-pull.service.j2:16`), started by its timer at `:12` and `:42`, runs one `zcrypto archive reconcile … --window-hours 48 --min-gap-seconds 30 --mint --textfile …` per tick in the ops image (`archive-pull.sh.j2:122-134`) after a gate on the NAS's `.pull-status` that skips the tick, rc 0, when the status is missing, unclean, over 4 h old or skewed (`:24-36`, `:77-95`).
- **The mirrors.** The NAS's copies of the two capture hosts, read over that NFS mount; a final appears in a cycle's scan once the NAS's pull of its host has carried it (`scan_hours` reads final names only, `settle.py:74-93`), the primary's copy ahead of the secondary's within a NAS loop.
- **The ledger.** `reconcile-ledger.jsonl` beside the overlay, written by this process alone, append-only, each `(pair, kind, hour, state)` decided once (`command.py:691`, `:735-748`); changed otherwise only by the owner-approved hand procedure (`infra/nas/README.md:148-185`).
- **What names a waiting hour, and when it is alive.** No stored state names it: on every cycle an hour waits while it is in the 48-hour window, has fleet-dark windows, holds no `both_streams_silent` record, read every book segment, has a present pair whose trades final is on neither mirror (or, under D5's recommendation, one that failed to read), and `is_late` is false. Its book heal waits on those cycles, and on a cycle before `is_late` on which one of its book segments fails to read, whether or not the hour is fleet-dark (D4). A cycle that dies leaves nothing to clean, and a rolled-back image sees an unbooked hour, which it books on its next cycle as today.
- **The skip cache.** `scan-cache.json` beside the ledger keeps an hour's entry when its examination on a minting cycle appended nothing, and skips an hour only when that entry was late, complete and failure-free (`cli/archive/scan_cache.py:224-233`, `command.py:1182`, `:1198-1212`).

## Decisions

**D1. A fleet-dark hour with a missing trades file is not booked yet: no record, examined again each cycle.** The ruling: "A both-streams-silent hour with a missing trades file is not booked yet; it is re-read each cycle". Where the record is decided today, after the halt evidence is read, the pairs of `present` whose trades final is on neither mirror are listed; while that list is not empty and the hour is not late, no `both_streams_silent` record is ledgered, nor (D4) a book-heal record, and the cycle moves on, the hour's trades heal and `total_loss` check running as on any cycle; `_decided`, `settled_hours` and every later cycle's examination stay as they are, so "re-read each cycle" is the window the cycle already scans. "Missing" is the file the ruling's question names, one that has not reached the NAS: a final on either mirror has, and ends the wait, the halt proof already reading through one mirror (`tests/test_archive_reconcile_command.py:1599-1611`); waiting for its twin as well, which can fill an id hole, would hold every hour whose secondary copy trails the primary within a NAS loop.

**D2. The bound is the late deadline, H+6 h.** The ruling: "until the file arrives or a bound passes (I propose H+6 h)". The wait reads `late`, `is_late(hour, now)`, which the cycle already computes once per hour (`command.py:802`): the first `:12`/`:42` cycle at or past H+6 h books. One constant, `LATE_MINT_HOURS`, then holds both the heal's late deadline and this bound, the deadline `PANEL_SETTLE = 7 h` already takes as the reconciler's last mint (`cli/panel/materialize.py:41-46`), and the gate's 4 h status age was sized under it (`archive-pull.sh.j2:25-27`). The ruling names two ends and this spec adds no third: a clock-free end, such as the pair's later-hour trades final proving H printless, is not read. What the bound does not cover books at it as today: a pair with no print in H, a pair whose next print lands more than about four hours after H's end (none in the sample), a trades merge that failed on both hosts until a capture restart's sweep, and a NAS view the gate admits up to 4 h stale, which at H+6:12 can be the NAS as it stood at about H+2:12. A wait no tape can end in a halt waits all the same: a `capture_divergent` triage, read from book rows alone, refuses the halt whatever a late tape shows, so where every book pair already holds both finals the wait only moves that loss's ERROR line, its residual page and the hour's book-heal records (D4) from the first look to the cycle that books, up to four hours later. The plan's review then asked whether such an hour's wait should end early; asked 2026-11-27T17:49:42Z, verbatim: "From the plan review: when a fleet-dark hour's book data already shows a capture fault (the `capture_divergent` triage, read from book rows alone), the hour books as loss whatever trades file arrives later. Under D2 it still waits, so that loss's ERROR line and residual-gap page come up to 4 h later than today. Should the wait end early for such an hour?" The owner's answer by 17:49:51Z, verbatim: "Keep D2, wait as ruled (Recommended)".

**D3. At the end of the wait the hour is booked as today, from that cycle's view.** The ruling: "then booked as today". The cycle that ends the wait runs today's code unchanged over what it reads: the present pairs, the fleet windows recomputed from every book stamp (a book mirror that landed meanwhile can shrink, split or erase a window, and an hour left with none books no record), the stream windows, the triage, the halt proof, the verdict, the line (WARNING for a halt, ERROR for loss) and the record with its pinned key set (`tests/test_archive_reconcile_command.py:1181`). A pair still without a trades final logs today's `no trades segment on either mirror` WARNING and refuses the halt, and the residual counter steps and both pages fire, on that cycle. No field says the booking waited.

**D4. The book heal of a waiting hour.** The owner picked A: Asked 2026-11-27T16:11:03Z, verbatim: "D4. While a fleet-dark hour's booking waits for a missing trades file, should that hour's book heals wait with it? If they don't, a pair whose two capture copies resume a little apart inside a halt books those seconds as permanent loss immediately, and that pages." The owner's answer by 16:18:57Z, verbatim: "Heals wait too (Recommended)". The plan's review then found the heal still minting first on a waiting cycle whose book read fails, which skips the fleet detector; asked 2026-11-27T17:12:56Z, verbatim: "D4 follow-up, from the plan review: you picked 'heals wait too', but the plan's code only holds the heal on a cycle where every book file reads. If one of an hour's book files fails to read on one of the waiting cycles (a transient NFS error, say), the fleet check is skipped and the hour's heal runs first. On the reviewer's run that booked 610 s of a provable halt as permanent loss and paged residual-gap with no fleet record. Should an hour whose book read fails before H+6 h hold its heal too?" The owner's answer by 17:13:09Z, verbatim: "Hold the heal too (Recommended)".
- **A — it waits with the record (recommended).** While an hour waits, no pair of it enters the book heal: no `minted`, `would_mint`, `unwitnessed` or heal `failed` record for it. Nor does one on a cycle before the late deadline on which one of the hour's book segments fails to read, whether or not the hour is fleet-dark: that cycle skips the fleet detector and already fails (exit 1), and the next cycle that reads every segment decides the record first, then heals. At the end of the wait the record is decided first and the heal subtracts the stream windows it booked, as on a first look today; past the late deadline a cycle whose book read fails heals ahead of the record as today, and the record then books only what the heal did not (`_booked_residual`, `command.py:314-329`). Cost: a waiting hour's book mints and their failures land up to H+6:12 instead of H+2:12, and a book file corrupt for good holds its hour's heals until H+6:12 — the late mints' edge, inside `PANEL_SETTLE` only while the gate admits one of the H+6:12, H+6:42 and H+7:12 ticks: the panel first takes the hour at H+7:22 (`infra/ansible/roles/ops/templates/panel-materialize.timer.j2:14`), so a heal those three ticks all skip misses it, as a late mint does; an ordinary hour with a failed book read heals one cycle later; two lines of code, two cases, and today's broken-read case rewritten. Its benefit is the skeptic's fixture, 0 s of loss and 1220 s of halt in place of 610 s and 610 s with a page that has no record to read; whether a real halt produces that fixture's skew is not established.
- **B — it runs as today.** Cost: wherever a pair's two mirrors resume apart inside a waiting halt, its unfilled seconds book as permanent loss on the first look, `zcrypto-reconcile-residual-gap` pages with no `both_streams_silent` record and no ERROR line, and each such booking is a hand correction whose 24 h `resets()` blind spot follows (`infra/nas/README.md:146`).

**D5. A trades final that fails to read.** The owner picked A: Asked 2026-11-27T16:11:03Z, verbatim: "D5. Should a trades file that exists but fails to read (for example a transient NFS error) wait like a missing one?" The owner's answer by 16:18:57Z, verbatim: "Yes, same bound (Recommended)". The ruling names a missing file; the halt proof's `unread` also holds a present final that fails to read or holds a null, mistyped or unconvertible `ts` or `trade_id` (`command.py:762-780`).
- **A — it waits too, to the same bound (recommended).** The wait's condition is `missing or unread`, one term more. A read that fails on one cycle is read again on the next, as a book read already is. Cost: a final corrupt for good holds its hour's loss booking and page from H+2:12 to H+6:12, though the trades heal fails the cycle on that file where it reads one — the secondary's copy, or the primary's beside a secondary copy, until the pair-hour is minted (`command.py:1092-1108`) — and three hours of failed cycles page `zcrypto-reconcile-exporter-stale`; nine existing cases move their run from the first look to the bound.
- **B — only an absent file waits.** The ruling's words, nothing more. Cost: a transient read error on one trades file books a provable halt as loss once and for good, as above, and pages.

**D6. What shows a waiting hour.** The owner picked A: Asked 2026-11-27T16:11:03Z, verbatim: "D6. What should show that a booking is waiting?" The owner's answer by 16:18:57Z, verbatim: "A WARNING per cycle (Recommended)".
- **A — one WARNING per waiting cycle (recommended):** `archive reconcile: booking deferred hour=<H> until=<H+6 h> missing=<pairs or -> unreadable=<mirror pair, or -> -- a fleet-dark hour waits for these trades segments, then books whatever arrived`. At most eight lines an hour (H+2:12 to H+5:42), paging nothing (`zcrypto-ops-error-logs` reads ERROR and CRITICAL, `infra/grafana/alerts.yaml:2652`); no metric, no record. **D7. The skip cache's `ALGO_VERSION`.** The owner picked A: Asked 2026-11-27T16:11:03Z, verbatim: "D7. Should the reconciler's scan-cache version be bumped with this change?" The owner's answer by 16:18:57Z, verbatim: "Keep version 1 (Recommended)".
