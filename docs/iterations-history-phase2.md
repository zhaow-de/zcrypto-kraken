Per-iteration changelog for Phase 2. Appended at each iteration's close-out; see `.claude/rules/prose.md`.

## 2026-07-08 — iter-013: CPCV splitter — validation harness opens (Phase 2)

- **Opened `cli/validation/`** (the §9 "harness is the product" package) with the **CPCV (combinatorial purged cross-validation) splitter** — the first Phase-2 component, built on synthetic index positions before any strategy exists. `cpcv.py`: `make_groups` (contiguous half-open `[start, stop)` blocks, first `n%N` one larger), `n_backtest_paths` (`C(N-1, k-1)`), `cpcv_splits` (every `C(N, k)` combination of `k` test groups → `{test_groups, train, test}` with purge + embargo); `errors.py` (`ValidationError`). Stdlib-only (`itertools`, `math`); pure functions, no data/strategy/logging.
- **Purge + embargo (the leakage defense, §9.1), per contiguous test block `[a, b]`:** purge drops training indices in `[a - label_horizon, a)` (their forward label window reaches into the test); embargo drops indices in `(b, b + embargo]` (serial-correlation buffer; caller sets `embargo ≥ label horizon + feature lookback`). Non-adjacent test groups form multiple blocks, each purged/embargoed independently. **26 tests** (full suite 227) — property-style: coverage `= C(N-1, k-1)` per group, train ∩ test = ∅, and no train index leaks into any test block.
- **Distrust-the-instrument:** because this splitter judges every future strategy, the whole-branch review **mutation-tested** the property tests — planting under-purge / under-embargo / forgot-per-block bugs and confirming each turns a purge/embargo test red — proving the tests catch real train→test leakage, not tautologies. The leakage math was independently re-derived + executed against hand calculations; no off-by-one.
- **Deferred (harness-precision follow-up):** the property tests verify the purge/embargo windows are *sufficient* (catch all leakage) but not *tight* (leakage-safe over-trimming isn't caught) — a two-sided-bound assertion belongs in the Phase-2 acceptance-suite iteration, per the review.
- **Design/plan:** `docs/specs/00006-cpcv-splitter-design.md`, `docs/plans/00006-cpcv-splitter.md`. First Phase-2 iteration (kickoff decision logged in the running `.tmp/decisions.md`).
- Independent whole-branch review (Sonnet): APPROVED — leakage math, path-count formula, guards, and spec compliance all verified; tests confirmed non-tautological via mutation testing.

## 2026-07-08 — iter-014: deflated & probabilistic Sharpe ratio (Phase 2)

- **Added `cli/validation/dsr.py`** — the §9.4 multiple-testing control: `probabilistic_sharpe_ratio` (PSR = Φ of the Sharpe estimator's studentized excess over a benchmark, with the non-normal skew/kurtosis SE correction), `expected_max_sharpe` (Bailey & López de Prado's expected maximum of `N` i.i.d. null trial Sharpes), and `deflated_sharpe_ratio` = PSR deflated by that expected-max benchmark (more trials ⇒ higher bar). Stdlib `statistics.NormalDist` (Φ, Φ⁻¹); pure scalar functions consuming the trial-Sharpe distribution CPCV (iter-013) produces. **31 tests** (full suite 258).
- **NaN-refusal is the deliverable (§7 PoC lesson).** The PoC minted a fake winner from a NaN deflated-Sharpe; this module raises `ValidationError` on any degenerate input rather than returning NaN — the integrity the trial registry asserts on read.
- **Distrust-the-instrument — the review caught the cardinal bug live.** The first whole-branch review (adversarial NaN-hunt) found that the integer count params `n_trials`/`n_obs` were range-checked only (`< 1`, `< 2`), never `isfinite`-checked — and `NaN < 1` is `False`, so `deflated_sharpe_ratio(1.5, float("nan"), 100, 1.0)` **returned NaN**, the exact PoC failure. It also found `expected_max_sharpe(inf)` / `(1e16)` raising a bare `StatisticsError` instead of `ValidationError`. Fixed (commit `743b01b`): `isfinite` guards on both counts + an inverse-CDF domain guard (`0 < 1 - 1/N < 1`) for extreme finite `n_trials`; regression tests for `nan`/`inf`/`1e16` and the `denom == 0` boundary. Re-review verified the boundary (1e15 finite → 9e15/1e16 raise) and found no remaining leak.
- **Design/plan:** `docs/specs/00007-deflated-sharpe-design.md`, `docs/plans/00007-deflated-sharpe.md`. Formulas independently re-derived in review (`expected_max_sharpe(10, 1.0) = 1.5746`; PSR SE denominator `1 + sr²/2` for normal returns; `√(n_obs−1)`; full — not excess — kurtosis).
- Independent whole-branch review (Sonnet): APPROVED after the NaN-leak fix — formulas correct, every degenerate input now raises `ValidationError`, no non-`ValidationError` crash path remains.

## 2026-07-08 — iter-015: probability of backtest overfitting (Phase 2)

- **Added `cli/validation/pbo.py`** — the §9.4 companion to DSR: **PBO via CSCV** (Bailey/Borwein/López de Prado/Zhu). Over **every** `C(S, S/2)` symmetric split of `S` time blocks into in-sample/out-of-sample, it takes the IS-best config and measures its **average OOS rank** `r = #{oos<v} + (#{oos==v}+1)/2`; the split is overfit iff `logit(r/(N+1)) < 0` (IS-best below the OOS median); PBO = the overfit fraction. Reuses `make_groups` for the block partition; `metric` defaults to `statistics.mean`, callable-overridable. Returns `{"pbo", "n_combinations"}`. **18 tests** (full suite 276).
- **Bounded ⇒ never NaN.** `r ∈ [1, N]` (the equality count includes the config itself), so `w = r/(N+1) ∈ (0, 1)` strictly and the logit is always finite; degenerate *inputs* raise `ValidationError` — non-rectangular / non-finite matrix, odd or non-int `n_splits`, `T < n_splits`, `N < 2`, a `metric` that returns non-finite **or raises**.
- **Distrust-the-instrument — review + mutation testing again earned its keep.** The whole-branch review hand-derived the CSCV math (matched all exact cases) and **mutation-tested** the suite: flipping the overfit sign or the rank comparator turns the exact-value tests red (good), but last-argmax tie-breaking and a `<=` boundary initially slipped through. It also found two non-`ValidationError` crash paths — a `metric` that *raises* (e.g. `statistics.stdev` on a size-1 block → `StatisticsError`) and an even-*float* `n_splits` (`2.0 % 2 == 0` → later `TypeError` in `make_groups`). Fixed (commit `0857ff5`): wrap the metric calls, add an `isinstance(n_splits, int)` guard, and regression-test both crash paths + the first-argmax (`pbo=0.5`) and `w==0.5` strict-`<` (`pbo=0.0`) boundaries. Re-review re-ran the mutations — all now killed.
- **Design/plan:** `docs/specs/00008-pbo-design.md`, `docs/plans/00008-pbo.md`. Completes the DSR + PBO overfitting-detection core of §9.4.
- Independent whole-branch review (Sonnet): APPROVED after the crash-path fix — CSCV math correct, every degenerate input raises `ValidationError`, tie/boundary conventions test-pinned.

## 2026-07-08 — iter-018: performance statistics (Phase 2)

- **Added `cli/validation/metrics.py`** — the statistics a strategy is scored on: `sharpe` (`(mean − risk_free)/sample-stdev`, optional `× sqrt(periods_per_year)`), `volatility` (sample stdev, optional annualization), `annualized_return` (geometric: `prod(1+r)**(ppy/n) − 1`), `max_drawdown` (worst peak-to-trough on the equity curve, as a non-negative fraction).
